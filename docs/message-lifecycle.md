## 데이터 경계와 안전장치

- 일반 메시지에 선택적 `sentBody`, `changes`, `editedAt`, `deletedAt`, `hiddenFor`를 추가했다. 기존 자료의 ID·발신 순번·첨부 ID를 바꾸거나 파일을 다시 인코딩하지 않는다. 변경 전 자료는 버전 1로 해석한다.
- 수정·전체 삭제는 현재 버전을 `expectedVersion`으로 확인한다. 오래된 창의 내용을 덮어쓰지 않고 재확인을 요구한다. 고유 변경 ID와 영수증을 확인하여 같은 요청 재시도는 한 번만 반영하며, 같은 ID의 다른 본문·범위·사용자·대상은 거부한다. 삭제 후 예전 수정 요청을 재시도해도 내용이 복구되지 않는다.
- 현재 참여·과거 열람 경계를 먼저 검사한다. 관계가 해제된 계정은 이전 요청 ID로 권한을 되살릴 수 없다. 다른 아동·다른 작성자·카드 유형·잘못된 시간·불완전 확인도 공통 로직에서 거부한다.
- 답변은 선택 당시 `replyVersion`을 유지한다. 원문 수정 후에는 당시 인용과 ‘원문 수정됨’을 보여주되 전체 삭제·사용자 숨김·과거 범위 밖 원문은 인용에서 감춘다. 새 답변 초안의 원문 버전이 바뀌면 재선택을 요구한다.
- 내부 반영 메모에는 `reviewVersion`을 연결한다. 원문이 수정되면 현재 소식의 반영 완료로 취급하지 않으며, 치료사에게 이전 메모와 재확인 안내를 제공한다. 보호자에게 내부 메모를 공개하지 않는다.
- 기록에는 비공개 `referenceSources`를 둔다. 선택 당시 일반 소식의 ID·버전·본문·첨부 메타데이터·확보 시각을 보존한다. 기존 ID만 가진 답변·임상 참고도 원문을 처음 변경하기 직전에 고정한다. 기록을 나중에 수정해도 이미 저장된 참고 내용은 그대로이며 보호자 공유본으로 자동 복사하지 않는다.
- 새 임상 참고는 현재 열람 가능한 미삭제 소식만 허용하고 UI가 선택한 버전을 확인한다. 레거시 호출 호환을 위해 일부 버전 입력은 선택적이므로 이 로컬 계약을 그대로 운영 API로 노출하면 안 된다.
- 저장 실패 시 수정창의 입력·변경 ID와 작성 중이던 대화 초안을 유지한다. 저장 후에도 다른 방이나 뒤이어 작성한 초안을 지우지 않는다. 수정 입력과 삭제 선택에는 본문 값과 분리된 명시적 접근성 이름을 연결했다.
- 홈의 이어 쓸 기록에도 과거 열람 경계를 적용하여 신규 치료사가 과거 비공개 초안의 제목·열기 동작을 보는 경로를 차단했다.

### 삭제는 영구 파기가 아니다

**현재 삭제는 대화 표시에서 숨기는 처리다.** 브라우저 저장소에는 최초/수정 본문·변경 영수증·임상 참고 원문과 IndexedDB 파일 바이트가 남는다. 숨긴 내용은 개발자 도구·이전 앱 버전·원본 저장소를 통해 접근할 수 있으며 로컬 역할 선택은 실제 인증이 아니다. 기기별 영구 삭제, 다운로드 사본 회수, 저장소·백업 파기 기능을 제공한다고 표시하지 않는다.

보존은 참고한 임상 내용이 조용히 변하는 일을 막기 위한 이번 체험의 구현 선택이지, 무기한 보존에 대한 사용자 승인이나 법적 보존 의무 판정이 아니다. 실제 자료 전환 전에 보관 기간·정당한 목적·삭제 요청 처리·원문/임상 기록/공유본/파일/백업별 파기 및 감사 경계를 별도로 확정해야 한다. 이 작업에서 실제 아동 자료를 사용하거나 유료/외부 자원을 만들지 않았다.

### 중간 실패를 보존한 이유

1. 단위 검사에서 편집 이력이 있는데 빈 `deletedAt`을 허용하던 검증을 발견해 수정했다. 삭제 이력이 없으면 속성 자체가 없어야 한다.
2. 전체 새 화면 검사 첫 실행은 접힌 제목 입력을 직접 채우려는 시험 도구 오류로 멈췄다. 실제 요약 영역을 펼치도록 수정했다.
3. 두 번째 전체 실행은 본문 값이 입력창 접근성 이름에 섞여 정확한 이름으로 선택하지 못했다. 제품 공통 입력 도우미에 명시적 이름 연결을 추가했다. 이 전체 검사는 두 번 실패했으며 이후 세 번째 실행하지 않았다.
4. 별도 집중 검사 첫 실행은 실제 수정·실패 재시도·인용 확인 후 배경 기록과 편집창에 모두 있는 참고 영역을 단일 선택하려다 멈췄다. 제품 내용을 제거하지 않고 시험 선택자를 편집창으로 한정했다. 두 번째 집중 실행은 3폭 모두 통과했다.

## 남은 작업과 우선순위

1. **서버 내부 계약**: 서버 신원·시계, 작성자 권한·현재 참여·과거 열람, 변경 버전/명령 ID, 사용자별 숨김, 삭제 투영, 당시 답변·임상 참고, 비공개 반영 메모를 트랜잭션으로 구현. 추가 마이그레이션·최소 권한·복원 계약과 실제 PostgreSQL 경합을 검증한다. 현재 서버에는 이 새 일반 메시지 수정·삭제가 구현되지 않았다.
2. **운영 보존·삭제 결정**: 임상 원문 분리, 보존 기간, 삭제 요청과 파일/백업 파기 범위, 최소 사건 및 관리자 처리 권한을 확정한다. 현재 프로토타입의 전체 이력 보존을 운영 정책으로 자동 승격하지 않는다.
3. **실사용 준비**: 독립 백업 매체·복원 훈련, 운영 Windows 서비스/계정, 실제 사람의 이해도·시간, iOS/Android 실제 키보드/사진/영상과 별도 기기 전달을 확인한다.
4. **마지막 API 연결**: 위 준비 후 실제 계정·메시지·파일·재접속·오프라인/실패·재시도·동기화를 연결하고 검증한다. 독립 백업 매체가 아직 없으므로 실제 아동 자료 수집·외부 보호자 접속은 계속 보류한다.

배포·GitHub push·실제 계정 발급·메일 발송·API 활성화·운영 DB 변경은 하지 않았다. 전체 목표를 완료 또는 차단으로 판정하지 않는다.
