# 대화 전송 중 화면 갱신·담당 변경의 초안 보존

작성·검증: 2026-10-06. 개편안의 사례 4·5·6을 보완한 로컬 P0 작업이다. 실제 계정이나 서버 전송을 연결한 작업이 아니다. 전체 개편안은 진행 중이며 API 연결은 마지막 단계로 유지한다.

## 확인한 문제와 원인

전송은 사진·영상의 IndexedDB 저장을 기다린 뒤 메시지 JSON을 확정한다. 그 사이 다른 탭의 `storage` 이벤트가 현재 화면을 다시 그릴 수 있다. 기존 전송 완료 코드는 발신 당시가 아니라 그때의 `this.form`, `this.draft`, `this.editor`, `this.key`를 정리했다. 다른 방의 입력을 비우거나, 새 첨부 편집기를 폐기하거나, 원래 방의 실패를 새 방에 표시할 수 있었다. 입력창이 이미 제거되면 메시지 저장 후 정리가 중단되는 문제도 있었다.

수정 전 지연 전송 계약 검사 6개 중 5개가 실패했다. 이는 DOM·저장소 대역을 쓰는 단위 재현이며 실제 브라우저 증거와 구분한다. 별도 브라우저 검증에서는 전송 중 담당자 변경을 저장하지 못하는 추가 문제를 발견했다. 현재 참여자에게만 열람 위치를 허용하는 저장 검증 때문에 이미 읽은 이전 참여자의 이력이 데이터 전체를 무효화했다. 추가한 관계·열람 검사 2개도 수정 전 실패했다.

## 변경한 동작과 보존 경계

| 경계 | 현재 동작 |
| --- | --- |
| 발신 시점 | 사용자·아동·방 키·본문·답변·첨부 메타데이터/Blob을 복사하고 원래 폼/편집기를 고정한다. 늦은 완료가 다른 방의 상태를 사용하지 않는다. |
| 전송 중 같은 방 갱신 | 다시 생성된 입력창도 잠근다. 완료/실패 후 원래 비활성 상태를 복원하며, 원래 사용할 수 없던 버튼을 임의로 켜지 않는다. |
| 전송 성공 | 원래 키와 발신 ID가 여전히 일치할 때만 빈 새 초안을 저장한다. 다른 아이의 초안과 같은 방의 다음 발신 ID는 지우지 않는다. |
| 전송 실패 | 입력·사진·영상·발신 ID를 유지한다. 오류는 원래 방/발신 ID에 연결하고 해당 방을 다시 열면 표시한다. 다른 방에는 옮기지 않는다. 재시도는 사용자가 명시적으로 한다. |
| 메시지 성공, 초안 디스크 정리 실패 | 이를 발신 실패로 표시하지 않는다. 초안 저장 오류는 별도로 알린다. 새로고침에서는 해당 아동·작성자의 이미 저장된 발신 ID를 확인하고 빈 새 초안을 다시 저장한다. 기존 메시지나 파일을 삭제하지 않는다. |
| 담당 관계 종료 | 메시지와 같은 과거 참여자 범위에서 기존 열람 위치를 보존한다. 현재 조회·발신·읽음 변경은 기존 `canConverse`/담당 관계 검사로 계속 거부한다. 새 참여자에게 이전 사람의 읽음 위치를 부여하지 않는다. |

기존 localStorage/IndexedDB 이름·버전, 탭/사용자/아동 키, 기록·공유본·메시지·첨부 ID를 유지했다. 저장 형식 이관·초기화·기존 원본 삭제는 없다. 센터의 임상 원문 접근, 공유 철회 정책, 읽음/임상 반영 구분, 서버 인증·SQL·HTTP·운영 설정은 변경하지 않았다. 의존성을 추가하거나 GitHub/Vercel에 배포하지 않았다.

## 실제 브라우저 증거

검증 스킬로 전용 로컬 브라우저의 홈·대화 로딩, 화면, 콘솔·페이지 오류와 내비게이션을 먼저 확인했다. 이후 각 사례는 별도의 비영구 Chromium 컨텍스트와 두 개의 합성 탭을 사용한다. 사용자 Chrome 탭·프로필·기존 저장소를 채택하거나 초기화하지 않는다.

화면의 보내기 → 실제 파일 저장 직전 대기 → 다른 탭의 공통 도메인 변경/JSON 저장 → 실제 `storage` 이벤트/화면 갱신 → 파일 저장 및 메시지 확정/롤백 → 초안 정리/복원까지 확인했다. 대기/실패 주입만 시험 도구로 제어하며, 실제 IndexedDB 트랜잭션과 Blob 바이트·메시지 JSON은 읽어서 비교한다. 임의의 `storage` 이벤트나 성공 API 응답을 만들어 통과시키지 않는다.

1440px·390px·320px에서 다음 네 사례를 각각 수행했다(총 12개).

1. 전송 중 같은 방에 다른 탭의 소식 도착: 재생성된 입력을 잠그고 원래 사용자/아동에게 한 번 저장한다.
2. 지연된 파일 저장 실패: 갱신 후에도 오류·원문·PNG/영상·ID를 유지한다. 추가 갱신 후 Enter로 재시도해 한 번 저장한다.
3. 전송 중 담당자 해제: 화면은 다른 담당 아이로 이동한다. 기존 발신은 현재 권한으로 거부되고 새 파일만 롤백된다. 다른 방의 작성 내용/ID와 원래 초안 Blob을 보존한다. 명시적으로 관계를 복원하고 원래 방에 돌아가 같은 ID로 재시도한다.
4. 메시지 확정 후 초안 쓰기 실패: 메시지 성공은 유지하고 내부 IO 오류를 노출하지 않는다. 새로고침 후 빈 새 ID의 초안까지 실제로 저장하고 중복 발신하지 않는다.

모든 사례는 PNG와 실제로 디코딩 가능한 WebM을 첨부하며, 원래 파일 바이트·작성자·아동·본문·메타데이터·단일 메시지와 새로고침 결과를 확인한다. 좁은 화면에서 전송/초안 오류 전문을 작성 영역 스크롤로 읽을 수 있고 가로 넘침이 없음을 검사했다.

초기 영상 fixture는 두 탭 중 배경 탭에서 캔버스 프레임을 만들지 못해 실제 디코딩 검사에서 중단됐다. 합성 작성 탭을 활성화한 뒤 생성하도록 시험 준비만 수정했다. 앱의 영상 검사 조건을 완화하거나 디코딩 실패를 통과시키지 않았다. 담당자 변경 저장 실패는 이 fixture 문제와 다른 실제 제품 문제이며 저장 검증을 수정했다.

## 변경 파일과 재현

- `src/chat-controller.js`: 발신 스냅샷, 폼별 잠금/원상 복원, 방별 오류, 성공/초안 정리 실패 구분, 이미 확정된 초안의 새로고침 정리.
- `src/chat-drafts.js`: 방 키/발신 ID 일치 조건의 `clearSent`.
- `src/conversations.js`: 과거 열람 위치의 저장 검증. 현재 접근 정책은 유지.
- `tests/chat-controller.test.mjs`: 지연 완료·화면 제거·다른/같은 방의 새 초안·비활성 상태·중복 제출·정리 실패·첨부/발신자 스냅샷 9개.
- `tests/chat-drafts.test.mjs`: 기존 8개와 조건부 정리/정리 실패 2개, 총 10개.
- `tests/communication.test.mjs`: 관계 변경 후 저장·복원·새 접근 차단과 손상 열람 위치 거부 2개 추가, 총 8개.
- `tests/chat-send-lifecycle-browser.mjs`, `package.json`: 12개 실제 브라우저 경계 검증과 실행 명령.
- `README.md`, `communication-implementation.md`, `chat-draft-reliability.md`, `p0-device-matrix.md`: 현재 단계/검증 문서 연결. 이전 단계 숫자는 당시 결과로 보존한다.

```powershell
npm test
npm run check
npm run build
npm run test:chat-send:browser
npm run test:communication:browser
```

브라우저 명령은 별도로 설치된 Playwright의 `index.mjs` 절대 경로(`PLAYWRIGHT_MODULE`), 전용 테스트 Chromium의 주소(`CDP_URL`), 인증/DB 연결을 켜지 않은 루프백 주소(`APP_URL`)를 지정해야 한다. 운영 URL로 신규 시험을 실행하지 않는다. 신규 시험은 루프백 주소만 허용한다.

결과/화면은 Git·정적 배포에서 제외된 `test-results/chat-send-lifecycle-results.json`, `chat-send-*.png`에 남는다. 최종 신규 실행 UUID는 `f0bd2c3c-d31e-4717-a6be-a56647e1f201`이며 12개 통과, 페이지/콘솔 오류와 API/외부 요청은 0건이다. 저장된 보고서만으로 성공 판정하지 않고 해당 실행의 프로세스 종료 코드 0까지 확인했다.

## 남은 위험과 다음 우선순위

1. 이 검증은 같은 브라우저 안의 로컬 탭/역할 체험이다. 실제 인증·서버 파일 전달·다른 기기 동기화·운영 복구를 증명하지 않는다. 이번 서버 코드는 변경하지 않아 서버 시험을 재실행하지 않았다.
2. 물리 iOS/Android/Safari, 탭 복제·세션 복원의 키 충돌, OS 강제 종료/저장소 회수는 별도 확인이 필요하다. 오류 안내는 현재 탭의 메모리 상태이며 페이지 종료 뒤까지 발신 실패 이력을 따로 저장하지 않는다. 원문·첨부 복원과는 구분한다.
3. P0의 실제 치료사/보호자 과제 완주·동일 과제의 화면 이동/소요 시간 비교·공유 요약 이해도 확인이 남아 있다. 자동화 시간이나 통과 수를 사람의 사용성 개선 성과로 주장하지 않는다.
4. P1의 국내 공급자/예산·영구 저장/키/보존·파기·메일·관리자/계정 복구·운영 승인과 [복구 준비](recovery-readiness.md)를 진행한 뒤 마지막 API/화면 연결과 기기 간 검증을 수행한다. P2는 확인된 사용자 필요에 따라 결정한다.

전체 개편안의 완료 요건을 위 12개 검사로 축소하지 않는다. 실제 개인정보·아동 사진·건강 자료를 입력하거나 현재 로컬 저장을 유일한 원본으로 사용하면 안 된다.
