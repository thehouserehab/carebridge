# 연결된 아동이 없는 계정 — 화면 유지와 이력 보존

작성·검증일: 2026-10-06

## 현재 상태와 원인

센터가 담당 치료사·보호자 연결을 모두 해제하면 해당 사용자의 접근 가능한 아동은 0명이 된다. 데이터가 손상된 것이 아니며, 기록·공유본·메시지·열람 이력도 남아 있어야 한다.

기존 `render()`는 접근 가능한 아동이 없어도 아동별 `project()`를 호출했다. 조회 함수가 올바르게 권한 오류를 내면 화면 전체가 ‘기록을 불러오지 못했어요’로 바뀌어 역할 선택·메뉴·계정 설정까지 사라졌다. 가상 센터의 실제 관계 관리 폼으로 두 아동의 관계를 해제한 수정 전 브라우저 실행에서 이를 재현했다(`A valid zero-assignment state is not corrupt data`, fatal 화면 1개).

권한 검사를 완화하지 않고 화면 진입 조건을 수정했다. 연결된 아동이 있을 때만 아동별 조회를 호출한다. 아동이 없으면 선택 ID를 null로 정리하고 기존 화면 구조 안에 ‘연결된 아이가 아직 없어요’와 센터의 관계 연결 안내를 표시한다.

## 동작과 안전 경계

- 치료사·보호자의 홈 / 대화 / 기록 / 아이 정보 메뉴와 역할 선택, 로그인 체험, 본인 표시 이름 설정은 유지한다.
- 접근 가능한 아동이 없는 동안 아동 선택·대화 입력·기록 목록·새 기록/대화 작성 버튼을 만들지 않는다. 다른 아동을 임의로 선택하거나 가상 아동을 추가하지 않는다.
- `project()`, 대화 조회·발신·읽음·기록 작성의 담당 관계 검사는 변경하지 않는다. 저장된 과거 이력이 있다는 이유로 현재 접근을 허용하지 않는다.
- 관계 해제는 기존 기록·공유본·메시지·피드백·목표·일정·열람 이력을 삭제하지 않는다. 미전송 초안의 방 키·발신 ID·본문·첨부 메타데이터·사진 Blob도 유지한다.
- 센터의 명시적 관계 복원 후 같은 사용자·아동의 이력과 초안을 다시 사용한다. 재시도 발신은 같은 ID로 한 번만 저장한다.
- JSON 손상 등 실제 읽기 오류는 계속 오류 화면으로 차단하고 저장 원문을 덮어쓰지 않는다. 모든 실패를 ‘연결 없음’으로 숨기지 않는다.

이 작업은 **유효한 로컬 데이터에서 특정 치료사/보호자의 연결이 0명인 경우**를 다룬다. 아동이 전혀 없는 신규 센터의 실제 계정·등록 흐름이나 운영 권한 정책을 구현했다는 뜻은 아니다. 기존 CSS와 저장 형식·키·ID는 유지했다.

## 실제 검증 흐름

브라우저 검증 스킬로 루프백 개발 화면의 홈·메뉴·콘솔 상태를 확인하고 아래 데이터 흐름을 수행했다.

센터의 관계 관리 폼 → 공통 관계 변경/실제 localStorage 저장 → 다른 탭의 실제 storage 이벤트 → 연결 없음 화면 → 메뉴·새로고침·계정 화면 → 센터의 명시적 관계 복원 → 기존 IndexedDB 초안/사진 복원 → 같은 ID로 메시지와 파일 확정.

각 사례는 독립적인 비영구 Chromium 컨텍스트와 합성 탭 두 개를 사용한다. 사용자 Chrome 프로필·기존 데이터나 운영 사이트는 사용하지 않는다. 서버/API 응답을 성공으로 꾸미거나 이벤트를 임의로 발송하지 않는다.

1440×1000, 390×844, 320×844에서 다음을 각각 확인했다.

1. 사진을 포함한 치료사 초안을 작성한 뒤 센터 화면에서 실제 관계를 해제한다. 기록·공유본·메시지·피드백·목표·일정의 값은 전후 동일하다.
2. 치료사와 보호자 각각 네 메뉴를 키보드 Enter로 열고, 연결 안내·계정 선택·현재 메뉴 표시와 가로 넘침 없음을 확인한다. 기존 기록 제목·내부 메모·대화/작성 영역은 표시되지 않는다.
3. 새로고침 후에도 유효한 연결 없음 상태가 유지된다. 로그인 체험과 표시 이름 설정을 열고 닫을 수 있다.
4. 실제 센터 폼에서 관계를 복원한다. 원래 발신 ID·본문·첨부 정보·PNG 원본 바이트가 그대로 복원되고 해당 아동/작성자의 메시지가 한 번만 저장된다.
5. 별도 손상 JSON 사례에서는 오류 화면을 표시하고 원문을 그대로 보존한다.

연결 해제·복원 한 묶음과 손상 데이터 한 묶음씩, 세 화면에서 총 6개 검증 묶음이다. 검사 수를 사용자 수나 기능 수로 해석하지 않는다. 화면을 직접 확인했으며 320px에서도 안내·하단 메뉴·계정 접근에 가로 넘침이 없다.

최초 수정 후 실행은 배경 탭 스크린샷에서 8초 시간 초과로 중단됐다. 시험의 촬영 전에 해당 합성 탭을 활성화하고 촬영 시간만 15초로 지정했다. 기능·보존·권한 검사를 삭제하거나 완화하지 않았다. 최종 실행 UUID는 `821d3bbc-1c71-4559-8394-cda1b537e56f`, 종료 코드 0이며 6개 통과·페이지/콘솔 오류와 API/외부 요청 0건이다.

단위 검사 2개는 조회/발신/작성 거부, 저장·재로드와 명시적 관계 복원, 기존 열람 위치의 정확한 보존을 확인한다. 센터 조회는 기존 계약대로 임상 배열이 비어 있고 기록 건수만 제공한다. 처음 추가한 검사에서 배열 필드 자체가 없다고 잘못 가정한 부분을 이 실제 계약에 맞췄으며 제품의 센터 조회를 변경하지 않았다.

## 변경 파일과 재현

- `src/app.js`: 0명 연결 상태의 렌더링 분기, 아동 관련 UI 숨김, 연결 안내. 다른 화면과 권한 함수는 유지.
- `tests/empty-assignment.test.mjs`: 현재 접근 거부·원문/열람 위치 보존·관계 복원 2개.
- `tests/empty-assignment-browser.mjs`: 센터 폼·두 역할·네 메뉴·계정 화면·초안/사진·손상 데이터의 실제 브라우저 검증.
- `package.json`: `test:empty-assignment:browser` 명령.
- `README.md`, `communication-implementation.md`, `p0-device-matrix.md`: 현재 상태와 검증 범위 연결.

```powershell
npm test
npm run check
npm run build
npm run test:empty-assignment:browser
npm run test:communication:browser
npm run test:chat-send:browser
```

브라우저 명령에는 설치된 Playwright `index.mjs`의 절대 경로(`PLAYWRIGHT_MODULE`), 전용 테스트 Chromium 주소(`CDP_URL`), 인증/DB 연결을 켜지 않은 루프백 개발 주소(`APP_URL`)를 지정한다. 신규 시험은 루프백만 허용한다.

최종 신규 결과는 Git·정적 배포에서 제외한 `test-results/empty-assignment-results.json`, 화면은 `empty-assignment-<폭>-<역할>.png`에 있다. 이전 실패 화면·보고서를 성공 증거로 사용하지 않는다.

## 남은 위험과 다음 우선순위

1. 현재 브라우저 역할 전환은 실제 인증/보안 경계가 아니다. 다른 기기에서의 계정·관계·대화·첨부 전달과 재접속 복원은 서버/API 연결 후 검증해야 한다. 이번 서버 코드·SQL·인증 정책은 변경하지 않아 서버 시험을 다시 실행하지 않았다.
2. 이번 0명 관계 변경 시험은 임상 편집 모달을 닫은 상태다. 후속 [편집 중 다른 탭 변경](dialog-workspace-sync.md)에서 열린 창의 입력/사진 보존·사전/최종 충돌 차단·종료 후 최신 관계/수신자 반영·손상/소실을 추가로 검증했다. 두 로컬 시험 모두 운영 권한 실시간 회수를 증명하지 않는다.
3. 실물 iOS/Android/Safari와 치료사·보호자 과제 완주/소요 시간/요약 이해도 확인은 남아 있다. Chromium 화면 축소나 자동 클릭 시간을 사람의 사용성 성과로 주장하지 않는다.
4. 실제 계정 복구·관리자 추가는 신원 확인과 승인 정책이 미정이므로 관리자 우회 기능을 만들지 않았다. 국내 공급자/예산·메일·영구 파일/키·보존/파기·복구/운영 승인도 [복구 준비도](recovery-readiness.md)의 미완료 항목으로 유지한다.
5. API는 사용자의 순서대로 마지막에 연결한다. 이후 실제 계정과 기기 간 전달을 검증하고, P2는 사용자 필요의 증거가 있을 때 우선순위를 정한다. GitHub/Vercel 배포나 유료 자원 생성은 하지 않았다.

전체 개편안의 완료 기준을 위 6개 검사로 축소하지 않는다. 실제 개인정보·건강 자료·아동 사진을 입력하거나 로컬 저장소를 유일한 원본으로 사용하면 안 된다.
