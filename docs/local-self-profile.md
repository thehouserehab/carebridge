# 로컬 API — 센터별 내 표시 이름

작성일: 2026-10-10. 가상 계정·자료와 loopback 전용 후속 작업이다. 기존 정적 프로토타입과 공개 배포는 변경하지 않는다.

## 목적과 범위

초대로 가입한 보호자에게 표시 이름 등록 경로가 없어 여러 참여자가 같은 역할명으로 보이는 문제를 보완한다. 치료사·보호자·센터 관리자의 상단 `계정 설정`에서 **이 센터의 내 표시 이름**만 변경한다. 치료사·보호자의 4메뉴, 센터의 3메뉴는 그대로다.

표시 이름은 본인이 정하는 소통용 이름이지 실명 인증·자격 확인이 아니다. 이메일·역할·담당 관계를 편집하거나 이름으로 권한을 부여하지 않는다. 이름을 비우면 기존 역할명 표시로 돌아간다. 같은 이름을 금지하거나 고유한 사람임을 보증하지 않는다.

## 데이터 흐름과 안전 경계

`계정 설정 → 세션에 묶인 본인 API → 기존 MemberProfiles 트랜잭션 → 최신 프로필 재조회 → 대화·홈·센터 명단 표시`

- `GET /api/local/centers/:centerId/account/profile`은 현재 로그인된 본인의 해당 센터 프로필만 반환한다.
- 같은 경로의 `POST`는 `clientId`, `expectedRevision`, `displayName`만 받는다. 사용자 ID는 본문에서 선택하지 않으며 인증 세션과 계정 바인딩 헤더가 일치해야 한다. 기존 서비스가 활성 계정·센터 소속을 다시 검사한다.
- 기존 `src/profile-fields.js`의 이름 규칙, 버전 충돌 검사와 요청 영수증을 재사용한다. DB 스키마·인증 공급자·임상 접근 권한은 바꾸지 않는다.
- 변경되는 것은 센터별 현재 표시 이름뿐이다. 과거 메시지의 작성자 ID·본문·기록·공유본·담당 관계를 다시 쓰지 않는다. 현재 참여자의 이름 표시는 갱신되므로 과거 작성 당시 이름을 보존하는 기능은 아니다.
- 다른 창이 먼저 수정하면 최신 값과 내 입력을 비교한 후 선택한다. 응답 유실·중단 후에는 성공/실패를 단정하지 않고 내용과 요청 ID를 보존한다. 사용자가 같은 요청으로 확인하며, 새로운 ID로 자동 재전송하지 않는다.
- 미저장 입력과 확인 대기 요청은 같은 창의 메모리에만 남는다. 닫기 후 같은 계정·센터에서 이어갈 수 있지만 새로고침·로그아웃·계정/센터 전환 시 사라진다. 이때 서버에 이미 적용되었을 가능성은 남으므로 다시 열어 최신 값을 확인한다.
- 숨김·오프라인 시 프로필 화면을 비우고 대기 조회를 중단한다. 늦게 도착한 다른 계정/센터의 응답을 그리지 않는다. 계정 설정 뒤에 가려진 대화는 새 읽음 처리하지 않는다.
- 센터 관리자에게 임상 대화 조회를 열지 않는다. 로컬 제공 목록에 명시한 스크립트만 추가하며 공개 정적 빌드에는 포함하지 않는다.

## 재현

`npm run dev:local-api`로 실행한 별도 가상 계정 시험 화면에서 로그인 후 상단 `계정 설정`을 연다. 이 기본 실행기는 메모리 DB이므로 실행기 종료 후 같은 자료가 남는 영속 서비스가 아니다.

자동 전체 흐름 명령은 `npm run test:local-self-profile:browser`다. 기존 Playwright 모듈과 전용 Chromium 경로가 필요하다. 사용자의 브라우저·계정·저장소를 시험에 재사용하지 않는다.

## 남은 작업과 제한

표시 이름 연결의 위 회귀는 마무리했지만 P1과 전체 개편안의 완료는 아니다. 다음 핵심 간극은 전체 실행기 종료 후 같은 E 가상 세션 재개이며, 시험 키 삭제 방식을 바꾸기 전에 사용자의 보존 선택이 필요하다. 기존 폴더/키를 임의 재사용하지 않는다. 실제 메일·실물 기기·보호자/치료사 사용성 검증과 독립 백업은 남아 있고, 이전 Windows native 간헐 종료 원인도 미확정이다. 본인 비밀번호 변경 화면 같은 인접 기능을 이 검증 작업에 추가하지 않았다.

독립 백업이 없는 상태에서 실제 아동 자료를 받거나 외부 접속·운영 배포를 열지 않는다. 이번 작업은 GitHub push·Vercel 배포·유료 자원 생성·실제 메일 발송을 하지 않는다.
