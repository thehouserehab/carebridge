# 가상 Wi-Fi 시험의 PC 임시 인증서 신뢰

`tests/hold-synthetic-wifi-current-user-trust.ps1`은 사용자가 명시적으로 허용한 실물 시험에서만 운영자가 실행하는 보조 도구다. 앱·Wi-Fi 실행기는 이 도구를 자동 실행하지 않는다. 시스템 전체 저장소, 기존 인증서, 방화벽, 인증/세션 규칙은 변경하지 않는다.

## 범위와 수명

- PowerShell 7, 일반 권한, 지정한 현재 Windows 사용자만 허용한다. `CurrentUser/Root`는 이 사용자의 다른 앱에도 영향을 주는 신뢰 저장소이며 Carebridge 전용 저장소가 아니다.
- 공개 DER 인증서의 SHA-256·지문·시험용 CA 속성·유효기간을 확인하고, 파일 핸들로 고정한 같은 바이트만 사용한다. 개인키는 입력하거나 저장하지 않는다.
- 소유 CLI 프로세스의 핸들·생성 시각·실행 경로를 확인한다. 만료 시각은 **원래 CLI 시작부터 2시간**이며 관찰자 실행부터 새로 연장하지 않는다. 경과 시간도 함께 검사한다.
- 소유 프로세스 상태는 명시적인 Boolean 값일 때만 인정한다. 추가 직전·직후의 취소 요청과 상태 관측 실패는 진행하지 않고 정리한다.
- 정확히 같은 인증서가 이미 있으면 거부한다. 기존 신뢰를 채택하거나 나중에 대신 삭제하지 않는다. `-ValidateOnly`는 읽기 검사만 하며 파일·저장소를 변경하지 않는다.
- 소유 프로세스 종료, 기한 만료 또는 정확한 영수증 경로 뒤에 `.stop`을 붙인 파일이 생기면 이번 인증서만 제거한다. 새 저장소 조회에서 부재를 확인해야 제거 성공으로 기록한다.
- 영수증에는 공개 인증서 식별값·상태·프로세스 식별값·기한만 기록한다. 계정 비밀번호·쿠키·개인키·메시지·실제 자료는 기록하지 않는다.

## 실패와 정리

추가 도중 실패해도 정확한 인증서 제거를 시도한다. 영수증 기록 실패는 실제 제거를 막지 않으며, 제거가 불확실하면 `cleanup-unconfirmed`와 실패 종료로 보고한다. 그런 경우 성공으로 간주하거나 새 관찰자를 중복 실행하지 말고 정확한 지문과 SHA-256으로 현재 사용자 저장소를 재확인한다.

**강제 종료·Windows 재시작은 `finally` 정리를 건너뛸 수 있다.** 이 도구는 장애 후 자동 복구를 보장하는 서비스가 아니다. 시험 중 관찰자를 강제 종료하지 않는다. 비정상 종료 후에는 보존된 공개 영수증을 기준으로 이번 인증서만 제거하고 부재를 독립 확인해야 한다. 아이폰의 프로파일은 별도로 사용자가 제거해야 한다.

## 검증

다음 집중 검사는 실제 인증서 저장소 대신 메모리 대역을 사용한다. 정상 종료, 기존 인증서 거부, 잘못된 해시/소유자/기한, 부분 추가 실패, 소유자 종료, 관찰 실패, 영수증 기록 실패와 제거 실패를 구분한다.

```text
CAREBRIDGE_TEST_POWERSHELL=<설치된 pwsh.exe 절대 경로>
node --test --test-concurrency=1 tests/synthetic-wifi-current-user-trust.test.mjs
```

2026-10-13 최초 집중 실행은 **14/14 통과**였다. 이 버전의 실제 시험 인증서·소유 프로세스 사전검사는 `preflight=true, changed=false`, 종료 0이었다. 이후 사용자가 PC 보안 경고창에서 승인했고, 동일 감시 프로세스의 `active` 출력·영수증과 정확한 SHA-256/개인키 부재를 독립 조회했다. 승인창이 잠시 보이지 않았지만 재실행·강제 종료·승인 우회는 하지 않았다. 원 CLI 시작+2시간 기한은 유지됐다. 종료·제거는 아직 검증 전이다.

별도 후속 수정본은 상태 관측의 null/예외, 준비 중 취소, 추가 도중 취소, 관찰 결과 불명확을 추가 검사했다. 최종 집중 실행 **22/22 통과**, 실패·취소·건너뜀 0, 종료 0(42,892ms)이다. JavaScript 구문 검사와 PowerShell AST 구문 검사도 통과했다. 실행 중이던 감시 프로세스는 최초 14개 검사 버전이며, 수정본을 재주입하거나 다시 실행하지 않았다. 실제 실행 소스 SHA-256은 진행 보고서에 보존했다. 모의 22개 검사 결과를 실행 중 버전의 추가 검증으로 소급하지 않는다.

아이폰 사용자는 인증서 설치·신뢰 설정과 Safari 로그인 화면 표시를 확인했다. PC 자동 Chrome 탭은 `ERR_BLOCKED_BY_CLIENT`를 반환했고 인증서 오류로 단정하지 않았다. 인증·기기 간 메시지/미디어·단절/재접속 및 최종 정리는 아직 미완료다. 실제 시험 증거는 별도 진행 보고서에 구분해 기록한다.
