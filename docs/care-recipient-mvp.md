# 대상자 독립 계정과 주 소통자 MVP 설계

작성일: 2026-10-16. 상태: 독립 작업 사본에 첫 MVP 구현 및 합성 로컬 브라우저 검증 완료. 원본 반영·운영 배포·실제 사용자 평가는 미완료.

성장한 재활 대상자가 자신의 계정으로 소통에 참여하되, 보호자 계정과 기존 재활 기록은 그대로 보존한다. 주 소통자는 연락의 우선 대상일 뿐, 기록 열람·동의·관리 권한을 뜻하지 않는다. 나이를 기준으로 계정이나 권한을 자동 이전하지 않는다.

이 설계의 실행 범위는 합성 자료를 이용한 로컬 구현과 검증이다. 실제 대상자 등록, 실제 자료 권한 변경, 운영 DB 변경, 배포, 외부 접속은 포함하지 않는다. PC 사용성 평가의 원본 화면·서버 소스는 고정하고 `carebridge-recipient-work/workspace`에서만 구현했다. 원래 평가 세션은 종료됐으며, 별도 AI 기능 확인을 사람 평가 완료로 간주하지 않는다.

아래 현재 구조·위험 설명은 구현 전 기준선에 대한 설계 근거다. 구현 상태와 실제 시험 범위는 마지막 절 및 [검증 기록](care-recipient-verification-20261016.md)을 따른다.

## 1. 현재 구조와 확장 지점

| 영역 | 현재 구조 | 확장 시 보존할 원칙 |
| --- | --- | --- |
| 계정 | `cb_users`와 `cb_auth_accounts` | 대상자는 별도 사용자 ID와 로그인 계정을 사용한다. 보호자 계정·비밀번호·세션을 양도하지 않는다. |
| 센터 역할 | `cb_memberships`, 센터와 사용자 조합당 역할 하나 | 기존 보호자 역할을 대상자로 덮어쓰지 않는다. 일반 초대로 관리자 역할을 부여하지 않는다. |
| 재활 기록의 대상 | `cb_children`과 대상별 `cb_conversations` | 기존 대상 ID·기록·작성자·첨부를 유지한다. 계정 추가 때문에 기록을 복제하거나 이전하지 않는다. |
| 대화 연결 | `cb_participants`와 `first_sequence` | 센터 가입과 특정 대상 기록의 연결을 분리한다. 신규 대상자는 연결 이후 대화부터 접근한다. |
| 임상 기록 | 치료사 전용 원본과 별도 공유본 | 원본·내부 메모·평가 원문을 대상자에게 자동 공개하지 않는다. |

계정 생성과 대상 연결이 분리되어 있고, 대화의 이력 경계와 공유 버전이 존재하므로 기존 구조를 확장할 수 있다. 다만 현재는 치료사·보호자 중심의 권한 모델이다. 새 역할을 허용목록에 추가하는 것만으로 안전한 대상자 계정이 완성되지는 않는다.

관련 코드: `server/auth.mjs`, `server/relationships.mjs`, `server/conversations.mjs`, `server/profiles.mjs`, `server/records.mjs`.

## 2. MVP 범위와 보류 범위

우선 구현할 기능은 독립 대상자 계정, 명시적인 대상 연결, 주 소통자 표시·변경이다. 연결 이후 허용된 대화에서 자신의 목표·운동 소감·질문을 텍스트로 전달할 수 있게 한다. 이 텍스트는 치료사의 임상 목표나 보호자의 가족 관심사를 수정하는 기능이 아니다.

대상자 전용 목표 편집기, 기존 활동 소감에 대한 새 작성자 역할, 과거 자료의 소급 공개, 동의 대리·권한 이전 자동화는 첫 단계에 포함하지 않는다. 기존 공유 기록을 대상자가 열람하게 하는 기능은 수신자별 접근 검증을 완성한 다음 단계로 분리한다. 그 전에는 대상자에게 공유 카드·연결된 소감·그 첨부를 기본 비공개로 유지한다.

대상자의 첫 MVP는 일반 텍스트 송수신으로 한정한다. 일반 메시지의 사진·영상도 대상자에게는 업로드·수신·다운로드를 열지 않으며 파일명·썸네일·인용 미리보기로 대신 노출하지 않는다. 첨부 전 경로의 권한 검증 후 후속 단계에서 허용한다. 이 제한은 새 대상자 역할에 대한 것이며 기존 보호자·치료사의 첨부 기능은 유지한다.

## 3. 독립 계정과 대상 연결

내부 역할 이름은 기존 참여자 테이블과 혼동하지 않도록 `care_recipient`를 사용한다. 화면에는 ‘대상자’로 표시한다.

1. 활성 센터 관리자가 대상자 역할로 초대한다. 기존 초대 만료·일회성 토큰·현재 관리자 재검사 정책을 유지한다.
2. 초대 수락은 새 계정 또는 해당 역할과 충돌하지 않는 독립 계정의 센터 소속까지만 만든다. 아동 목록이나 대화 접근을 자동으로 만들지 않는다.
3. 관리자가 별도 연결 명령으로 계정과 재활 대상 기록을 연결한다. 기존 보호자·치료사 연결은 보존한다.
4. 신규 연결은 방을 잠근 트랜잭션 안에서 `last_sequence + 1`을 이력 시작점으로 확정한다. 재연결도 과거 이력을 자동 복원하지 않는다.
5. 연결 해제 후 다른 대상 기록에 같은 본인 계정을 임의로 재배정하지 않도록 안정적인 본인 연결 제약을 둔다. 잘못된 본인 연결의 정정은 일반 연결 버튼과 분리해 검토한다.

대상과 계정의 대응 관계는 별도 연결 모델로 관리한다. 센터 내에서 한 대상자의 본인 계정이 여러 대상 기록에 연결되거나 한 대상 기록에 여러 활성 본인 계정이 생기지 않도록 제약한다. 계정 복구·정정 절차는 기존 기록의 작성자 ID를 바꾸지 않는다.

기존 `Relationships.replace()`는 치료사·보호자로 구성한 활성 참여자 전체를 치환한다. 대상자를 추가한 후 기존 관리 화면을 저장하면 대상자가 누락되어 해제될 수 있다. 대상자 연결 전용 명령을 만들고, 기존 치환 명령의 변경 범위를 치료사·보호자로 한정하여 대상자 연결을 명시적으로 보존해야 한다. 요청에 필드가 없다는 이유로 해제 의사를 추정하지 않는다.

## 4. 주 소통자는 별도 메타데이터

주 소통자 설정은 대화방별로 현재 활성 보호자 또는 연결된 대상자 중 한 명을 지정하거나 미지정으로 두는 기능이다. 기존 활성 센터 관리자 권한으로 변경하며, 대상자의 의사와 필요한 검토 절차를 대신하는 기능으로 표현하지 않는다.

제안 필드는 방 ID, 지정 사용자 ID, 독립 버전, 변경자, 변경 시각이다. 동시 변경은 `expectedRevision`, 동일 요청 재전송은 `clientId`와 요청 해시로 처리한다. 감사 자료에는 연락 내용이나 민감한 판단 사유를 저장하지 않는다.

변경 시 다음 값은 바뀌지 않아야 한다.

- 계정·센터 역할, 관리자 권한, 로그인 세션
- 방 참여 여부, `first_sequence`, 읽음 위치
- 기록 수신자, 기존 기록·메시지의 작성자와 내용
- 동의 주체나 법적 대리 관계

주 소통자가 연결 해제되거나 계정·소속이 비활성화되면 현재 자격을 다시 검사한다. 가능한 변경 경로에서는 같은 트랜잭션에서 미지정 처리하고, 모든 조회·사용 경로에서도 활성 상태를 검증하여 오래된 지정값을 유효한 대상으로 표시하지 않는다. 다른 보호자나 대상자를 자동 승격하지 않는다.

구현에서는 계정·센터 소속·방 참여 각각의 `communication_generation`을 지정 당시 값과 비교한다. 활성 상태나 역할이 바뀌면 DB 트리거가 세대를 증가시킨다. 재활성화·재연결·예전 요청 재시도만으로 과거 주 소통자가 되살아나지 않으며, 관리자의 새 명시적 저장이 필요하다. 임상 기록 수신 권한에는 이 값을 사용하지 않는다.

화면에서는 대상자 정보·참여자 목록에 ‘주 소통자’를 표시하고 관리 화면에서만 변경한다. 일반 발신의 수신 범위는 바꾸지 않는다. ‘주 소통자’라는 표시를 개인 대화, 동의 완료 또는 다른 참여자에게 보이지 않는 메시지로 오인하게 해서는 안 된다.

## 5. 정보 공개의 기본 규칙

| 자료 | 새 대상자의 기본 접근 | 추가 구현 조건 |
| --- | --- | --- |
| 연결 이전 일반 메시지·사진·영상 | 비공개 | MVP에서 소급 공개하지 않음 |
| 연결 이후 일반 텍스트 대화 | 현재 참여와 이력 경계 내에서 허용 | 발신자가 현재 참여자를 확인할 수 있어야 하며, 모든 인용·답글은 원문의 별도 접근 권한도 검사 |
| 일반 대화의 사진·영상 | 첫 MVP에서 송수신 차단 | 후속 첨부 권한 검증 이후 허용. 파일명·썸네일·인용 미리보기와 직접 다운로드도 차단 |
| 치료 기록 공유본·활동·연결된 소감 | 기본 비공개 | 정확한 버전과 명시적 대상자 수신 지정, 모든 읽기 경로에 같은 접근 규칙 적용 후 허용 |
| 임상 원본·내부 메모·평가 원문 | 비공개 | 치료사 전용 경계 유지 |
| 기존 보호자의 가족 관심사 | 비공개 | 대상자 역할 추가로 현재값을 자동 공개하지 않음 |
| 기존 임상 목표·일정 | 기본 비공개 | 필요한 운영 정보와 공유 기준을 별도로 정한 뒤 최소 범위만 허용 |
| 대상자가 새로 보낸 목표·소감·질문 | 허용된 일반 대화로 전달 | 보호자 관심사나 임상 목표를 덮어쓰지 않음 |

이름과 참여 역할 등 대화에 필요한 최소 연결 정보만 제공한다. 개인 연락처·계정 이메일·관리자 메모는 참여자 표시만을 위해 추가 노출하지 않는다.

### 공유 기록의 수신자 검증

현재 `cb_record_recipients`는 공유 당시 보호자 수신자를 기록하지만 대화의 읽기 경로는 이를 수신자별 접근 제어 목록으로 사용하지 않는다. 대상자를 방에 추가하기만 하면 미리보기의 수신자에는 없는데도 새 공유 카드를 볼 수 있는 설계 위험이 있다.

첫 단계의 기본 비공개부터 카드 직접 조회·목록·홈 미리보기·미확인 수·읽음·피드백·인용·사진 및 영상 다운로드까지 같은 규칙을 적용한다. 연결 이후 만들어진 보호자 전용 공유본도 대상자에게는 비공개이다. 이를 일반 메시지가 인용하더라도 제목·반응·첨부 미리보기는 제공하지 않으며, 비공개 원문을 지정한 답글 작성이나 읽음 처리 요청으로 접근 제한을 우회할 수 없어야 한다. 목록에서만 숨기거나 직접 URL 접근을 남기는 방식은 허용하지 않는다.

후속 명시적 공유 기능은 이 공통 경계를 기반으로 지정한 대상자에게만 접근을 연다. 기존 보호자에게 승인된 과거 이력 정책은 별도 호환 규칙으로 보존하며, 기존 수신자 기록을 곧바로 전체 역할의 접근 목록으로 전환하지 않는다.

관련 코드: `server/conversations.mjs`, `server/media-bindings.mjs`, `server/media-access.mjs`, `server/message-read-states.mjs`, `server/activity-feedback.mjs`.

### 보호자 전용 조건의 확장

철회 카드·철회된 인용·첨부 차단에는 현재 `role === 'guardian'` 조건이 있다. 대상자 역할을 추가하면서 이 조건을 그대로 두면 철회 내용이 대상자에게 노출될 수 있다. 임상 내부 접근과 외부 공유 접근을 구분하는 공통 정책으로 바꾸되, 무조건 `role !== 'therapist'`로 치환하지 않는다. 각 경로의 허용 역할과 현재 참여 여부를 함께 검사한다.

`Children.get()`의 가족 관심사와 `Goals.get/list()`의 현재 목표는 대화의 과거 이력 경계와 별개로 제공된다. 대상자 응답에는 별도의 최소 투영을 적용한다. 이 항목들은 역할 확장 시 해결해야 할 위험이며, 현재 2역할 모델의 실제 정보 유출을 확인했다는 의미는 아니다.

## 6. 구현 순서

1. PC 사용성 평가의 원본·소스 기준을 보존한다. 승인된 독립 사본에서 구현하되 자동 준비 검사·AI 대행·실제 사람의 수행 결과를 구분한다.
2. 외부 공유 접근 정책과 대상자 기본 비공개 경계를 먼저 정의하고 실패하는 합성 시험을 작성한다.
3. 후속 마이그레이션으로 역할 제약·본인 연결·주 소통자 버전·요청 영수증을 추가한다. 기존 마이그레이션과 기록 ID를 수정하지 않는다.
4. 초대·연결·주 소통자 서비스 및 제한된 로컬 HTTP 계약을 구현한다. 화면에서 보낸 역할값을 권한 근거로 신뢰하지 않는다.
5. 기존 관계 저장이 대상자를 보존하도록 변경하고 비활성화·재연결·동시 변경을 검증한다.
6. 역할별 홈·대상자 정보·초대·연결·참여자 표시를 구현한다. 열람할 수 없는 메뉴를 제거하되 서버 차단은 별도로 유지한다.
7. 명시적 기록 공유와 대상자 첨부 기능은 해당 권한 검증 전 경로가 준비된 뒤 추가한다. 이 단계 전에는 일반 텍스트 대화 참여와 주 소통자 기능만 제공한다.
8. 기존 보호자·치료사·센터 회귀, 모바일·PC 화면, 재시작 및 복원 후 권한 보존을 합성 자료로 확인한다.

기준선의 마이그레이션 001–022는 유지하고, 독립 사본에 `023-care-recipient-links.sql`을 추가했다. `server/migrate.mjs`가 적용 이력의 체크섬을 검사한다. 권한 정책 7은 테이블 66개·함수 57개의 정확한 권한 목록을 사용한다. 복원 비교는 격리 과정에서 활성 계정을 비활성화할 때 생기는 계정 세대 증가 1회만 원본 측의 예상값에 반영하며, 복원본 실제 값·회원/참여 세대·주 소통자 스냅샷은 그대로 비교한다. 편의를 위한 `GRANT ALL` 또는 인증 우회는 추가하지 않았다. 이후 새 E 합성 DB의 서비스 입장·재시작·복원 검사를 수행했으며, 실패·수정·재검사 범위는 검증 기록 6절에 구분했다. 기존 E DB 이관이나 서비스 활성화는 하지 않았다.

## 8. 실제 운영 전에 결정할 사항

- 본인 확인, 본인의 의사 및 필요한 동의 확인 주체·절차·철회 처리
- 보호자와 대상자 의사가 다른 경우 주 소통자를 정하는 절차
- 별도 이메일 확보가 어려운 대상자의 계정 발급·복구 방법
- 잘못된 본인 연결을 정정하는 승인 절차와 감사 범위
- 대상자에게 공유할 활동·기록·일정의 범위와 화면 표현

이 사항들은 합성 로컬 구현과 분리된 운영 결정이다. 나이, 체크박스 하나 또는 주 소통자 지정만으로 해결되었다고 간주하지 않는다. 실제 자료 사용과 배포 전에는 별도 검토가 필요하다.

## 9. 독립 사본의 구현 상태

- 별도 대상자 초대·수락·로그인과 본인 표시 이름, 관리자 연결·해제, 버전 충돌 및 정확한 재시도 처리.
- 연결 이후 일반 텍스트만 제공하는 공통 서버 조회 경계. 임상 기록·활동·가족 관심사·목표·일정·첨부는 새 역할에 비공개.
- 대상자 메뉴는 홈·대화·참여 정보 3개. 기존 보호자·치료사 4개 메뉴와 센터 운영 화면은 유지.
- 주 소통자 지정은 별도 메타데이터로 저장하며 기존 참여·읽음·수신자를 변경하지 않는다.
- 390px와 1440px의 새 소유 브라우저에서 실제 UI 초대→연결→대화→보호자 수신→주 소통자 변경→새로고침을 확인했다. 기존 사용자 Chrome에 연결하지 않았다.
- 메뉴 개수에 대한 불필요한 인라인 스타일을 제거해 기존 CSP를 유지했다. 기존 외부 CSS의 flex 배치가 메뉴 수에 맞춰 동작한다.
- 비어 있지 않은 023 복원 fixture와 Windows/Linux 실행기 연결을 보완했다. 후속 Windows native 복원·격리 27개와 역할 권한 48개 검사를 별도 실행했다. 역할 검사에서 발견한 기존 보호자 미디어 작업의 권한 회귀를 추가 권한 없이 수정하고 재통과했다. 단계별 코드 버전과 실제 증거·대역·남은 제한은 [검증 기록 6절](care-recipient-verification-20261016.md#6-후속-실제-windows-postgresql-검증)을 따른다.
- 최종 권한 수정본에서도 기존 브라우저 검사를 한 번 실행해 390px/1440px의 대상자 텍스트 수신·주 소통자 재조회·자료 접근 차단과 임시 자원 종료를 확인했다. 실행 `8bb1d96e-46e0-4ae0-bd4b-6093f89a64a8`의 범위·소스 지문·한계는 [검증 기록 7절](care-recipient-verification-20261016.md#7-최종-권한-수정-후-제한된-브라우저-재검증)에 분리했다. 사람 평가 또는 실제 iPhone 검증 결과가 아니다.

이는 가상 자료의 첫 MVP이며 실사용 승인이나 개편안 전체 완료가 아니다. 대상자 선택 공유·첨부, 최신 변경의 실제 iPhone 시험, 사람의 A/B 시간·이동 수·C 이해도 평가는 남아 있다.
