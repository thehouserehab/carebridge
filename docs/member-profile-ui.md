# 구성원 본인 표시 이름 — 로컬 UI와 공통 입력 계약

2026-10-03. 상단의 `내 표시 이름`에서 현재 가상 계정의 표시 이름을 설정·해제할 수 있다. 홈·대화·아이 정보·센터 명단·담당 관계 선택지에 같은 이름을 사용한다. **실제 로그인·서버 연결·권한 변경이 아닌 로컬 체험 기능**이다. API는 마지막 단계로 유지하며 실제 이름·연락처·건강정보는 입력하지 않는다.

## 확인 방법

1. 로컬 앱 상단의 `내 표시 이름`을 연다. 모바일에서는 같은 접근성 이름을 가진 사람 아이콘이다.
2. 가상 이름을 1~30자로 입력해 저장한다. 빈 칸으로 저장하면 기본 표시로 돌아간다.
3. 홈·대화와 센터의 `구성원`에서 표시를 확인한다. 같은 브라우저·주소에서 새로고침해도 유지된다.
4. 치료사·보호자·센터의 설정은 서로 분리된다. 이름 변경으로 담당 관계나 다른 계정의 이름이 바뀌지 않는다.

저장 실패·다른 탭의 변경 충돌에서는 입력을 유지하고 이전 저장값을 덮어쓰지 않는다. 충돌 후에는 최신값을 확인하고 다시 수정한다. 설정 도중 가상 계정이 바뀌면 저장을 거부한다. Enter 제출, Escape 종료, 닫은 뒤 설정 버튼으로 포커스 복귀를 제공한다.

## 데이터·권한·기존 이력 경계

- 기존 localStorage 키와 schema 3을 유지한다. 선택적인 `memberProfiles`에 고정 체험 센터 ID·가상 사용자 ID·표시 이름만 저장한다. 프로필이 없는 이전 데이터는 읽을 때 일괄 수정하지 않는다.
- 로컬 fixture 등록부에 있는 현재 가상 계정만 설정할 수 있다. 입력에서 다른 사용자·센터·역할·아동·비밀번호를 지정할 수 없다. 새 초대 시연 계정에 프로필이나 아동 접근권한을 자동 생성하지 않는다.
- 기존 메시지의 발신 ID·기록·공유 스냅샷·읽음·담당 관계·미디어 ID와 원본 바이트는 유지한다. 과거 메시지에서도 발신 ID에 연결된 **현재 표시 이름**을 보여 주며 당시 이름의 별도 이력을 생성하지 않는다. 이전 치료사를 보호자로 표시하지 않는다.
- 이름은 HTML로 실행하지 않고 텍스트로 이스케이프한다. 표시 이름은 신원 확인이나 서버 권한의 증거가 아니다.
- 센터 구성원 화면은 조회용 사본에만 현재 이름을 반영한다. 초대용 메모리 상태·로그인 이메일·다른 센터 계정의 이름을 덮어쓰지 않는다.
- 서버는 기존 `MemberProfiles.saveSelf`의 세션·센터 소속·버전·영수증 검사를 유지한다. 순수 내용 검증만 `src/profile-fields.js`로 공통화했다. 앞뒤 줄바꿈/탭도 공백 정리 전에 거부하며 null만 명시적 해제로 취급한다. HTML 폼의 빈 문자열을 null로 바꾸는 것은 로컬 폼 경계에서만 한다.
- 저장소 읽기 오류는 공개 안내로 변환해 내부 예외 원문을 폼에 노출하지 않는다. 브라우저 개발 도구로 로컬 데이터에 접근할 수 있다는 기존 한계는 변하지 않는다.

## 변경 파일

- `src/member-profiles.js`: 가상 구성원 조회·현재 이름·엄격한 선택 프로필 검증·본인 설정.
- `src/profile-fields.js`, `src/profile-ui.js`: 공통 이름 검증·빈 폼 어댑터·설정 화면.
- `src/app.js`, `src/chat-ui.js`, `src/domain.js`, `src/repository.js`: 진입/저장/포커스·화면 표시·발신 역할·수정 주체와 저장 실패 보호.
- `src/config.js`, `src/onboarding-demo.js`, `src/onboarding-controller.js`, `src/onboarding.css`: 체험 센터 상수 재사용·명단 조회 표시·작은 화면의 44px 설정 버튼.
- `server/profiles.mjs`, `server/tests/profiles.test.mjs`: 공통 내용 규칙 재사용과 제어문자 거부 회귀. SQL·인증 HTTP 경로·새 API는 변경하지 않았다.
- `tests/member-profiles.test.mjs`, `tests/member-profiles-browser.mjs`, `tests/layout-browser.mjs`: 내용/보존·실제 브라우저 저장/충돌·긴 이름/설정 모달 검증.
- `tests/media-browser.mjs`: 비동기 갤러리 로딩 후 공유 사진을 검증하도록 대기 경계를 수정했다. 사진 개수·실제 디코딩·비공유 영상 제외 검사는 유지했다.
- README와 관련 구현 문서: 현재 로컬 완료 범위·검증 결과·남은 운영 작업 갱신.

브라우저 검증 스킬에 따라 전용 Chromium의 독립 컨텍스트를 사용해 시작 화면·이름 설정·콘솔·스크린샷을 확인했다. 사용자의 탭/저장소를 초기화하지 않았다. 합성 정보와 합성 사진만 사용했다. 결과와 화면은 공개 저장소/배포에서 제외된 `test-results/member-profiles-*`, `test-results/layout-*` 및 각 회귀 시험 결과에 남긴다. 실행에는 기존 Playwright 모듈과 전용 브라우저의 `PLAYWRIGHT_MODULE`, `CDP_URL`, `APP_URL`을 지정한다.

이전 중단의 native 확인창 응답 오류 원인은 확정하지 못했다. 자동 응답을 하지 않는 별도 관찰 시험에서는 확인창이 실제 응답을 기다렸으므로 브라우저 CLI가 자동 수락한다고 결론 내리지 않았다. 이번 재실행은 응답 전에 창이 종료되는 조건을 별도 경고로 기록하면서 기존 저장/종료 검사를 유지했고, 해당 오류나 경고가 재발하지 않았다. 재발 시 경고 종류와 실패 상태를 함께 조사해야 한다.

이번 미디어 회귀의 첫 실패는 IndexedDB에서 사진을 읽기 전에 개수를 검사한 비동기 대기 누락이었다. 실패 직후 화면에는 정상 사진이 표시됐다. 이미지가 보이고 실제로 디코딩된 뒤 사진 1개·비공유 영상 0개를 확인하도록 고친 재실행 7묶음은 통과했다. 제품의 공유 범위나 저장 규칙을 완화하지 않았다.

## 남은 위험과 다음 순서

현재는 로컬 UI와 서버 내부 내용 계약을 준비한 단계다. 실제 인증된 표시 이름 변경·서버 명단/프로필 캐시 갱신·메일·기기 간 동기화는 미구현이다. Chromium 자동화는 실물 iOS/Android/Safari나 보호자·치료사의 사용성 확인을 대체하지 않는다. GitHub push/Vercel 배포·유료 자원·운영 계정 생성은 하지 않았다.

다음은 실제 파일 검사/디코딩의 격리 실행환경과 국내 인프라·보존/파기·메일/복구·백업 준비다. 현재 PC의 Docker/WSL 설치 또는 승인된 국내 실행환경 결정이 필요하며 승인 전에는 시스템을 설치하거나 실제 파일 승인 기능을 활성화하지 않는다. 업로드 상태의 실제 서버 연결도 아직 남아 있다. 그다음 마지막 API 단계에서 세션 기반으로 화면을 연결한다. 이 작업으로 P1/전체 개편안/국내 통제가 완료된 것은 아니다.
