# 편집 중 다른 탭 변경 — 충돌·갱신·첨부 보존

작성·검증일: 2026-10-06

## 현재 상태와 실제 문제

개편안의 담당 관계·기록·공유 흐름을 이어서 검토했다. 다른 탭에서 데이터가 변경되면 최종 JSON 저장의 revision 검사가 오래된 입력의 덮어쓰기를 막고 있었다. 그러나 편집창이 열려 있을 때 storage 이벤트를 안내만 하고 버렸으며, 창 종료 후 최신 상태를 다시 읽지 않았다.

실제 가상 센터 폼에서 하루의 치료사를 교체한 뒤 치료사 탭의 기록 저장이 거부되는 것은 확인했다. 입력과 사진도 남았다. 문제는 편집창을 닫은 뒤에도 하루가 선택된 채 해제된 담당자의 기록 화면이 계속 보였다는 점이다. 수정 전 브라우저 실행은 최신 담당 아동 `c2`로 전환되는 검사에서 시간 초과로 실패했으며 당시 화면을 확인했다. 이는 운영 인증을 우회한 증거가 아니라 로컬 화면 갱신 오류다.

또한 기존 commit은 이미 알 수 있는 revision 충돌도 새 Blob을 쓴 뒤 JSON 저장 시 발견했다. 새 파일을 롤백하는 기존 보호는 있었지만 불필요한 파일 쓰기를 먼저 수행했다.

## 변경한 동작

| 경계 | 현재 처리 |
| --- | --- |
| 편집 중 다른 탭 변경 | 입력창·선택 파일을 다시 만들지 않는다. 창 안에 지속적인 변경 안내를 추가하고 최신 내용을 자동으로 입력에 합치지 않는다. |
| 오래된 입력 저장 | 공통 revision 사전 검사로 파일 쓰기 전에 거부한다. 입력·첨부 메타데이터·원본 Blob은 창이 열린 동안 유지된다. |
| 비동기 파일 준비 이후 | 기존 persist의 최종 revision 검사도 유지한다. 사전 검사 후 발생한 변경은 최신 JSON을 덮어쓰지 못한다. 기존 새 파일 롤백 절차는 유지한다. |
| 창의 최종 종료 | 현재 저장소를 다시 읽고 최신 관계·기록·표시 이름을 반영한다. 종료 알림이 지연됐거나 놓쳤어도 현재 상태를 재조회한다. |
| 기록 저장 → 공유 준비의 재열림 | 이전 close 이벤트 시 새 창이 열려 있으면 갱신/정리를 하지 않는다. 새 미리보기와 첨부 로딩을 취소하지 않는다. |
| 최신 저장소 손상/소실 | 기존 화면을 계속 보여 주거나 초기 샘플로 자동 대체하지 않는다. 안전한 오류 화면으로 전환하며 읽기/형식 오류의 내부 상세를 노출하지 않는다. |
| 추가 clear 이벤트 | 초기 읽기 오류와 이후 오류 상태에서도 ‘기존 저장소를 요구함’을 기억한다. db가 null이라는 이유로 샘플을 다시 만들지 않는다. 실제 localStorage의 key=null 이벤트도 처리한다. |

revision 판정은 `repository.js`의 `assertRevision()` 하나로 공통화했다. UI와 persist에 서로 다른 충돌 규칙을 복사하지 않았다. persist는 새 상태 연결 검증 → revision 확인 → JSON 쓰기 순서를 유지한다. `load()`의 선택 사항 `requireExisting`은 처음의 빈 데모 실행을 허용하되, 이미 사용 중이거나 읽기 오류가 난 작업공간의 자동 샘플 복귀를 막는다.

현재 DOM 안내는 필요한 입력을 보관한 뒤 창을 닫고 최신 내용을 확인하도록 설명한다. **닫기는 기존 확인창에서 미저장 입력을 버리기로 명시한 경우다.** 이 작업은 세션 기록 폼의 장기 자동 저장·자동 병합·충돌 내용 다운로드 기능을 추가하지 않았다. 사진 원본의 실제 위치와 당시 공유본은 삭제하지 않으며, 선택만 한 새 사진은 창을 닫아 버리면 다시 선택해야 한다.

아동별 조회/발신·센터의 임상 비노출·공유 철회·읽음/임상 반영 정책은 변경하지 않았다. 저장 형식·키·기존 ID·SQL·서버 인증·API·운영 배포도 그대로다. 의존성을 추가하지 않았다.

## 실제 브라우저 검증 범위

브라우저 검증 스킬로 루프백 개발 화면의 로딩·홈·메뉴·콘솔을 확인하고 다음 흐름을 검사했다.

기록/공유/설정 창 → 다른 탭의 실제 센터 관계 관리 또는 합성 저장 실패 주입 → 실제 localStorage 이벤트 → 입력 유지와 저장 거부 → 명시적 창 종료 → 현재 저장소 조회와 역할별 화면.

각 사례는 전용 Chromium의 새로운 비영구 컨텍스트와 합성 탭 두 개를 사용한다. 사용자 Chrome 프로필·탭·기존 저장 내용은 채택하지 않는다. clear/remove/corruption 주입도 해당 시험 컨텍스트에만 적용한다. 이벤트를 직접 만들어 발송하거나 API 성공 응답을 조작하지 않는다.

1440×1000, 390×844, 320×844에서 다음 다섯 사례씩, 총 15개 검증 묶음을 수행한다.

1. **작성 중 담당 해제**: 활동·반응·다음 계획과 실제 PNG를 넣고 센터 폼으로 담당자를 바꾼다. 오래된 초안 저장은 거부되며 입력·메타데이터·원본 바이트가 동일하다. 새 파일 쓰기 호출이 0회이고 파일 저장소에도 새 ID가 없다. 닫은 뒤 현재 담당 아이만 표시한다.
2. **오래된 공유 수신자**: 열린 공유 미리보기의 보호자를 센터 폼에서 교체한다. 이전 미리보기로 공유하지 못하고 원래 기록/공유본을 유지한다. 창을 닫아 새로 열면 최신 수신자를 표시하고, 명시적으로 확인한 뒤 새 공유본 한 개를 생성한다.
3. **설정 중 저장소 소실**: 실제 UI로 저장된 작업공간을 합성 탭에서 제거한다. 설정 창 종료 후 오류 화면이며 새 샘플/JSON 쓰기가 없다. 추가 clear 이벤트에도 오류 상태를 유지한다.
4. **설정 중 JSON 손상**: 합성 손상 원문을 덮어쓰지 않는다. 종료 후 임상 화면을 숨기고 추가 clear에서도 샘플을 생성하지 않는다.
5. **초기 JSON 손상 후 clear**: 처음부터 오류 화면인 경우에도 실제 clear 이벤트를 관찰해 자동 샘플 복귀를 거부한다.

PNG 원본 비교는 실제 편집기의 메타데이터와 Blob 바이트를 읽는다. 파일 쓰기 계수는 실제 MediaStore.write를 감싸 관찰하며 다른 동작을 성공으로 바꾸지 않는다. clear 이벤트 처리도 DOM MutationObserver와 제한 시간 있는 대기로 확인한다. 가로 넘침과 페이지/콘솔 오류·API/외부 요청을 검사한다.

초기 시험 준비에서 존재하지 않는 반응 필드 이름을 사용했고 모바일에서 숨겨진 사이드바 안내 버튼을 선택해 중단됐다. 실제 `아이의 반응` 레이블과 모든 화면에서 접근 가능한 본인 표시 이름 버튼으로 시험 준비를 수정했다. 제품 문제인 창 종료 후 최신 관계 미반영과 이를 구분하며, 기능/권한/파일 검사를 완화하지 않았다.

새 단위 검사 5개는 초기 빈 저장소와 기존 소실의 구분, 손상/접근 거부의 안전한 안내, 사전 검사의 비쓰기, 충돌/연결 오류 차단, 사전 검사 이후 변경의 최종 저장 거부를 확인한다. 마지막 사례는 단위 검사이며 실제 파일 쓰기를 지연시킨 기록 폼 브라우저 시험으로 확대 해석하지 않는다.

## 남은 위험과 다음 우선순위

1. 로컬 역할 전환은 실제 인증/권한 경계가 아니다. 이미 읽은 내용을 회수할 수 없으며 실제 계정의 기기 간 권한 회수·서버 동기화·파일 전달은 P1 연결 뒤 검증해야 한다. 서버·SQL·인증을 수정하지 않아 서버 시험을 이번 결과로 재인용하지 않는다.
2. 기록 폼의 미저장 입력/새 사진은 현재 열린 창에서만 보존된다. 명시적으로 버린 뒤의 복원·OS 강제 종료·저장소 회수 복구를 보장하지 않는다. 대화 초안의 별도 IndexedDB 복원과 구분한다. localStorage revision 검사는 여러 탭의 완전히 동시에 발생하는 쓰기를 원자적으로 직렬화하는 서버 트랜잭션이 아니며, JSON과 Blob을 하나의 저장소 트랜잭션으로 묶은 것도 아니다. 이번 시험을 그 보장의 증거로 확대하지 않는다.
3. 실물 iOS/Android/Safari, 치료사/보호자 과제 완주·사람의 소요 시간·공유 요약 이해도 확인은 아직 필요하다. 자동화 시간·검사 수를 사람의 사용성 성과로 주장하지 않는다.
4. 국내 공급자/예산·메일·영구 파일/키·보존/파기·관리자/계정 복구·운영 승인과 [복구 준비](recovery-readiness.md)는 미완료 상태로 유지한다. 임의의 관리자 우회 기능이나 유료 자원을 만들지 않는다. API는 사용자의 순서대로 마지막에 연결한다.
5. 다음 로컬 검토는 이전 목표·측정 항목을 가져온 새 회기에서 관찰값을 복사하지 않고 초안/정식 저장을 구분하는 흐름이다. P2는 사용자 필요가 확인된 경우에 우선순위를 정한다.

전체 개편안의 완료 기준을 이 15개 검사로 줄이지 않는다. 실제 아동 정보·사진·건강 데이터를 입력하거나 로컬 저장소를 유일한 원본으로 사용하면 안 된다.
