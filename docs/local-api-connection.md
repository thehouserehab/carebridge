# 가상 자료 전용 로컬 API 연결

최신 UI 연결(2026-10-10): [인용 답장의 사진·영상](local-prepared-media-ui.md#2026-10-10-인용-답장에-사진영상-연결). 활동 없는 공유 기록에도 첨부 답장을 보낼 수 있다. 기존 메시지 API를 사용하며 원문 판·파일·발신 번호를 고정하고, 서로 다른 답장/방의 선택 파일을 분리한다. 새 E 세션에서 실제 검사/저장/수신/재생·응답 유실 재시도·공유 종료 후 독립 첨부 열람이 통과했다. `--reply-attachments` 전용 검증 결과와 재현 명령은 링크 문서를 따른다. 기본 격리 모드·SQL·인증/권한·키 보존 정책·공개 배포는 바꾸지 않았다.

최신 E 검증(2026-10-10): [현재 스키마의 비공개 반영 메모와 API 재시작](synthetic-e-session.md#2026-10-10-현재-스키마의-비공개-반영-메모와-재시작-검증)에서 새 가상 PostgreSQL 세션의 **22/22** 항목과 실제 종료/소유 자원 정리를 확인했다. 스키마022/권한 v6 준비 후 일반 소식 메모 저장·보호자 비노출·새 로그인 복원·동일 요청 재확인을 포함한다. 기존 E 세션 업그레이드나 완전 종료 후 재개는 아니다. 초대/복구의 비공개 가상 전달은 여전히 별도 메모리 하네스 범위이며 native 실행기에는 활성화하지 않았다. 실제 자료·외부 접속·배포 보류를 유지한다. 아래의 메모리 API 범위와 각 단계 이력을 구분한다.

최신 후속(2026-10-10): [센터별 본인 표시 이름 연결](local-self-profile.md). 상단 계정 설정 → 본인 API → 기존 저장 서비스 → 다른 가상 계정 화면 반영을 연결했다. 촬영 도구 수정 후 한 번의 최종 390/768/1440px 검증에서 기능 **75/75**와 자원 정리를 통과했다. 오류/예상 밖 요청 0·실제 종료 0·소스 지문 일치를 확인했으며 이전 두 실패는 보존한다. 기존 단위1,234·서버 집중84·구문/빌드 근거는 상세 기록에 구분했다. 완전 종료 후 같은 E 가상 세션 재개는 키 보존 선택 이후의 별도 작업이다. 실제 자료·외부 접속·배포 보류는 그대로다. 아래는 각 단계 당시 기록이다.

작성 2026-10-08 · 갱신 2026-10-10. 사용자가 승인한 범위는 **가상 계정·자료로 로컬 로그인 → 서버 저장 → 다른 시험 브라우저 수신**이다. 실제 자료·외부 접속·배포 승인이 아니다. 원 개편안 전체와 사람 대상 비교·실물 기기 검증은 미완료로 유지한다.

## 현재 연결 범위

현재 범위는 아래 목록과 [본인 표시 이름](local-self-profile.md), 이 문서의 가상 초대·복구 및 센터 운영 연결 절을 따른다. 날짜별 결과와 당시 남은 작업은 이력이며 현재의 미구현 목록으로 해석하지 않는다. 전체 서비스 완료를 뜻하지 않는다.

이 절은 기본 `npm run dev:local-api` 화면의 범위다. 별도의 합성 Windows PostgreSQL/API 자식·검사 작업자 결합은 [Windows 연결 기록](windows-local-api-connection.md)에, 후속 명시적 `prepared` 시험 화면은 [사진·영상 송수신 기록](local-prepared-media-ui.md)에 구분했다. 기본 실행기를 영속 DB/준비 첨부 UI로 자동 전환하지 않는다. 아래 날짜별 단계와 당시의 다음 작업·검증 수치는 각 시점의 기록이다.

기존 정적 프로토타입은 그대로 보존했다. `local-api/`는 기존의 전체 가상 DB·역할 선택기를 가져오지 않는 별도 연결 시험 화면이다. 기존 `Auth`, `Conversations`, `Children` 및 기록·피드백·목표·일정 서비스를 실제 HTTP와 연결하고, 서버가 현재 로그인 사용자에게 허용한 최소 응답만 표시한다. 임상·메시지 규칙을 새로 복제하지 않는다. 2026-10-08 텍스트 연결에 이어 2026-10-09 기록·공유·피드백 경로를 추가했다.

- 매 실행 생성한 치료사·보호자·센터 관리자 가상 계정으로 로그인, HttpOnly 세션 확인·로그아웃. 센터 계정은 운영 현황·아동·일정의 별도 화면을 사용하며 임상 대화에 참여하지 않는다. 아동 등록/기본정보, 담당 관계·과거 열람 범위의 명시적 연결, 일정·출결과 가상 초대를 관리한다.
- 초대 수락과 비밀번호 복구는 비공개 가상 전달 하네스로 검증했다. 실제 메일이나 공개 시험 메일함은 제공하지 않는다. 각 역할의 계정 설정에서는 이 센터의 본인 표시 이름만 변경한다.
- 허용된 아동의 홈 소식 → 해당 대화 → 텍스트 발신·조회·화면에 나타난 메시지 읽음.
- 다른 브라우저 세션에서 약 5초 간격 조회로 수신·읽음 확인. 푸시 알림이나 실시간 소켓으로 표현하지 않는다.
- 브라우저 새로고침 뒤 서버의 대화 재조회. DB는 **메모리 PGlite**이며 서버 재시작 시 계정·대화가 모두 사라진다. E 드라이브 영속 DB와 연결하지 않았다.
- 치료사 기록 임시저장/정식 저장 → 수신자·공개 내용 미리보기 → 보호자 공유 → 가정 활동 피드백 → 치료사 비공개 검토/공개 인용 답장 → 다음 기록에 당시 버전 참고 → 재공유/공유 종료.
- 기본 3칸과 선택 상세 관찰·여러 측정값, 보호자 요약/가정 활동, 치료사 내부 메모를 구분한다. 측정값 0은 빈값과 다르게 보존하며 초안의 미완성 입력은 정식 저장 검사를 완화하지 않는다.
- 기록 목록의 ‘양식으로 새 기록’은 현재 열람 가능한 이전 버전의 목표·측정 항목만 가져온다. 수치·본문·관찰·첨부·참고·일정은 복사하지 않으며 새 기록으로 저장한다. 아래 R05 연결 절에 검증 범위를 구분했다.
- 일반 메시지 메뉴에서 인용 답장·치료사 기록 참고·본문 수정·나에게만 삭제·모두에게서 삭제를 연결했다. 공유 카드에도 공개 인용 답장을 보낼 수 있다. 본문 수정과 전체 삭제의 24시간 제한은 기존 Carebridge 초기 정책이며 서버 시계와 현재 권한으로 다시 검사한다. 카카오톡의 모든 정책과 같다는 뜻은 아니다.
- 4메뉴의 홈 소식·월별 일정·아이 정보 조회와 일정에서 기록 진입, 일반 소식의 비공개 반영 메모, 보호자 가족 관심사 편집과 현재 활동 접근, 치료사 목표·일정 편집을 연결했다. 기본 실행기의 사진·영상은 아래의 **비공개 격리 업로드 시험만** 가능하며 검사·상대방 전송·파일 열람은 제공하지 않는다. 준비 첨부를 지원하는 별도 E 실행기와 구분한다. 기존 정적 프로토타입, 메모리 API 화면, E/native 시험의 증거를 혼동하지 않는다.

## 안전 경계와 실패 처리

1. 실행기는 `127.0.0.1`만 수신한다. 설정 입력은 포트 `0` 또는 `1024~65535`뿐이며, 운영 환경변수·DB 주소·파일 경로·공급자 자격증명을 채택하지 않는다. 실행마다 다른 계정·비밀번호·쿠키 이름을 사용한다.
2. 모든 요청에서 실제 루프백 소켓·Host·출처를 확인한다. 변경 요청은 정확한 Origin과 전용 요청 헤더가 필요하며 CORS는 열지 않는다. 일반 변경은 JSON이고, 정확한 업로드 `/content` 경로만 크기·버전 헤더가 있는 바이너리를 받는다. 정적 파일은 listener의 명시적 허용 목록으로만 제공하고 서버 코드·환경 파일·기존 인증 실험 경로는 제공하지 않는다. 뷰어 모듈을 제공해도 기본 격리 모드의 파일 열람 권한이나 Blob CSP는 활성화하지 않는다.
3. 신원은 서버가 검증한 쿠키에서만 결정한다. 요청의 사용자 역할·사용자 ID는 권한 근거로 받지 않는다. 보호된 조회·변경은 **화면이 확인한 계정과 현재 쿠키 계정이 같은지**도 확인한다. 이는 계정 전환 경합 방지용 사전 조건이지 인증 수단이 아니다. 다른 탭에서 계정이 바뀐 경우 이전 탭의 발신·재시도·읽음은 거부된다.
4. 사용자별·센터별·아동 담당·과거 열람 범위는 기존 서비스가 매 요청 다시 검사한다. 일반 대화 응답에는 세션 토큰, 비밀번호, 내부 임상 검토, 상세 기록, 파일 경로를 넣지 않는다. 상세 기록과 임상 검토는 치료사 전용 요청으로만 조회하며 보호자에게는 공유한 시점의 요약·활동만 제공한다.
5. 임상 대화의 여러 페이지는 하나의 변경 버전으로 끝까지 확인한 후 교체한다. 대화 목록을 읽은 뒤 프로필·선택 대화를 조회하고, 마지막에 목록의 변경 토큰을 다시 대조해 대화 변경 전 미리보기와 변경 후 본문을 섞지 않는다. 중간 버전·관계 변경은 전체 묶음을 최대 3회 재조회하며, 한도나 반복 변경 시 일부 결과만 완전한 목록인 것처럼 표시하지 않는다. 이 토큰은 서버 대화 revision·과거 열람 범위·역할의 변경 감지용이며, 모든 프로필 필드의 원자적 조회나 접근 권한을 부여하는 토큰은 아니다. 별도 센터 목록은 키 기반 페이지 조회이며 전체 시점 일치를 보장하지 않는다. 목록에서 사라진 것만으로 초안을 폐기하지 않고, 상세 조회·저장 때 현재 아동/센터 권한을 재검사한다.
6. 전송 응답이 유실되면 본문과 요청 ID를 고정하고 같은 요청으로 재시도한다. 내용이 다른 새 요청으로 임의 재전송하지 않는다. 명백한 입력 거부·버전 충돌처럼 저장하지 않은 확정 응답은 입력을 보존하고 수정/명시적 취소를 허용한다. 충돌한 내용으로 최신 기록을 강제로 덮어쓰지 않는다.
7. 화면의 초안은 탭 메모리에만 보관한다. 일시 연결 끊김·화면 전환 뒤 현재 열람 권한을 다시 확인한 후 복원하며, **새로고침·로그아웃·권한 상실에는 폐기**한다. 아직 저장하지 않은 원문 의존 입력은 원문의 열람이 닫히면 함께 폐기될 수 있다. 처리 결과가 불확실한 변경 요청은 화면 원문을 가린 채 같은 요청 번호로 결과만 재확인한다. localStorage/sessionStorage에 계정·비밀번호·대화를 저장하지 않는다. 미저장 초안의 새로고침 복구는 현재 제공하지 않는다.
8. 인증 만료·권한 오류·연결 재확인 중에는 이전 대화 표시를 제거한다. 숨겨진 화면에서는 조회와 읽음을 중단하고 복귀 시 다시 확인한다. 입력 창의 원문 조회가 더 최근의 열람 종료를 발견한 경우 미리보기를 포함한 다른 화면 투영도 즉시 지우고 다시 조회한다. 서버의 권한 변경을 즉시 푸시받는 구조는 아니며 다음 조회/발신에서 확인한다.
9. 로그아웃은 화면 자료를 먼저 지우고 서버 종료를 확인한다. 네트워크 실패는 ‘종료 확인 필요’와 재시도를 표시한다. 다른 탭 계정 불일치 시 그 계정의 세션을 종료하지 않고 이 탭만 로그인 화면으로 돌아간다.
10. 실제 오류·요청 본문·자격증명을 공개 응답이나 시험 결과에 기록하지 않는다. HTTP의 Secure 쿠키가 없는 것은 루프백 HTTP 시험 범위에 한정되며 운영 인증 설정으로 재사용하지 않는다. 메모리 참조 폐기는 보안 RAM 소거 보장이 아니다.

## 직접 확인하는 방법

프로젝트 폴더의 직접 사용하는 터미널에서 실행한다. 비대화형 파이프 실행은 거부한다.

```powershell
npm run dev:local-api
```

기본 주소는 `http://127.0.0.1:4180/`이며, 터미널에 표시된 세 역할의 가상 계정을 이용한다. 포트가 사용 중이면 `npm run dev:local-api -- --port=0`으로 빈 포트를 배정받고 출력된 주소를 사용한다. `.test` 주소는 실제 수신 메일 주소가 아니다.

1. Chrome 일반 창과 시크릿 창처럼 **쿠키가 분리된 두 브라우저 세션**을 연다. 같은 일반 창의 탭 두 개는 독립 계정 세션이 아니다.
2. 각각 가상 치료사·보호자로 로그인하고 ‘가상 아동’ 대화를 연다.
3. 가상 메시지를 보내고 상대 화면 수신·읽음, 새로고침 뒤 서버 대화 유지, 로그아웃을 확인한다.
   치료사 화면의 ‘기록하기’에서 가상 목표에 연결된 기록을 저장하고 ‘공유 미리보기’에서 보호자와 공개 내용을 확인한다. 보호자는 공유 카드에서 ‘활동 경험 남기기’, 치료사는 그 카드에서 ‘임상 검토’/‘인용 답장’/‘다음 기록에 참고’를 확인할 수 있다. 원기록 수정만으로 기존 공유본은 바뀌지 않는다.
4. 별도 쿠키 세션에서 가상 센터 관리자로 로그인하면 '아이 기본정보' 화면이 열린다. 아이를 선택해 가상 이름·연령·기준일을 저장하고 치료사/보호자의 새 조회에 반영되는지 확인한다. 센터에는 대화·임상 원문·가족 관심사를 표시하지 않는다. 같은 센터 계정의 두 독립 세션으로 동시 수정 시 최신 내용 비교를 확인할 수 있다.

독립 백업이 없는 현재 상태에서는 실제 아동 자료·외부 접속을 열지 않는다. 위 실행은 운영 전환이나 E 드라이브 서버 준비 완료를 뜻하지 않는다.

## 2026-10-09 승인 첨부 전송·열람 HTTP 경계 준비

### 현재 상태와 적용 범위

검사를 마친 처리 후보를 일반 메시지에 연결하고, 현재 그 메시지를 볼 권한이 있는 사용자만 파일을 읽는 HTTP/클라이언트 경계를 추가했다. **기본 `npm run dev:local-api` 화면은 여전히 격리 업로드 전용이다.** 이번 코드는 별도 신뢰된 실행기가 실제 `MediaAccess` 인스턴스를 넘길 때만 활성화되며, 공개 요청이나 `mediaDelivery: true` 설정만으로 켤 수 없다. 실제 PostgreSQL/API 자식 프로세스/검사 작업자의 결합과 첨부 발신·뷰어 화면은 다음 단계다. 검사 대역을 기본 실행기에 넣지 않았다.

### 동작과 데이터 보호

1. 준비 모드의 업로드 응답은 `source`에 원본 이름·형식·크기를, `upload`에 처리 후보의 현재 상태·크기를 분리한다. 메타데이터 제거로 후보 크기가 달라져도 원본 예약의 동일 요청 재확인이 가능하다. 소유권·현재 과거 열람 범위는 다시 확인하며 해시·저장 키·경로·검사 증거는 반환하지 않는다.
2. 일반 메시지의 첨부 입력은 `{ id }` 목록뿐이다. 기존 `Conversations.sendText` 트랜잭션이 소유권·준비 완료·개수/용량을 확인하고 메시지 저장과 `ready → bound`를 함께 확정한다. 일부 파일만 연결되는 성공은 허용하지 않는다. 첨부만 있는 빈 본문을 허용하며 재시도는 같은 요청 ID·본문·첨부 ID를 사용한다.
3. 파일 읽기 경로는 `/api/local/centers/:center/conversations/:room/messages/:message/attachments/:id/content` 하나다. 기존 출처·쿠키·예상 계정·센터 검사 후 `MediaAccess.open`이 메시지 문맥의 현재 권한과 처리 후보 증거·파일 바이트를 확인한다. 업로드 소유권만으로 공유를 허용하거나 원본으로 대체하지 않는다. 숨김/전체 삭제/담당 해제/과거 열람 종료는 새 파일 읽기를 차단한다. 이미 내려받은 파일을 원격 회수하는 기능은 아니다.
4. 전체 파일을 200 응답으로만 제공한다. Range는 무시하고 `Accept-Ranges: none`을 보낸다. `no-store`·`nosniff`·동일 출처·referrer 차단 헤더와 고정 다운로드 이름을 사용한다. 동시 읽기 2개, 열기부터 전송까지 30초 제한이며 늦게 열린 스트림도 종료한다. 실제 종료가 확인되기 전에는 슬롯을 재사용하지 않으므로 저장소 작업이 영구 정지하면 용량도 계속 점유된다.
5. 클라이언트는 메시지 문맥·확인한 계정으로 요청하고 200/MIME/정확한 길이를 재검사한다. 최대 허용 크기 안에서 스트림을 읽고 계정 전환·명시적 중단·시간 초과·불완전 응답은 Blob을 반환하지 않는다. 서버 오류 원문은 표시하지 않는다. 브라우저 Blob 생성은 검사·승인이나 안전한 메모리 소거를 보장하지 않는다.
6. 본인 숨김 이후 발신 응답 재시도에서 최소 DTO의 작성자/시각 필드가 빠져 클라이언트가 정상 결과를 거부하던 오류를 고쳤다. 숨김 안내와 최소 식별자만 유지하고 원문·인용·첨부는 다시 노출하지 않는다. 메시지 수와 저장된 원본은 변하지 않는다.

### 다음 구현 순서

1. 새 가상 자료만 사용하는 명시적 PostgreSQL 실행 환경을 조립한다. 감독 프로세스가 시험 자원과 수명을 소유하고, API 자식은 runtime DB 권한만, 검사 자식은 worker DB 권한과 검사 엔진만 갖게 한다. API 프로세스에 소유자/worker 자격증명이나 Docker 제어 권한을 전달하지 않는다.
2. 준비 신호와 실제 서비스 준비 완료를 구분하고, 원본·후보·작업 원장의 소유권을 확인한 종료/정리를 구현한다. 기존 메모리 실행기의 원본 키 목록만으로 worker가 만든 후보까지 삭제하지 않는다. 종료 불확실·낯선 파일은 보존한다.
3. 실제 ClamAV·격리 디코더 처리와 후보 검사를 통과한 뒤에만 준비 모드 UI, 동일 요청 첨부 발신, 다른 시험 브라우저의 사진/영상 열람과 URL 해제를 연결한다. 이어 기록/피드백의 첨부 보존과 공유 선택을 연결한다.

운영 E 저장·독립 백업·복원·실제 기기/사람 검증은 별도다. 실제 아동 자료·외부 접속 보류는 유지한다.

### 이번 단계의 결과와 한계

대화 아래 ‘사진·영상 업로드 시험’에서 가상 파일 선택 → 업로드 → 상태 갱신 → 취소를 연결했다. **검사 완료·상대방 전송·파일 미리보기/열람은 구현 완료가 아니다.** 현재 실제 ClamAV/격리 미디어 처리 워커를 메모리 DB와 연결하지 않았으므로 모든 정상 업로드는 `quarantined`에 머문다. 파일 시그니처·크기·SHA-256 일치는 악성코드 검사나 전체 디코딩 결과가 아니다.

기존 `MediaUploads`·`MediaResourcePolicy`·`PrivateFileStore`를 재사용한다. HTTP 프로세스에 Docker 엔진을 열거나 `fakePreparation`으로 승인하지 않는다. 기록/피드백의 `ATTACHMENTS_NOT_CONNECTED` 보호와 일반 메시지의 첨부 입력 차단을 유지한다. 기존 정적 프로토타입과 배포는 변경하지 않는다.

### 파일과 권한의 수명

- 파일명은 저장 경로가 아니다. 실행기가 OS 임시 폴더 아래 새 전용 폴더를 만들고 서버 UUID로 원본을 비공개 저장한다. E 드라이브·기존 사용자 파일·영속 DB·클라우드 저장소는 사용하지 않는다.
- 예약/조회/수신/취소 모두 현재 쿠키, 예상 계정, 센터·아동별 참여 및 업로드 소유권을 검사한다. 바이너리 수신은 **인증·소유권 확인 후** 시작한다. 다른 참여자도 아직 연결되지 않은 업로드를 조회할 수 없다.
- 요청은 고정 Content-Length, `application/octet-stream`, 버전 헤더를 요구한다. 청크 전송·다른 출처·중복 헤더·임의 작업 경로는 거부한다. 최대 동시 수신은 실행기 전체 2개이며 수신 제한 시간은 8초다.
- 업로드 예약 응답 유실은 같은 clientId/파일 지문으로 재확인한다. 바이트 전송 응답 유실은 같은 업로드 상태부터 조회하고 `pending`일 때만 다시 수신한다. `receiving`은 상태 확인/취소, `quarantined`는 재업로드하지 않는다. 취소 결과 확인 전에는 선택 파일을 제거하지 않는다.
- 미전송 선택 파일은 계정·센터·방별 탭 메모리에 보관하며 메뉴 이동 시 유지한다. 로그아웃·권한 상실에는 폐기한다. 완전한 현재 방 목록에서 빠진 비선택 방도 정리하므로, 다른 아이를 보고 있는 사이 권한이 종료되었다가 재연결돼도 이전 파일명이 복원되지 않는다. 실패/부분 목록을 권한 종료 증거로 사용하지 않는다. 새로고침 복구나 서버의 과거 임시 업로드 목록 재조회는 아직 없다.
- 예약 TTL은 15분이다. 서버 정리는 예약·수신·취소 시 실행되며, 유휴 상태에서 만료 즉시 삭제되는 주기적 작업은 아니다. 정상 종료는 진행 중 요청/파일 작업 종료를 확인한 다음 소유 파일·폴더를 정리하고 DB를 닫는다. 낯선 파일·경로 교체·작업 종료 불명 시 삭제와 DB 종료를 보류하고 오류를 반환한다.
- 강제 종료/PC 전원 차단 때 임시 파일이 남을 수 있다. 운영 ACL·전원 장애 내구성·보안 삭제·실제 아동 자료 보호 준비가 완료된 것이 아니다. 임시 폴더 전체를 이름 패턴만으로 일괄 삭제하지 않는다.

### 합성 시험 용량

클라이언트 선택은 방당 6개, 모든 방 합계 24개·100MiB, 사진 10MiB/영상 50MiB까지다. 별도로 서버 전체는 대기 4개·시간당 예약 8회·예약 용량 120MiB를 제한한다. 서버는 실제 작은 파일 크기가 아니라 원본/처리 후보의 **형식별 최대 용량**을 예약하므로 사진 1개는 20MiB, 영상 1개는 100MiB를 사용한다. 예를 들어 영상 1개와 사진 1개까지 동시에 대기할 수 있다. 취소가 시간당 횟수를 초기화하지 않는다. 이 값은 운영 요금제나 실제 센터 정책이 아니다.

`npm run dev:local-api` → 가상 계정 로그인 → 대화 → ‘사진·영상 업로드 시험’을 펼친다. 가상 파일만 선택하여 업로드하고 ‘격리 보관됨 · 검사 서버 미연결’ 상태를 확인한다. 다른 가상 계정에는 파일이 보이지 않아야 한다. 메뉴를 이동해 돌아오면 선택이 유지되고, ‘업로드 취소’ 확인 후 목록에서 제거되어야 한다. 실제 사진·영상은 선택하지 않는다.

- 초기 인증 회귀는 불완전 요청의 응답 종료 처리에서 시험 응답 객체에 없는 메서드를 호출했다. 실제 불완전 요청만 분기하도록 수정했다. 이후 서버 전체 검사에서 Windows가 413 응답을 보내기 전에 소켓을 파괴해 `ECONNRESET`을 일으키는 제품 오류도 발견했다. 즉시 `req.destroy()`를 제거하고 안전한 응답을 내보낸 뒤 연결을 종료하도록 고쳤다. 집중 60개와 최종 서버 전체 검사가 통과했다.

## 2026-10-09 이전 기록 양식의 로컬 API 재사용

원 개편안 R05에 따라 치료사 기록 목록에 **‘양식으로 새 기록’**을 연결했다. 별도 복사 API나 SQL을 만들지 않고 기존 `Records.get()`의 현재 담당·과거 열람 권한과 정확한 revision 조회, 기존 저장의 요청 ID·충돌 검사를 재사용한다. 인증/백엔드 검토 중 확인된 비밀번호 변경 HTTP/UI는 이번 범위에 넣지 않았다. 원 개편안의 기록 작성 흐름에 직접 필요한 양식 재사용을 먼저 완결했다.

### 동작과 데이터 경계

- 선택한 기록 목록의 revision을 고정해 서버에서 읽고 **목표 ID와 측정 도구·항목·단위·조건만** 명시적으로 추출한다. 측정값은 0도 포함해 전부 빈칸이며, 원래 값을 읽어 새 입력에 주입하지 않는다. 공통 `recordDetails()`의 draft 규칙과 20행 제한을 재사용한다.
- 새 UUID·revision 0·오늘 날짜·빈 제목으로 시작한다. 관찰/활동/반응/다음 계획·내부 메모·공유 요약·가정 활동·파일·참고 소식·이전 일정은 복사하지 않는다. 기존 기록과 공유본도 변경하지 않는다.
- 이전 목표가 현재 선택 목록에 없으면 다른 목표를 자동 선택하지 않는다. 빈 선택과 안내를 표시하고 직접 고르게 한다. 측정 양식이 있으면 상세 영역을 펼쳐 새 수치가 필요하다는 점을 보여준다.
- 미완성 양식은 임시저장할 수 있지만 정식 저장 규칙은 완화하지 않는다. 작성 중인 입력이나 결과 불명 요청이 있으면 그 입력/영수증 확인을 먼저 복원하며 새 양식으로 덮어쓰지 않는다.
- 응답이 늦게 도착해도 계정·아동·화면 세대/요청 소유권이 바뀌면 적용하지 않는다. 조회 도중 현재 목표 목록이 사라지거나 미준비 상태가 되어도 빈 폼을 새로 만들지 않는다.
- 미저장 양식 재개 시 원본의 정확한 버전 열람 권한을 다시 확인한다. 확정 거부면 관련 메모리 입력과 DOM을 제거하고, 일시적 조회 실패면 화면만 가린다. 독립 저장된 새 기록은 이후 자체 기록 권한을 따른다. 이 UI 재확인은 서버 권한 검사의 대체 수단이 아니다.

## 2026-10-09 일반 소식의 비공개 반영 메모

원 개편안 C05의 **읽음과 다음 회기 반영 확인 분리**를 일반 텍스트 소식에 연결했다. 치료사는 상대방 소식의 `반영 메모`에서 해당 원문을 확인하고 내부 메모를 저장한다. 보호자에게는 현재 원문에 대한 반영 여부만 표시하며, 공개 답변은 기존 `인용 답장`으로 별도 작성한다.

### 동작과 데이터 경계

- `GET/POST /api/local/centers/:centerId/conversations/:conversationId/messages/:messageId/review`는 기존 공통 세션·요청 출처·예상 계정 검사와 현재 담당/과거 열람 범위를 유지한다. 보호자·센터 관리자에게 내부 메모 조회 권한을 추가하지 않는다.
- GET은 현재 원문과 최신 메모를 한 트랜잭션에서 읽고 ID·원문판·메모판·메모가 참고한 원문판·본문·메모·첨부 개수의 8필드만 반환한다. 일반 대화/홈/인용 응답에는 내부 메모·메모 작성자·메모판을 넣지 않는다. 첨부 원본이나 파일 ID도 이 private 응답에 포함하지 않는다.
- 저장은 작성 시작 당시 원문판과 메모판을 함께 비교한다. 다른 창에서 원문이나 메모가 변경되면 조용히 덮어쓰지 않는다. 폴링에서 변경을 확인하면 미전송 입력을 보존하고 저장을 막으며, 사용자가 입력 취소 후 최신 메모를 다시 열어야 한다. 자동 병합은 하지 않는다.
- 같은 요청 ID의 재시도는 최초 결과를 반환한다. 메모·대화 변경 버전·감사 사건·내용 없는 영수증을 한 트랜잭션에서 처리하므로 저장 응답이 유실되어도 중복 저장이나 최신 메모 덮어쓰기를 막는다. 숨김/전체 삭제 이후의 동일 완료 요청도 현재 관계·과거 범위를 통과한 경우에만 내용 없는 영수증으로 확인한다.
- 원문 수정 후 이전 메모는 어떤 원문판을 확인한 것인지 안내한다. 이전 메모가 존재해도 새 원문은 미반영 상태이며 치료사가 명시적으로 확인·저장해야 한다. 읽음 처리나 공개 답장은 반영 확인을 대신하지 않는다.
- 미전송 메모는 현재 계정·센터·아동의 메모리에만 유지한다. 권한 종료/삭제 확정 시 원문과 입력을 비우고, 일시적 조회 실패 시 화면을 가린다. 방·메뉴·계정 변경 뒤 늦은 응답이 메모 창을 복원하지 못한다. 결과 불명 요청은 원문 없는 동일 요청 확인 화면으로 분리한다.
- 모바일에서 선택한 대화 권한이 끝나면 대화 선택뿐 아니라 `roomOpen` 상태도 해제하고 목록 화면을 즉시 적용한다. 기존에는 원문은 제거해도 닫힌 방의 레이아웃이 남아 허용된 다른 방을 선택하기 어려웠다. 인증·담당 해제 정책을 완화하지 않고 이동 경로만 복구했다.

- `GET /api/local/centers/:center/operations/conversations/:room/profile`: 같은 최소 필드의 정확한 아동 상세. 쿠키 계정·화면 예상 계정·현재 센터 역할을 확인하며 서비스 트랜잭션 안에서도 현재 관리 권한을 재검사한다.
- 같은 경로의 `POST`: 기존 `Children.save`를 재사용한다. 정확한 요청 번호·기대 버전·이름/연령/기준일만 받고 내용 없는 저장 영수증을 반환한다. 치료사·보호자의 편집 권한을 추가하지 않았다.

이름은 필수, 연령 0~26 정수와 기준일은 함께 입력하거나 함께 비운다. 0세와 미등록을 구별하고 미래 기준일을 거부한다. 생년월일 추정·자동 연령 변경·변경 메시지 자동 발신은 없다. 규칙은 기존 공통 `src/profile-fields.js`를 재사용한다.

다른 창이 먼저 저장하면 작성 입력을 보존하고 최신 내용을 비교하게 한다. '현재 입력 유지하고 다시 검토'는 기준 버전만 명시적으로 갱신하며 저장을 자동 실행하지 않는다. 저장 응답이 유실되면 요청 번호·내용·기대 버전을 고정하고 같은 요청으로만 재확인한다. 재시도로 프로필 버전이나 영수증을 중복 증가시키지 않는다. 미확정 요청의 입력 변경·취소는 잠그고, 단순 입력 오류/확정 충돌과 구분한다.

입력은 현재 계정·센터·아동별 탭 메모리에만 둔다. 목록 왕복에는 보존하되 브라우저 새로고침·센터 전환·로그아웃·권한 상실 시 폐기한다. 숨김/연결 끊김에는 화면을 가리고 재확인 후 복원한다. 다른 아동/계정으로 바뀐 뒤 도착한 응답은 무시한다. 정기 조회에서 변하지 않은 목록 DOM을 다시 만들거나 키보드 포커스를 제목으로 옮기지 않도록 보완했다.

센터 목록은 최대 20페이지/2,000명까지 완주 후 표시하며 한도·중복·잘못된 응답은 일부 성공으로 처리하지 않는다. 키 기반 페이지 조회이지 시점 고정 스냅샷은 아니다. 목록 부재만으로 초안을 삭제하지 않고 상세/저장 시 정확한 권한을 확인한다.

## 2026-10-09 치료사 목표 편집과 기록 연결 복구

### 연결한 동작과 보존 경계

- 치료사는 아이 정보에서 목표를 추가하고 제목·설명·진행/달성/보류 상태를 수정한다. 목표가 없는 아이도 첫 목표를 만든 뒤 기록을 작성할 수 있다.
- 보호자와 담당 치료사는 현재 목표를 공유한다. 새 참여자의 현재 목표 조회는 기존 규칙을 유지하며, 이를 과거 치료 기록 열람 권한으로 확대하지 않는다. 보호자는 목표를 변경할 수 없고 센터 관리자는 임상 목표 경로에 접근하지 않는다.
- 목표 변경은 과거 기록의 당시 목표·측정값·참고·첨부·공유본을 바꾸지 않는다. 새 기록이나 사용자가 명시적으로 다시 저장한 기록에만 확인한 목표 판을 연결한다. 저장된 기록의 당시 목표와 현재 연결할 목표를 화면에서 구분한다.
- 동시 수정은 409로 거절한다. 작성한 입력과 서버 최신 내용을 비교한 뒤, 입력 유지 또는 최신 내용 적용을 선택하고 별도로 저장한다. 무변경 저장은 목표 판을 늘리지 않는다.
- 응답 유실은 동일 요청 번호·본문으로 결과만 재확인한다. 이후의 충돌만으로 최초 저장 실패를 단정하지 않는다. 목표 저장만으로 메시지·읽음·치료 기록을 자동 생성하지 않는다.
- 기록 저장 중 목표·일정이 변경되어 처음 확정된 `CONTEXT_CHANGED` 409를 받으면, 정기 조회가 입력창을 가렸더라도 현재 아이·원문 열람 권한을 재검사한 뒤 작성 내용을 복원한다. 저장은 잠그고 ‘목표·일정 다시 확인’으로 선택 메타데이터만 갱신한다. 관찰·측정값 0·내부 메모·첨부·당시 참고·과거 목표 스냅샷·기록 판은 유지하며, 사용자의 별도 저장이 필요하다.
- 최신 목표/일정 조회 중 하나라도 실패하면 기존 연결 판을 부분 갱신하지 않는다. 닫기·계정/아이/역할 전환 뒤 늦은 응답은 반영하지 않는다. 열람 종료는 기존 입력 폐기 정책, 일시 조회 실패는 화면 제거 후 메모리 보존 정책을 유지한다.

## 2026-10-10 가상 비밀번호 복구 API 연결

로그인 화면의 `비밀번호를 잊으셨나요?`에서 가상 `.test` 주소의 재설정을 요청하고, 수신자 전용 링크에서 새 시험 비밀번호를 설정하도록 연결했다. 기존 `Auth`의 일회용 복구·암호 검증·세션 종료 트랜잭션을 재사용한다. 인증 공급자·DB 스키마·임상 조회 권한과 공개 배포는 바꾸지 않았다.

### 구현과 안전 경계

- `POST /api/local/auth/password-recovery/request`는 동일한 202 안내만 반환한다. 계정 조회·발급·전달을 즉시 HTTP 응답에서 분리한 제한 큐를 사용한다. 없는 주소·중복·용량 제한·발급 실패를 응답으로 구분하지 않는다. 이 검증은 응답 내용의 동일성이지 네트워크 시간의 완전한 동일성을 보장하지 않는다.
- 큐는 프로세스 소유, 동시 실행 1개·대기 16개·분당 접수 32개·주소별 60초 중복 제한이다. 운영용 분산 속도 제한이나 영속 전달 장치가 아니다. 실제 외부 메일을 보내지 않으며 고정 HTTPS 안내는 비공개 메모리 전달함에만 남긴다. 시험 하네스만 `takeRecovery(email)`로 해당 수신자 안내를 한 번 가져온다. 공개 메일함·관리자 응답·로그에서 토큰을 꺼낼 수 없다.
- `POST /api/local/auth/password-recovery/complete`는 토큰·새 비밀번호·확인 값만 받는다. 성공 시 복구 대상의 기존 세션을 모두 종료하고, 다른 계정·담당 관계·임상 기록·읽음 상태를 변경하지 않는다. 자동 로그인하지 않으며 복구 응답에는 쿠키 설정/삭제가 전혀 없다. 처리 도중 다른 탭에서 새로 로그인한 계정의 쿠키도 덮지 않는다.
- 두 API는 현재 로그인된 쿠키나 예상 계정 헤더가 있으면 거절한다. 화면은 실제 401을 확인한 뒤에만 입력을 열고, 현재 세션이 있으면 명시적 로그아웃을 요구한다. 통신 실패를 로그아웃으로 간주하지 않는다. 출처·loopback·요청 헤더·본문 크기 제한을 유지한다.
- 복구 전용 화면은 주소의 fragment/query를 지운 뒤 나머지 모듈을 불러온다. 비밀번호·토큰을 브라우저 저장소·DOM 속성·로그에 보관하지 않는다. 숨김/오프라인 시 비밀번호 입력과 화면을 비우고, 종료 후 늦은 응답은 반영하지 않는다. 새로고침에는 원래 링크가 다시 필요하다.
- 완료 응답 유실·중단·서버 오류는 실패나 원복으로 단정하지 않는다. 일회용 재설정을 재전송하지 않고 토큰·비밀번호 참조를 폐기한 뒤 **새 비밀번호로 일반 로그인**하도록 안내한다. 확실한 입력 오류만 빈 입력으로 다시 작성하게 하며 소비/만료 링크는 닫는다.
- 실행기 종료는 listener의 실제 요청 종료 → 복구 작업의 실제 종료 → 임시 미디어 → DB 순서다. 전달함을 먼저 닫아 늦은 안내가 남지 않게 한다. 종료 관측 시간 초과를 작업 종료로 간주하지 않는다. 일반 외부 transport의 취소/전달 보장은 이번 메모리 전용 경계에 포함하지 않는다.

## 남은 작업과 우선순위

아래 우선순위는 가상 자료 전용 로컬 연결의 후속이며, 운영 전환을 허가하거나 전체 목표를 완료 처리하는 목록이 아니다.

1. 4메뉴 기본 서버 조회/기록 진입, 이전 양식 재사용·정식 측정 비교·일반 소식의 비공개 반영 메모·보호자 공동 가족 관심사 편집·현재 활동 접근·센터 전용 아이 기본정보/신규 등록/명시적 담당 관계·센터 운영 현황/일정과 치료사 목표·일정 편집 및 가상 초대/신규·기존 계정 수락을 연결했다. 가상 비밀번호 복구의 전용 화면/API를 추가했으며 최종 검증 범위는 바로 위 결과를 따른다. 다음은 남은 계정 설정과 영속 재접속 경계를 점검한다. 실제 메일 발송은 별도 공급자·운영 준비 전 열지 않는다. 센터는 임상 workspace에 진입시키지 않고 별도 운영 경로/최소 필드를 유지한다. 현재 임상 원문·과거 열람·재공유·철회 규칙을 유지하고 일정 충돌·수신자 변경을 단순 화면 상태로 해결하지 않는다.
