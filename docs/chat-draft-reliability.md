# 대화 초안 보존과 실제 저장 상태

2026-10-06 후속: [전송 중 화면 갱신·담당 변경의 초안 보존](chat-send-lifecycle.md). 지연 전송이 다른 방의 초안을 정리하지 않도록 발신 시점/ID를 고정하고, 성공 후 디스크 정리 실패와 메시지 전송 실패를 분리했다. 아래 숫자는 2026-10-02 당시 검증이며 후속 결과와 혼동하지 않는다.

2026-10-02. 개편안의 검증 항목 5(실패·재시도·방 전환의 입력/첨부 보존)와 6(모바일·키보드 접근)을 보완했다. 서버 업로드나 실제 메시지 전송 상태를 구현한 것이 아니다. API·인증·SQL·서버 서비스·배포는 변경하지 않았다.

## 확인한 문제와 수정

기존 화면은 빈 초안에도 `이 대화에만 임시 저장`을 표시했고 모바일에서는 이 상태를 숨겼다. 실제 저장 실패 여부와 완료 시점을 상태에서 구분하지 못했다. 저장소 접근을 차단한 독립 브라우저 시험에서는 파일 저장소 생성자의 IndexedDB 접근 예외로 홈까지 중단됐다. 손상된 초안의 첨부 튜플을 읽을 때에도 안전한 안내가 필요했다.

| 상태 | 현재 화면과 동작 |
| --- | --- |
| 미작성 | 아직 작성한 소식이 없어요. 저장된 초안이 있다고 표시하지 않는다. |
| 저장 중 | 초안 저장 중. 최신 입력의 쓰기가 커밋될 때까지 완료로 표시하지 않는다. |
| 저장 완료 | 이 브라우저에 초안 저장됨. 실제 IndexedDB 트랜잭션 완료 후 표시한다. 다른 기기/서버 전달을 뜻하지 않는다. |
| 저장 실패 | 입력·미전송 첨부는 이 탭에 유지. `초안 다시 저장`은 발신 없이 같은 초안 ID로 재시도한다. |
| 불러오기 실패/손상 | 기존 저장 원문을 변경하지 않고 작성·발신을 막는다. `초안 다시 불러오기`를 제공한다. |
| 탭 저장소 제한 | IndexedDB 쓰기가 완료돼도 새로고침 복원 한계를 별도로 안내한다. 미전송 내용이 있으면 종료 경고를 유지한다. |

실패를 표시한 뒤 뒤따르는 성공이 초안 오류만 해제하며 발신 오류와 혼동하지 않는다. 모바일에서는 사진 선택/보내기를 첫 줄, 상태/재시도를 다음 줄에 두어 주요 버튼을 유지한다. 저장 상태는 `role=status`, 오류는 별도 `role=alert`로 알린다. 재시도 후 입력창으로 포커스를 돌린다.

## 보존·실패 경계

- 기존 `carebridge-chat-drafts-v1` 버전 1, `carebridge-draft-tab`, 탭/사용자/아동 키 구조, 메시지 발신 ID·사진/영상 메타데이터와 원본 참조를 유지한다. 일괄 변환·초기화·삭제·서버 자동 반입은 없다.
- 쓰기 시점의 초안을 복사해 순서대로 저장한다. 키별 메모리 revision으로 오래된 완료/실패가 최신 입력의 상태를 덮어쓰지 못하게 한다. 이 revision은 서버 버전이나 새 DB 필드가 아니다.
- 실패한 초안은 메모리에서 유지하고 해당 키의 실패 표시를 보존한다. 다른 방의 성공이 이 실패를 해제하지 않는다. 성공적 재시도도 현재 방의 초안만 저장하고 메시지를 만들지 않는다.
- 본문/발신 ID/답변 ID·첨부 메타데이터, 실제 Blob의 크기/MIME/ID 쌍과 중복/손상 튜플을 검사한다. 손상된 저장 내용은 임의로 버리거나 빈 초안으로 덮어쓰지 않는다. 손상 자체를 자동 복구하는 기능은 아니다.
- IndexedDB 연결을 필요할 때 시도한다. 동기 접근/IO 오류의 원문을 UI에 노출하지 않는다. blocked 이후 늦게 열린 초안 연결은 닫고 versionchange에서는 기존 연결을 닫아 재접속하도록 한다.
- 파일 읽기도 트랜잭션 완료 후 반환한다. 파일 추가/삭제 중 동기 오류는 트랜잭션을 취소해 부분 반영을 막는다. 과거 공유본이 사용하는 기존 파일을 자동 삭제하지 않는다.
- `beforeunload`는 실패/대기와 복원할 탭 키가 없는 미전송 초안을 확인한다. 탭 저장소가 차단되면 새로 만든 임시 키로 이 탭의 방을 분리하되 새로고침 복원을 보장하지 않는다.

## 변경 파일

- `src/chat-drafts.js`: 안전한 내용 검사·지연 연결·키별 최신 저장 상태·실패/복원 경고.
- `src/chat-controller.js`: 실제 상태 표시, 초안 재저장/재불러오기, 별도 초안 오류·포커스.
- `src/chat-ui.js`, `src/communication.css`: 상태/오류/재시도 진입점과 모바일 배치.
- `src/media-store.js`: 지연 연결·공개 오류·완료 확인·부분 쓰기/삭제 취소.
- `tests/chat-drafts.test.mjs`, `tests/media-store.test.mjs`: 각각 8개·3개 단위 검증.
- `tests/chat-drafts-browser.mjs`: 독립 브라우저의 실제 IndexedDB·사진 바이트·재시도·접근 거부·손상/부분 쓰기 검증.
- `README.md`, `communication-implementation.md`: 현재 단계와 검증 결과 갱신.

## 실행한 검증

- `npm test`: 55개 통과(직전 44개 + 초안 8개 + 파일 저장소 3개).
- 신규 `tests/chat-drafts-browser.mjs`: 8묶음 통과. 사진/발신 ID와 새로고침, 실패 원문 비노출·종료 경고·방 전환, 320/390px·Enter 재저장, 명시적 1회 발신, 손상 원문 보존, IndexedDB 차단/복구, 실제 부분 파일 추가 취소, 탭 저장소 제한 안내.
- 기존 소통 8·기록/운영 14·미디어 7·기본정보 6·계정/초대 6·관계 3묶음 재실행 통과. 레이아웃 195조건에서 넘침/브라우저 오류 0건.
- `npm run check`, `npm run build`, `git diff --check` 통과. 정적 빌드에 서버 운영 코드가 들어가지 않음을 확인했다. 서버는 변경하지 않아 이번 단계에서 서버 시험을 재실행하지 않았다. 직전 서버 207개 결과와 미검증 한계는 [서버 기반 문서](server-foundation.md)에 유지한다.

브라우저 검증 스킬로 별도 세션의 페이지 로딩·콘솔·내비게이션을 확인하고, 독립 컨텍스트와 합성 자료로 검증했다. 사용자 탭/저장소는 지우거나 테스트 데이터로 바꾸지 않았다. 사진 원본 바이트도 비교했다. 결과·화면은 git/배포에서 제외된 `test-results/chat-drafts-*`에 보관한다. 첫 저장소 차단 시험의 홈 중단은 실제 제품 문제였고 파일 저장소 지연 연결 수정 후 통과했다. 단순히 시험 조건을 완화하지 않았다.

재현은 `PLAYWRIGHT_MODULE`, 격리 브라우저의 `CDP_URL`, 로컬 `APP_URL`을 지정하고 `node tests/chat-drafts-browser.mjs`를 실행한다. 각 브라우저 시험은 별도 컨텍스트를 만든다.

## 남은 제한과 다음 작업

초안은 로컬 보관일 뿐 운영 인증·서버 파일 검사/업로드·기기 간 동기화가 아니다. 브라우저 저장 공간 회수·사이트 데이터 삭제·갑작스러운 종료/모바일 OS 종료에서는 자료가 사라질 수 있고 종료 경고도 항상 실행된다고 보장할 수 없다. 탭 복제/세션 복원의 식별자 충돌과 실물 iOS/Android/Safari도 아직 검증하지 않았다. 실제 아동/건강 자료를 사용하거나 유일한 원본을 보관하면 안 된다.

P0의 사용자 과제·요약 이해도 확인과 P1의 실제 검사/디코딩·국내 운영 환경·보존/파기·메일/계정 복구·서버 연결이 남아 있다. 구성원 표시명과 서버 업로드 상태의 UX 준비도 계속 필요하다. API는 마지막 단계에 연결하며 전체 개편안은 완료로 판정하지 않는다.
