# 상세 기록의 초안 보존과 정식 저장

## 2026-10-08 기록 당시 참고 첨부 열기

원 개편안의 대화 참고 → 다음 회기 기록 → 공유 미리보기 흐름에서, 보존된 당시 사진·영상의 실제 열기 경로를 보완했다. 기존 `referenceSources[].attachments`와 파일 바이트는 남아 있었지만 기록 상세에는 인용문·버전만 표시됐고 편집 화면의 원문 보기는 현재 소식의 첨부를 열었다. 따라서 피드백 F1이 F2로 수정되면 당시 파일을 기록에서 직접 확인할 수 없었다.

### 구현 범위와 표시 규칙

- 기록 상세와 편집의 보존 참고마다 **당시 사진·영상 N개 보기**를 제공한다. 사용자가 열기 전에는 개수만 표시하며 파일명·미리보기·다운로드 링크를 만들지 않는다. 키보드로 열고 닫을 수 있고 버튼의 `aria-expanded`와 고유 패널 연결을 유지한다.
- 당시 영역은 기록의 보존 스냅샷만 읽는다. 현재 원문 보기와 분리하며, 일반 소식의 본문 수정·전체 삭제·나에게 숨기기 또는 활동 피드백 첨부 교체·공유 철회 때문에 당시 파일이 바뀌지 않는다. 일반 소식의 첨부 교체 기능을 새로 만든 것은 아니다.
- `recordReferenceMedia(db, actor, recordId, messageId)`는 현재 DB에서 기록을 찾고 `canReadRecord`, 참고 ID 포함, 해당 스냅샷 존재를 확인한 뒤 첨부 메타데이터 사본만 반환한다. 보호자·센터·비담당·기본 재연결자의 과거 기록은 거부한다. 당시 첨부의 `share:true`를 현재 기록 공유 허용으로 사용하지 않는다.
- 참고 파일은 `r.attachments`·공유 미리보기·publication에 자동 복사하지 않는다. 새 미저장 참고와 당시 스냅샷이 없는 이전 ID-only 기록에 과거 파일을 추측해 붙이지 않는다.
- 편집의 `.record-references`만 읽기 전용 MediaView로 처리한다. 별도 AttachmentEditor의 미저장 파일·선택·미리보기 URL은 건드리지 않는다. 다른 탭에서 자료가 바뀌면 입력은 남기되 참고 미리보기를 제거하고 열기 버튼을 중단한다.
- 읽기 시작 전과 비동기 파일 읽기 완료 뒤 URL 생성 직전에 저장 revision을 확인한다. 취소된 세대의 늦은 읽기도 폐기한다. 이미 내려받은 사본까지 회수하는 장치는 아니다.
- 당시 원본이 없거나 종류/크기가 맞지 않으면 찾지 못했다는 안내만 표시하고 현재 파일로 대체하지 않는다. 기존 파일 ID·Blob·기록·공유본·저장 형식에는 쓰지 않는다.

`MediaView.clear()`도 보완했다. 새 조회 중 이전 IMG/VIDEO에 해제된 blob URL이 남으면 `ERR_FILE_NOT_FOUND`와 이미지 디코딩 실패가 생길 수 있었다. 소유한 표시 노드·다운로드만 먼저 정리하고 영상 중단·src 해제 후 URL을 폐기한다. 다른 뷰의 노드와 미저장 첨부는 유지하며, 지연된 미디어 오류 이벤트도 현재 세대/노드일 때만 표시한다.

변경 제품 파일은 `src/app.js`, `src/record-ui.js`, `src/message-references.js`, `src/media-ui.js`다. 새 검증은 `tests/record-reference-media.test.mjs`, `tests/record-reference-media-browser.mjs`이며 기존 저장·역할·공유 정책을 재사용한다. 검증 스킬에 따라 UI 열기부터 브라우저 저장·원본 파일·재열기·공유 경계를 함께 확인하되 서버/API 검증과 혼동하지 않는다.

## 2026-10-08 이전 측정 기록의 로드 호환성

원 개편안 D01의 기존 측정 원문 보존을 재점검하면서 schema 2에서 유효한 측정 기록이 schema 3 전환 뒤 거부되는 문제를 재현했다. 빈 측정 조건 또는 앞뒤 공백을 가진 조건은 이전 저장 검증을 통과하지만, 전환 후 새 입력의 필수/정규화 검사가 적용되어 `repository.load()`가 `db:null`을 반환했다. 실제 원문은 덮어쓰지 않았으나 작업공간 전체를 열 수 없었다.

`src/record-fields.js`의 읽기 검증만 보완했다. `format:legacy`이고 기존 단일 `assessment`의 도구·항목·값·단위·조건과 `assessments`의 정확히 한 행이 일치할 때만 당시 문자 원문·유한한 숫자를 그대로 허용한다. 원문과 복사본이 다르면 거부하며, 새 작성/편집의 `recordDetails()` 검증은 우회하지 않는다. 미입력 조건을 임의로 채우거나 공백을 제거하지 않고, 빈값을 0으로 바꾸지 않는다.

기존 형식은 열어서 확인하고 다른 소식을 저장할 수 있다. 해당 기록을 다시 **정식 저장**할 때에는 빈 필수 측정 항목을 직접 완성하거나 해당 측정 행을 제거해야 한다. 신뢰할 수 없는 조건을 자동 추정해 넣지 않는다. 이후 정상 저장에서는 종전과 같이 단일 `assessment`가 `null`로 전환되고 새 측정 행 규칙이 적용된다. 저장 키·스키마 번호·공유 정책·원본 첨부 파일은 변경하지 않았다.

## 2026-10-08 측정 행 삭제·재추가의 번호와 키보드 초점

저장한 3행 기록을 다시 열어 첫 행을 삭제하고 추가하면 제목이 `2, 3, 3`이 되고 다섯 입력 `name`이 중복됐다. 삭제 버튼에 있던 초점도 `BODY`로 사라졌다. 원인은 미초기화 `dataset.next`가 남은 행 수를 다음 번호로 사용한 것이다. 기존 저장 함수는 각 행을 DOM 순서로 읽으므로 **저장된 값이 덮어써진 결함으로 확인된 것은 아니다**. 감싸는 label을 사용하므로 중복 input ID 문제도 아니다.

## 문제와 변경

이전 측정 항목을 가져오면 값은 비워 두지만 기존 검증은 초안에도 숫자·단위·조건을 모두 요구했다. 관찰 상태를 고르지 않았거나 가정 활동을 작성 중인 경우도 저장을 막았다. 항목을 버리거나 0을 넣어 우회하지 않는다.

- 초안의 미입력 숫자는 `null`이며 실제 0과 구분한다. 미완성 도구·항목·단위·조건과 행 순서를 보존한다.
- 상태 미선택 관찰과 미완성 가정 활동은 초안에 남긴다. ‘미관찰/해당 없음’과 관찰 내용의 모순은 여전히 거부한다.
- 숫자 입력창의 `-` 같은 미완성 숫자는 저장을 중단하고 입력창 안내를 표시한다. 브라우저가 이를 빈 값으로 반환해도 조용히 지우지 않는다.
- 정식 저장의 완전한 측정 행·실제 작성 내용 요구, 공유의 요약·수신자·선택 첨부 확인은 유지한다. 초안은 공유할 수 없다.
- 초안은 숫자가 있어도 비교 화면에서 제외한다. 상세 화면의 빈 값은 ‘아직 입력하지 않음’으로 표시한다.
- 기존 자유 텍스트 형식의 가정 활동은 새 정규화 규칙으로 다시 쓰거나 거부하지 않는다. 새 저장에는 공통 작성 규칙을 적용한다.

## 서버 계약과 데이터 보존

018은 `cb_record_revisions.draft_assessments`를 추가한다. 하나라도 미완성인 초안은 전체 순서 목록을 이 열에 보관하며, 기존 `cb_record_assessments`의 숫자·조건 필수 제약은 완화하지 않는다. 모든 행을 완성한 수정본은 기존 평가 테이블을 사용한다. 001~017 SQL과 기존 수정본은 다시 쓰지 않는다.

새 열은 초안 상태에서만 사용하며 최대 20행, 정확한 JSON 키·문자열 길이·유한 숫자/null을 DB에서도 검사한다. 초안 목록과 임상 평가 행은 같은 수정본에 공존할 수 없다. 기존 확정/불변/트랜잭션 제약이 새 열에도 적용된다. 정식 수정본을 만든 후에도 당시 초안은 서버 이력으로 남는다. 보호자·센터의 임상 원본 접근은 허용하지 않는다.

완성 기록의 정규화·요청 해시는 유지한다. 017에서 작성한 수정본·0을 포함한 평가 행·영수증을 018 적용 후 비교하고, 같은 요청 ID의 재시도가 기존 영수증을 반환하는지 확인한다. 복원 검사에는 실제 새 미완성 초안을 포함한다.

## 재현·검증 흐름

1. 이전 회기에 두 측정값과 관찰 결과를 작성한다. 새 기록에 목표·측정 항목만 가져오고 결과·내부 메모가 복사되지 않는지 확인한다.
2. 숫자·일부 단위를 비워 두고 빈 측정 행, 상태 미선택 관찰, 미완성 가정 활동, 기본 비공유 사진을 추가해 초안 저장한다.
3. 새로고침/재열기 후 필드·행·첨부 ID와 실제 바이트를 비교한다. 이전 원본·공유본이 바뀌지 않고 초안은 측정 비교에 없음을 확인한다.
4. 미완성 상태의 정식 저장이 거부되는지 확인한다. 직접 측정한 0과 9, 조건·활동 안내·관찰 상태를 작성한 뒤 정식 저장한다.
5. 수신자·요약·선택 첨부를 확인해 공유한다. 보호자 화면에 내부 메모·다음 계획·측정 원문이 없음을 확인한다.
6. 미완성 숫자와 저장 공간 오류를 발생시킨다. 입력·첨부가 유지되고 실패 원문은 바뀌지 않으며 재시도 후 초안이 한 개만 생기는지 확인한다.

브라우저 명령에는 `PLAYWRIGHT_MODULE`, 소유한 테스트 브라우저의 `CDP_URL`, loopback `APP_URL`이 필요하다. 가상 데이터와 독립 브라우저 컨텍스트만 사용한다. Docker 명령은 기존 이미지로 격리 테스트 자원을 만들고 실행 영수증으로 소유를 확인한 자원만 정리한다. 사용자 탭·저장소·계정·메일·외부 API는 사용하지 않는다.

최종 실행 증거는 아래에 기록한다. 전체 소통 검사의 첫 실행은 앱 전송 전 가상 동영상 생성에서 실패했다. 테스트 탭 활성화를 공통 생성기에 넣은 뒤 실제 프레임 디코딩 검사를 통과시켜 다시 검증했다. 서버 첫 전체 실행의 실패는 새 null 열을 반영하지 않은 과거 비교 기대값과 독립 해시 테스트의 측정 객체 키 순서였다. 원본 비교와 기존 해시 검사를 유지한 채 기대값을 정확히 수정한 후 전체 재실행했다.

## 남은 제한과 다음 순서

명시적인 초안 저장을 개선했으며 자동 저장·명시적 모달 닫기 후 미저장 입력 복구를 제공하지 않는다. 로컬 프로토타입은 같은 브라우저 저장만 사용한다. API/화면·실제 인증·다른 기기 소통은 연결되지 않았다. JSON/Blob 저장 경계, 운영 장기 보존/파기 정책도 해결했다고 주장하지 않는다.

P0 실물 모바일·보호자/치료사 과제 시간·요약 이해도 검증과 P1 운영 준비, 마지막 API/화면 연결 및 기기 간 검증은 남아 있다. 국내 통제·운영 한도·복구 승인 등 미확정 선택을 임의로 설정하지 않는다. P2는 사용성 필요성 확인 이후다.
