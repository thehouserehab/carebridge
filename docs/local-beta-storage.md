# E 드라이브 로컬 베타 저장 준비

최신 [암호화 자격증명 기반 DB 연결](windows-database-service.md)은 실제 DPAPI/PG/TLS/역할/복원 30개와 서버 625·로컬 87을 통과했다. 자기 UUID의 합성 자격증명·TLS 키만 정리하고 두 cluster를 정상 종료했다. 운영 비밀번호/서비스·독립 사본·실제 자료/API 전환은 아니며 아래 기록은 당시 범위다.

2026-10-07. 사용자 결정: 베타는 본기기 E 드라이브, 사업화 결정 후 유료 데이터센터 검토. **유료 자원/외부 접속/실제 자료 이관 승인으로 확대하지 않는다.** API 마지막 순서를 유지한다.

추가 사용자 결정: **센터·보호자가 실제 자료로 사용하는 베타**다. 가상 시연만을 최종 목표로 삼지 않는다. 다만 현재 앱은 가상 역할/브라우저 저장 기반이므로 실제 아동 자료 입력은 아직 허용 가능한 준비 상태가 아니다. 외부/센터 내부 접속 범위는 확인 중이다.

독립 백업 확인 답변(2026-10-07): **아직 별도 매체 없음**. E 내부 recovery/복원 시험 경로를 독립 사본으로 계산하지 않으며 실제 자료 운영 전환은 보류한다. 이 답변을 유료 저장소 생성이나 실제 자료를 무백업으로 받는 승인으로 확대하지 않는다. 비API 코드/합성 검증은 계속 준비할 수 있다.

최신 비API 후속은 [E PostgreSQL 지속 저장·복원](windows-e-postgres-verification.md)이다. 전용 Windows 도구를 E에 배치하고 가상 자료의 원본/별도 신규 cluster 독립 재시작·복원 9개를 통과했다. 실제 운영 DB 서비스/계정·독립 사본/키 복구·마지막 API와는 구분하며 아래 파일 IO 초기 기록은 유지한다.

이후 [Windows CurrentUser 복구 키 보관 모듈](windows-recovery-key-store.md)을 추가했다. 합성 키/암호문·새 프로세스 재읽기/묶음 인증·권한/링크/변조 거부 13개를 확인했다. 운영 `secrets/recovery-keys`나 운영 키는 만들지 않았으며 독립 매체·계정 상실 후 키 복구는 여전히 미완료다. 초기화와 키 모듈은 공통 NTFS/영수증 정책을 사용한다.

최신 [DB 연결 가드·작업자 조립](database-service-admission.md)은 같은 연결/트랜잭션에서 실제 목적/DB/OID·권한을 반복 검사하고 worker 원장/준비/업로드를 우회 없이 조립한다. 가상 scanner/decoder 통신과 실제 SQL/E·전체 파일 7개 복원/재시작 25개, 일반 E 9개·서버 599·로컬 87 통과. 원인 미확정 중간 종료는 별도 보존했다. 실제 native 검사/운영 worker·운영 자격증명/OS 서비스·RLS·독립 매체/키 회수·최신 권한/삭제 대조·마지막 API는 미완료다. 기존 E/DB/Docker 자료는 바꾸지 않았다.

## 현재 확인과 경계

후속 [DB 서비스 자격증명 보관](windows-database-credential-store.md)은 복구 키와 별도 목적/경로로 네 비소유자 역할의 비밀번호를 CurrentUser DPAPI로 묶는다. 가상 E 15·기존 키 최종 13·서버 611·로컬 87 통과. 키 회귀의 일시 실패는 원인 미확정으로 보존했다. 운영 secrets 파일 0개이며 실제 DB 로그인/계정 발급·독립 백업·API 활성화는 아니다.

- E는 정상 NTFS 고정 디스크, 확인 시 전체 256,042,332,160바이트·여유 242,655,571,968바이트(약 226GiB). 용량은 사용에 따라 달라진다.
- 코드/기존 브라우저 프로필/IndexedDB는 현재 위치를 유지한다. E 선택만으로 브라우저 데이터가 E로 옮겨지지 않는다.
- 신규 베타 전용 기반 경로는 `E:/CarebridgeBeta`로 선택한다. 이번에는 그 아래 `checks/storage-check-<UUID>`만 합성 파일 검증하고 자기 시험 파일만 정리한다. 기존 E 파일을 채택/수정/삭제하지 않는다.
- 이후 전용 `private`와 하위 디렉터리를 초기화했고, 보호된 `private/checks/storage-check-<UUID>`에서도 같은 IO를 재검증했다. 생성한 비공개 디렉터리는 유지하며 합성 시험 객체/UUID 시험 폴더만 정리했다.
- `PrivateFileStore`는 전용 비공개 절대 경로·UUID 객체·덮어쓰기 거부·전체 해시 확인·삭제 fence를 지원한다. Windows의 Node `mode` 숫자는 운영 NTFS ACL의 대체 증거가 아니며 디렉터리 fsync/전원 손실 내구성도 이번에 입증하지 않는다.
- 후속 시험은 프로젝트 전용 Windows PostgreSQL의 실제 `data_directory`가 E임을 검증했다. 운영 DB/서비스는 아직 만들지 않았으며 Docker 전체 디스크는 그대로다. 이름 있는 Docker 볼륨을 만들었다는 사실만으로 E에 저장됐다고 하지 않는다. Docker 전체 디스크 이동은 기존 다른 볼륨까지 영향을 주므로 실행하지 않는다.

## 재현 가능한 합성 IO 확인

```powershell
node scripts/check-beta-storage.mjs --base E:/CarebridgeBeta --confirm-synthetic-e-drive
```

새 UUID 시험 경로만 사용한다. 실제 PNG 바이트/크기/해시 저장 → **새 Node 프로세스**의 재읽기 → 같은 ID 덮어쓰기 거부 → 잘못된 해시 부분 파일 정리 → 삭제 fence의 읽기/재생성 거부를 확인한다. 끝에는 자기 이름·정상 파일·링크 아님을 확인해 개별 unlink와 빈 시험 폴더 rmdir만 수행한다. 알 수 없는 파일을 발견하면 전체/재귀 삭제하지 않는다.

보고서는 Git/배포 제외 경로 `test-results/beta-storage-results.json`에 저장한다. 합성 IO 성공은 운영 ACL/암호화/전원 손실·DB/파일 일관성·실제 API 연결/기기 간 전달 성공이 아니다.

초기화 후 보호된 폴더에서 재현하려면 `--base E:/CarebridgeBeta\private`를 사용한다. IO 도구 자체는 ACL을 설정하거나 전체 베타 준비 완료를 판정하지 않는다.

## 베타 전환 전 필요한 작업

1. 실제 센터/보호자 베타로 범위 확정. 같은 센터/LAN/외부 사용 방식은 확인하고, 접근 통제·복구 준비 전에는 합성 자료만 사용하고 루프백 접근만 유지.
2. DB의 Windows 전용 도구·E 저장/정상 종료 재시작·별도 cluster 합성 복원은 확인했다. 운영 DB/서비스·검사 작업자와 결합된 영구 저장/시작·종료·복구는 별도로 구현/검증한다. 기존 Docker 자료 이동/초기화 없음.
3. 프로젝트 전용 Windows 계정/디렉터리 접근·키 보관/로그 최소화·가용량/업로드 한도·자원/감시를 실제 확인. 임의로 실제 계정·비밀번호/키를 만들거나 공개 코드에 넣지 않음.
4. 보존/파기·책임·RPO/RTO와 사본 처리 확정. E 안의 사본은 같은 디스크 고장에 대비한 독립 백업이 아니다. 실제 자료를 쓸 경우 독립 사본/복구 검증 없이 운영 준비 완료로 표시하지 않음.
5. 기존 브라우저 자료는 기본 보존. 이관이 필요하면 실제 계정·센터·아동/첨부 귀속을 승인된 매핑으로 처리하며 원본 자동 삭제 없음.
6. 비API 준비 후 마지막 API/화면 연결·실제 인증된 독립 기기의 사진/영상/대화·통신 단절/재접속 확인. [전체 완료표](communication-acceptance.md)의 미완료 요건 유지.

국내 디스크 위치만으로 지원 접근·로그/사본/외부 서비스 경로나 법적 적합성을 완료 판정하지 않는다. 지금은 저비용 로컬 베타 기반 선택/합성 준비 단계다.

## 전용 비공개 디렉터리와 NTFS 접근 권한

E 기본 상속에는 일반 Users의 읽기와 Authenticated Users의 수정이 있었다. 실제 자료 저장 디렉터리에 그대로 상속하지 않는다. `scripts/initialize-beta-storage.ps1`은 새 `E:/CarebridgeBeta\private`에만 상속을 차단하고 현재 Windows 사용자·SYSTEM·Administrators의 3개 명시적 권한을 설정/재검증한다. E 전체·기존 다른 디렉터리의 권한은 바꾸지 않는다.

```powershell
pwsh -NoProfile -File scripts/initialize-beta-storage.ps1 -Base E:/CarebridgeBeta -ConfirmLocalBetaStorage
```

그 아래 `media`, `recovery`, `secrets`, `logs`를 만든다. 소유 영수증이 없는 기존 private 경로/잘못된 소유자/추가 접근 규칙·링크 경로는 자동 채택/수정하지 않고 거부한다. 재실행은 영수증/권한을 확인하고 자료와 영수증을 덮어쓰지 않는다. 전용 OS 서비스 계정·저장 암호화·키 복구·서비스 활성화와는 구분한다. 복구 사본이 같은 E에만 있으면 독립 백업이 아니다.

E DB 후속에서 `checks`도 같은 초기화/ACL 검사 대상에 포함했다. 기존 시험 폴더를 링크 검사만으로 신뢰하지 않고 **쓰기 전에** 비공개 권한을 확인한다. 최초 4개 디렉터리 결과는 당시 기록이며 현재 initializer는 위 4개와 checks 5개를 다룬다.

Docker WSL2 데이터의 기본 위치는 E라고 추정할 수 없으며, [공식 Docker 문서](https://docs.docker.com/desktop/features/wsl/)에서도 별도 디스크 위치 설정을 설명한다. PostgreSQL 18 공식 이미지의 저장 마운트는 `/var/lib/postgresql`이며 [공식 이미지 설명](https://hub.docker.com/_/postgres)에 버전별 경로 변경이 명시돼 있다. **이번 NTFS 파일/권한 확인은 Linux PostgreSQL 데이터 디렉터리의 올바른 지속 저장 증거가 아니다.** 프로젝트 전용 DB 경로·재시작/복구를 별도로 구현/검증한 뒤 선택한다.
