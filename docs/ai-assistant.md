# Carebridge AI 도우미

## 구현 범위

2026-11-06 구현. 최신 `local-api/` 앱에 자유 대화와 치료사 기록 요약 도우미를 추가했다. OpenAI Responses API를 사용하는 서버 provider, 기존 인증을 거치는 HTTP 라우트, PC·모바일 대화창, 검토 후 기존 기록 작성란에 적용하는 흐름으로 구성한다.

일반 `npm run dev:local-api`는 AI provider를 활성화하지 않는다. 별도 실행기만 외부 AI를 연결한다. Vercel의 현재 정적 빌드는 `src/`만 배포하므로 이번 AI 기능은 공개 사이트에 반영되지 않는다.

| 기능 | 입력과 동작 | 저장·공유 |
| --- | --- | --- |
| 자유 대화 | 사용자가 직접 쓴 질문과 최근 AI 대화만 전송. 사용자·센터·아동 대화방별로 분리 | 서버 메모리에 최근 6회 문답까지 유지. 종료 시 사라짐 |
| 기록 요약 | 치료사가 저장 기록 선택 → 활동(`performed`)·반응(`response`) 두 항목 확인 → 명시적으로 생성 | 결과 확인 후 기존 요약 작성란에 넣음. 저장·공유는 기존 버튼으로 별도 수행 |

AI는 기록·계정·첨부를 검색하거나 저장·공유·삭제하는 도구를 갖지 않는다. 아동 프로필, 다른 메시지, 비공개 메모, 다음 계획, 측정 원본, 사진·영상은 자동 전송하지 않는다. 다만 활동·반응 자유 서술문에 개인정보를 적었다면 그 문장에 포함될 수 있다. **자동 익명화 기능이 아니므로 전송 미리보기에서 확인해야 한다.**

## RP APP에서 재사용한 부분

RP AI Agent의 `src/providers/openaiConversation.ts`, `src/providers/openaiIntent.ts`, `src/conversation/service.ts`에서 사용한 명시적 서버 키, 제한된 Responses 호출, 구조화된 결과 검증, 사용자별 문맥, 실행 전후 권한 확인 패턴을 Carebridge 서비스에 맞춰 구현했다. RP APP의 입시·학생 도구, 데이터, 프롬프트, 자격증명을 복사하거나 해당 프로젝트를 수정하지 않았다. 별도 에이전트 프레임워크나 SDK 의존성은 추가하지 않았다.

## 실행

현재 통합 프로토타입은 `Carebridge-OpenAI.cmd`로 실행한다. 홈 AI·기록 요약의 실제 OpenAI 연결과 제공 샘플 첨부를 함께 사용할 수 있다. PowerShell 7의 가려진 입력창에 키를 입력하며, 상세 실행·검증 범위는 [프로토타입 안내](prototype-demo.md)와 [실제 응답 검증](home-ai-openai-verification.md)에 있다. 아래는 별도의 기존 AI 시험 실행기 안내다.

Node.js 24와 서버 개발 의존성이 필요하다.

```sh
npm ci --ignore-scripts
npm --prefix server ci --ignore-scripts
```

Windows의 직접 사용하는 PowerShell 7에서 저장소 루트 기준으로 실행한다.

```powershell
.\scripts\start-local-ai.ps1
```

Node가 PATH에 없다면 `-NodePath`에 설치된 Node 실행 파일의 경로를 지정한다. 실행기는 키를 가려서 입력받고 자식 서버 프로세스에만 연결한다. 키를 채팅·명령 인수·소스·`.env` 파일에 붙여 넣을 필요가 없다. 실행 정책이 차단한다면 정책을 우회하지 말고 환경을 확인한다.

기존 보안 환경에서 프로세스 환경 변수 `CAREBRIDGE_OPENAI_API_KEY`를 이미 주입했다면 직접 사용하는 터미널에서 `npm run dev:local-ai`를 사용할 수 있다. 일반 `OPENAI_API_KEY`는 읽지 않는다. 다른 프로젝트의 키를 자동 재사용하지 않는다.

터미널의 새 주소와 가상 치료사/보호자 계정으로 로그인한다. 홈의 **AI 도우미**를 바로 누르면 연결된 아이가 한 명일 때 자동으로 선택해 열고, 여러 명인데 아직 선택하지 않았다면 아이 선택창을 표시한다. 연결된 아이가 없거나 연결을 확인하는 동안에는 사용할 수 없다. 치료사는 **기록 요약** 탭도 사용할 수 있다. 저장 기록이 없다면 먼저 가상 활동·반응을 입력해 기록을 저장한다. 기본 실행 직후에는 모델을 호출하지 않으며, 질문 전송 또는 초안 생성 때 호출한다. 이 기존 시험 실행기의 종료는 `q + Enter` 또는 `Ctrl+C`, 최대 실행 시간은 120분이다. 종료하면 시험 DB와 AI 대화가 사라진다. 통합 프로토타입은 별도 실행 시간 제한 없이 직접 종료한다.

### 모델·호출 제한

| 설정 | 기본값 |
| --- | --- |
| 모델 | `gpt-6-luna` |
| 추론 강도 | `none` |
| 출력 상한 | 요청당 800토큰 |
| 공급자 응답 제한 | 8초 |
| 호출 횟수 | 대화 20회 + 요약 20회, 실패 포함 |
| 자동 재시도 / 도구 | 없음 |
| 요청 저장 설정 | `store:false`, `background:false` |

서버 프로세스의 `CAREBRIDGE_AI_MODEL`, `CAREBRIDGE_AI_REASONING_EFFORT`로 모델/추론 강도를 바꿀 수 있지만 조합 지원 여부는 해당 모델 문서에서 확인해야 한다. 기본 Luna의 `none` 지원은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)에서 확인했다. 호출 상한은 프로세스를 재시작하면 초기화되며 **운영 청구액 제한을 대신하지 않는다.** 이미 전송된 호출은 취소·시간 초과여도 비용이 생길 수 있다.

## 데이터와 권한

- 기존 로그인·세션·Origin·예상 계정 검사를 유지한다. 모델 호출 전후 현재 방 참가 권한을 확인한다. 로그아웃·계정/대화 변경 시 화면의 AI 내용과 진행 중 요청을 정리한다.
- 요약 생성/적용 시 기록 revision과 전송 원문 hash를 다시 확인한다. 다른 편집이 발생하면 최신 기록을 다시 선택해야 한다. 기존 미저장 작성란을 덮어쓰지 않는다.
- JSON Schema와 런타임 검증은 응답 형식·크기·경계를 확인한다. 임상적 사실 정확성을 보장하지 않으므로 치료사가 원문과 대조한 뒤 수정·저장·공유한다.
- API 키는 서버에만 주입하며 브라우저 번들·응답·로그로 보내지 않는다. 실제 JavaScript 메모리의 완전한 지움을 보장하지는 않는다.
- 대화 문맥·요약 요청 영수증은 메모리에만 둔다. 동시 요청·실패한 요청 ID·중복 요청을 제한하여 자동 중복 호출을 피한다.
- 일반 `api.openai.com`을 사용한다. **국내 저장·국내 처리 또는 무보존을 보장하는 설정이 아니다.** `store:false`와 별개인 남용 모니터링, 캐시, 계정별 데이터 제어는 [OpenAI 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)에 따른다. 이 구현은 가상 자료로 검증하며 실제 아동 정보를 사용하는 운영 승인을 의미하지 않는다.

### 실제 OpenAI 연결 확인 — 2026-11-06

사용자가 가려진 터미널 입력으로 키를 연결한 새 합성 세션에서 Chrome 화면을 조작했다. 설정 모델은 `gpt-6-luna`, 추론 강도는 `none`이었다. 대화 2회와 기록 요약 1회의 실제 응답을 확인했다. 후속 질문은 앞선 두 요령을 한 문장으로 요약했고, 기록 초안은 선택한 활동·반응의 범위에서 생성됐다. 작성란 적용 후 별도로 저장했고 새로고침·재열기에서 두 번째 기록 버전과 요약 보존을 확인했다. 보호자 공유는 실행하지 않았다.

이 근거는 해당 날짜의 사용자 창과 실제 응답 관측이다. 자동 fixture 검사와 합산하거나 전체 임상 정확성·비용·지연 성능으로 확대하지 않는다. 토큰 사용량과 청구액은 수집하지 않았다. 증거 화면은 공개 제외 `test-results/ai-live-20261106/`의 `openai-summary.png`, `openai-applied.png`에 있다. 실행 세션은 종료된 과거 세션이며 그 주소·계정을 재사용하지 않는다. 이 절은 2026-11-12에 당시 관측과 보존 화면을 대조해 기록했다.

운영 공개 전에는 서버 배포 환경, 운영 인증과 저장, 영속적 호출/비용 한도, 실제 데이터 처리 조건을 결정해야 한다. 실키의 가상 자료 연결 확인이 실제 아동 자료 처리나 운영 공개 승인을 뜻하지는 않는다. 사진·영상 분석과 자동 메시지 발송은 이번 적용 범위에 포함하지 않았다.

## 녹음 기반 수업 기록 — 2026-11-16

사용자 결정: 기존 녹음 파일 업로드부터 구현하며, OpenAI를 사용하되 **가상 녹음으로만 개발·검증**한다. 실시간 녹음·마이크 권한과 실제 상담·치료 녹음의 수집은 이번 구현에 포함하지 않는다. 앞선 국내 통제 방침을 실제 자료에 대해 해제한 결정이 아니다.

### 사용 흐름

1. 전용 AI 실행기에서 가상 치료사로 로그인하고 아이의 대화를 선택한다.
2. AI 도우미 → 녹음 정리에서 해당 수업의 저장 기록을 고른다. 일정에서 만든 기록이면 기존 일정 연결이 유지된다.
3. M4A·MP3·WAV·WebM 음성 파일(최대 20MiB)을 선택하고 가상 자료·외부 전송 범위를 확인한 뒤 업로드한다. **업로드만으로 모델을 호출하지 않는다.**
4. ‘OpenAI로 전사·초안 만들기’를 누르면 시간 구간 전사와 구조화된 초안을 차례로 생성한다. 합성 응답 시험에서는 실제 모델이 아님을 화면에 표시한다.
5. 시간 구간별 원문과 활동·반응·회고 질문·다음 준비·보호자 보고서를 대조한다. 근거 구간을 누르면 해당 전사 구간을 확인할 수 있다.
6. 적용할 항목을 선택하고 검토 확인 후 기존 기록 작성란에 넣는다. 빈 항목만 기본 선택하며, 이미 적은 글을 바꾸려면 변경 전후 확인과 별도 선택이 필요하다.
7. 기존 작성 화면에서 수정·저장하고, 보호자 공유 미리보기에서 받는 사람과 공개 내용을 확인한 뒤 공유한다. 생성·적용 단계에서 자동 저장하거나 메시지를 보내지 않는다.

| 결과 | 적용 위치 | 공개 범위 |
| --- | --- | --- |
| 녹음에서 확인한 활동 | performed | 치료사 기록 |
| 발언으로 확인되는 아이 반응 | response | 치료사 기록 |
| 확인할 질문·불확실한 내용 | privateNote | 치료사 내부 메모 |
| 녹음에서 언급한 다음 수업 준비 | nextPlan | 치료사 기록 |
| 보호자가 이해할 활동 보고서 | summary | 치료사 검토와 기존 별도 공유 후 공개 |
| 시간별 전사·원본·생성 이력 | 전용 임시 녹음 세션 | 업로드한 치료사 본인만 |

보호자는 아이 정보의 월별 일정 아래 ‘날짜별 치료 보고서’에서 현재 공유 중인 보고서로 이동한다. 서버가 이미 권한을 확인한 공유본만 사용하며, 철회·숨김·삭제·다른 아이·다른 달 자료를 제외한다. 이 목록은 **날짜 기준**이다. 같은 날 여러 수업이 있을 수 있으므로 특정 일정 한 건과 같은 자료라고 추정하지 않는다. 원음·전체 전사·내부 메모는 이 목록에 포함하지 않는다.

### AI 결과의 의미

전사는 발언자의 신원이나 역할을 확정하지 않는다. 초안의 각 문장은 실제 전사 구간 ID를 참조해야 하며, 존재하지 않는 구간·잘못된 형식·과도한 길이는 거부한다. 이 검사는 인용의 형식과 범위를 확인하는 것이며, AI 문장이 해당 발언을 정확히 해석했다는 보증은 아니다.

‘부족한 부분 피드백’은 녹음에 근거한 **치료사가 확인할 회고 질문**으로 구현했다. 녹음만으로 보이지 않는 자세·동작·치료 효과·치료사 실력을 평가하지 않는다. 다음 준비에는 녹음에서 언급한 계획만 정리하고, 새로운 치료 처방이나 활동 강도를 만들지 않는다. 불명확한 부분과 실제 시행 여부는 담당자가 확인한다.

### 처리·권한·비용

- 일반 로컬 실행기와 정적 Vercel 데모에는 이 기능을 활성화하지 않는다. 전용 AI sandbox의 서비스 주입과 서버 HTML 표식으로만 UI가 열리며 URL 옵션으로 활성화할 수 없다.
- 원음은 서버 메모리에 별도로 보관하며 받는 즉시 SHA-256과 서버 수신 시각을 기록한다. 전사·AI 초안은 원음과 분리하고 원본 다운로드 시 브라우저에서도 크기·해시를 대조한다. 서버 수신 시각은 실제 녹음 시작 시각의 인증이 아니다.
- 파일명과 MIME·서명은 형식 힌트만 검사한다. 악성코드 검사나 완전한 오디오 디코딩이 아니므로 실제 자료 운영 경로로 사용할 수 없다. 원본은 명시적 다운로드만 제공하고 브라우저에서 자동 재생하지 않는다.
- 원본과 처리 중 사본은 합계 80MiB, 전체 세션 20개, 소유자·기록별 3개로 제한한다. HTTP에서도 서비스당 큰 업로드/다운로드를 한 번에 하나만 허용한다.
- 외부 전사는 whisper-1의 시간 구간 응답을 사용한다. 그다음 Responses API에 전사 구간만 보내 구조화된 결과를 받는다. 외부 파일명은 synthetic-audio로 대체하지만 **음성 내용의 자동 익명화는 하지 않는다.**
- 전사와 분석 두 호출을 합해 기본 180초 제한을 적용한다. 실패를 포함해 분석 작업 최대 10회, 자동 재시도 없음. 재시작하면 한도가 초기화되므로 운영 비용 한도를 대신하지 않는다. 취소 전에 전송된 호출에는 비용이 발생할 수 있다.
- 로그인 세션·현재 담당 관계·기록 버전·작업 소유권을 전사 직전, 분석 직전, 결과 반영 전 확인한다. 취소·삭제·종료·권한 해제 후 늦은 결과를 반영하지 않는다.
- 조회는 기존 인증 쿠키와 예상 계정 헤더를 사용하고 대용량 본문을 받기 전에 권한을 확인한다. 원본은 캐시 금지·다운로드 전용 응답으로 반환한다. 센터 관리자라는 이유만으로 임상 녹음 접근권한을 확대하지 않는다.
- 원본·전사·초안은 서버 종료 시 사라진다. 화면 확인은 실녹음의 동의 수집 절차가 아니며, 가상 자료 확인란도 실제 개인정보가 없는지 기술적으로 탐지하는 기능은 아니다.

### 센터 보관 요구와 실제 베타 전에 남은 작업

센터 요구의 제품 목적은 ‘분쟁 대응을 위한 원본 및 처리 이력 보존’으로 정의한다. 해시와 전사·수정본 구분은 자료 확인을 도울 수 있지만, 녹음의 적법성·발언자의 신원·증거능력·증명력을 보장하지 않는다. 현재의 임시 메모리 세션은 그 보관 기능을 완성한 상태가 아니다.

실제 자료 공개 전에 녹음 참여자와 아동의 법정대리인 관련 동의·민감정보 처리 근거·국외 이전 조건을 검토하고, 센터의 목적별 열람 권한, 열람·다운로드 감사, 보존기간·파기·적법한 보존 예외, 암호화한 영속 저장과 독립 백업·복원을 구현해야 한다. 치료사 원음 접근과 센터 운영 권한은 분리하여 승인 범위를 설계한다.

공식 검토 출처: [통신비밀보호법 제14조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028764483), [개인정보 보호법 민감정보·동의 조항](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1006183947), [개인정보 보호법 최신 개정 내역](https://law.go.kr/LSW/lsRvsDocListP.do?lsId=011357). 개별 센터의 법적 적합성이나 녹음의 증거 효력을 확정한 검토는 아니다.

기술 출처: [OpenAI 음성 전사](https://developers.openai.com/api/docs/guides/speech-to-text), [전사 API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create), [OpenAI 데이터 처리 조건](https://developers.openai.com/api/docs/guides/your-data). 일반 OpenAI API 연결과 store:false만으로 국내 처리나 무보존을 보장하지 않는다.
