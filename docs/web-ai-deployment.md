# Vercel 웹 AI 배포 구성

가상 자료로 시연하는 웹 프로토타입에 실제 OpenAI 자유 대화와 기록 요약을 연결한다. 정적 화면은 `src/` → `dist/`, AI 요청은 같은 사이트의 `api/ai/` Vercel Functions → OpenAI Responses API를 사용한다. `local-api/`의 계정·DB·대화·첨부 서버는 이 배포에 포함하지 않는다. 이 문서는 구현 구성과 확인 절차이며 배포 완료나 실제 응답 확인을 주장하지 않는다.

## 서버 환경변수

배포 환경에 다음 값을 설정하고 새 배포에 반영한다. API 키·체험 코드·서명 비밀값을 소스, 브라우저 번들, URL, 로그에 넣지 않는다.

| 이름 | 용도와 조건 |
| --- | --- |
| `CAREBRIDGE_OPENAI_API_KEY` | OpenAI 호출용 서버 키. 일반 `OPENAI_API_KEY`를 자동 재사용하지 않는다. |
| `CAREBRIDGE_WEB_ACCESS_CODE` | 별도로 전달하는 AI 체험 코드. 무작위 URL-safe 문자열 32~128자. |
| `CAREBRIDGE_WEB_SESSION_SECRET` | AI 세션 서명용 비밀값. 체험 코드와 서로 다른 무작위 URL-safe 문자열 32~128자. |
| `CAREBRIDGE_WEB_ORIGINS` | 허용할 HTTPS origin을 쉼표로 구분한다. 경로·마지막 `/` 없이 최대 8개. 실제 접속할 기본 도메인과 사용자 도메인을 포함한다. |
| `CAREBRIDGE_AI_MODEL` | 사용할 모델. 생략하면 `gpt-6-luna`. |

Vercel이 제공한 유효한 `VERCEL_URL`의 배포 origin도 허용한다. 요청의 전달 헤더로 허용 도메인을 추가하지 않는다. 필수 설정이 없거나 유효하지 않으면 AI 사용을 차단하며 예시 응답으로 대체하지 않는다.

## 접근과 데이터 흐름

1. 홈의 **AI 도우미**에서 AI 체험 코드와 가상 자료 사용 확인을 입력한다. 화면의 시연 역할 선택은 서버 인증이 아니다.
2. `/api/ai/session`이 코드를 확인하면 서명된 1시간 쿠키를 발급한다. 쿠키는 `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/api/ai`이며 AI 사용 권한만 가진다. 서버 상태를 메모리에 저장하지 않아 함수 인스턴스가 바뀌어도 같은 만료 시각까지 검증할 수 있다.
3. `/api/ai/respond`는 허용 origin·같은 사이트 요청·세션·입력 형식을 확인한 뒤 서버 키로 OpenAI를 호출한다. 변경 요청에는 `X-Carebridge-AI: 1`이 필요하며, 연결·AI 생성 요청에는 가상 자료 확인도 필요하다. 응답과 세션 상태는 브라우저·CDN에서 캐시하지 않는다.
4. **연결 종료**는 현재 브라우저의 AI 쿠키와 화면 대화를 지운다. 체험 코드 또는 서명 비밀값을 교체하면 이전 세션도 무효가 된다. 개별 세션을 서버에서 따로 폐기하는 저장소는 없으므로 복사된 쿠키까지 즉시 취소하는 기능은 아니다.

웹 기록·첨부는 기존 브라우저 저장소에 남는다. AI 대화는 화면 메모리에만 두며, 전송한 질문과 최근 대화만 요청에 포함한다. 기록 요약은 선택한 저장 기록의 **활동(`performed`)·반응(`response`) 두 항목**을 미리 보여주고 명시적으로 전송한다. 다른 기록·프로필·비공개 메모·사진·영상은 자동으로 보내지 않는다. 자유 서술문을 자동 익명화하지 않으므로 가상 내용만 입력한다.

요약은 검토용 초안이다. **검토한 초안을 작성란에 넣기**는 기존 기록 편집란에 넣을 뿐 저장하거나 보호자에게 공유하지 않는다. 사용자가 원문과 대조하고 수정한 뒤 기존 저장·공유 버튼을 사용한다. 생성과 적용 사이에 선택 기록·역할·아동·원문이 달라지면 이전 초안을 적용하지 않는다.

## 제한과 범위

- 요청 본문은 최대 24KiB, 대화는 최대 11개 메시지·총 16,000자이다. 사용자 메시지는 2,000자, AI 메시지는 6,000자까지이며 마지막 메시지는 사용자 질문이어야 한다. 요약 원문은 활동·반응 각각 2,000자까지이다. 문자 제한보다 본문 바이트 제한에 먼저 도달할 수 있다.
- 모델 출력 상한은 800토큰, 공급자 응답 대기는 20초이며 자동 재시도하지 않는다. Vercel 함수는 최대 30초로 설정한다. 취소·시간 초과가 이미 발생한 호출 비용을 취소한다는 뜻은 아니다.
- 배포 시 WAF의 `/api/ai/` POST 요청 제한을 **IP당 60초에 20회 초과 시 429**로 적용하고 실제 설정을 확인한다. 이는 IP별 호출 속도 제한이며, 모든 사용자 합산 호출 수나 API 청구액의 상한이 아니다. 로컬 실행기의 프로세스별 호출 제한도 웹에 적용되지 않는다.
- 일반 OpenAI API로 전송하며 `store:false`를 사용한다. 서울 함수 리전이나 이 옵션만으로 국내 처리·무보존을 보장하지 않는다. 실제 아동 자료, 녹음 처리, 기관별 운영 계정, 기기 간 기록 동기화는 이번 웹 AI 범위에 포함하지 않는다.

## 배포 확인

아래는 수행해야 할 확인 항목이며 완료 증거가 아니다.

1. 루트의 `npm run check`, `npm test`, `npm run build`와 `node --test tests/web-ai-http.test.mjs`를 실행한다. 자동 검사에서 공급자 응답을 주입한 결과와 실제 OpenAI 호출 결과를 구분한다.
2. 배포에서 세션 API의 캐시 금지 헤더, 익명·잘못된 코드·만료된 세션·다른 origin 요청의 거절, WAF 설정을 확인한다. 브라우저 번들·응답·로그에 비밀값이 없는지 확인한다.
3. 올바른 체험 코드로 연결한 뒤 가상 질문을 보내 실제 모델 답변을 확인한다. 요약은 가상 활동·반응을 먼저 저장하고 전송 미리보기 → 초안 생성 → 작성란 적용까지 확인한다. 적용만으로 저장·공유되지 않는지 확인한다.
4. PC·모바일 화면에서 입력·전송·오류·취소·연결 종료를 확인한다. 역할·아동·기록이 바뀐 뒤 오래된 응답이 새 화면에 남거나 적용되지 않는지도 확인한다.

로컬 통합 앱은 [AI 도우미 안내](ai-assistant.md), 전체 빌드와 복구는 [배포 안내](deployment.md)를 참고한다.
