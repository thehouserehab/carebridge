# 실제 파일 검사 준비: ClamAV 통신·로컬 엔진

작성 2026-10-02 · 갱신 2026-10-04. P1 파일 처리의 후속 작업이다. **로컬 실제 ClamAV 13개에 이어 별도 FFmpeg 디코더 38개 시나리오를 검증했지만 두 경로 통합·운영 파일 승인은 완료하지 않았다.** API와 화면은 연결하지 않았다. 기존 브라우저 파일·저장 키·임시 업로드 상태 전환은 변경하지 않았다. 출처/digest·정의 갱신·실제 격리·검증 한계는 [안티멀웨어 검증 기록](clamav-native-verification.md)과 [디코더 검증 기록](media-decoder-verification.md)에 구분했다.

파일별 실행 후속은 [디코더 격리 문서](decoder-job-isolation.md)에 분리했다. 고정 byte-only stdin·각각의 오프라인 namespace/tmpfs·실제 종료/소유권 정리와 최소 decoder artifact의 합성 28개를 검증했다. 기존 ClamAV나 `MediaUploads`에 연결하지 않았으며 Windows 시험 전용 transport만 있다. 운영 Linux transport·durable queue/장애 회수·metadata 제거·두 경로 통합은 남아 있다.

## 현재 범위

2026-10-05 최신은 [원본/후보 검사 결합](media-preparation.md)이다. 실제 승인 ClamAV·Linux adapter·파일당 오프라인 worker를 연결한 이미지 native 12개와 전체 허용 형식의 최소 artifact 준비/디코딩 49개를 확인했다. 원본의 성공 디코딩 뒤에만 metadata 처리를 하며 후보의 전체 디코딩·manifest/timeline·정확한 반환 바이트를 재검사하고 같은 정의 상태로 후보를 검사한다. `LocalClamAvClient` 자체의 계약이나 `MediaUploads` 기본 검사기는 바꾸지 않았고 운영 객체·queue·업로드 승인/공유·API/화면은 아직 아니다. 아래 초기 Windows-only/결합 전 한계는 당시 기록이며 최신 구현·초기 실패·지원 부분집합/운영 경계는 새 문서를 따른다.

2026-10-05 [영상 후보 후속](video-metadata-processing.md)으로 MP4/WebM 압축 영상/음성·색/회전·타이밍/오프셋을 유지하는 컨테이너 변환과 native 19개를 추가했다. 원본 경고 거부를 유지했고 이를 변환으로 숨겨 승인하지 않는다. ClamAV/전체 디코딩/변환본 저장의 운영 결합이나 `MediaUploads.inspect` 연결은 아직 아니다.

최신 이미지 후속은 [공유용 메타데이터 처리](image-metadata-processing.md)의 v2다. 원본을 수정하지 않는 후보 생성과 지원 ICC RGB/회색 v2/v4 재작성에 대해 독립 CMM 색 비교·실제 픽셀/재생/변조 대조 27개를 확인했다. copyright/프로필 생성 날짜는 보존하므로 익명화는 아니다. ClamAV/디코더 결합·영상/미지원 ICC·기기 표시·원본/변환본 저장·파일 승인은 아직 아니다. 운영 Linux 경로는 [별도 구현/복구 검증](linux-decoder-runtime.md)으로 추가했고, 이 문서의 초기 Windows-only 한계는 당시 단계의 범위다. `LocalClamAvClient`/`MediaUploads`의 현재 계약은 변경하지 않는다.

`server/clamav-client.mjs`의 `LocalClamAvClient`는 서버 내부에서 명시적으로 생성하는 안티멀웨어 클라이언트다. 외부 SaaS에 파일을 보내지 않고, 설정된 같은 호스트의 ClamAV daemon으로 파일 바이트만 스트리밍한다. 파일명·아동/계정 ID·URL·저장 경로는 전송하지 않는다. 새 의존성, 환경변수 자동 활성화, HTTP 경로, 시스템 설치, 유료 자원 생성은 없다.

`scan()`의 `clean`은 **해당 안티멀웨어 검사에서 탐지되지 않았다는 뜻**이다. 이미지·영상 형식, 전체 프레임의 디코딩, 재생 가능성, 메타데이터 제거 또는 무해함을 보증하지 않는다. 정상 디코딩을 수행한 것처럼 가로/세로/진행 시간 값을 만들어 반환하지 않는다.

의도적으로 `scanner.inspect()`를 구현하지 않았다. `MediaUploads`에 이 클라이언트를 검사기로 바로 주입하면 생성자가 거부하며 기본 검사기는 계속 미설정이다. 반환값에도 디코딩 증명과 `carebridge-media-v1` 승인 정책이 없다. `status()`와 `scan()`은 항상 `mediaAcceptanceReady: false`를 포함한다. 임시 파일의 승인·공유·현재 권한 검사는 기존 서비스가 담당하며 이 모듈이 DB 상태를 바꾸지 않는다.

## 입력과 통신 계약

| 항목 | 계약 |
| --- | --- |
| 내부 구성 | `endpoint: { host, port }`, `approvedEngineVersions`, `daemonTimeZone: 'UTC'`를 명시한다. 요청 본문으로 결정하지 않는다. |
| 연결 대상 | 리터럴 `127.0.0.1` 또는 `::1`과 유효 포트만 허용. DNS·원격 주소·URL·경로·Unix socket/Windows named pipe는 현재 지원하지 않는다. |
| 버전 | 운영자가 승인한 정식 `x.y.z` 버전 목록만 허용. 기본 승인 목록·`latest`·개발 버전은 없다. 테스트의 `1.4.3`은 가상 응답 값이며 운영 권장 버전이 아니다. |
| `status({ signal? })` | `PING` 응답, `VERSIONCOMMANDS`의 필요한 명령, 보고된 엔진/정의 날짜를 검사한다. 안티멀웨어 연결 진단이며 파일 승인 준비 판정이 아니다. |
| `scan({ stream, type, size, sha256 }, { signal? })` | 서버 소유 바이트 모드 Node Readable, 기존 허용 MIME·사진 10MiB/영상 50MiB·전체 SHA-256을 받는다. 파일명/경로 등 추가 필드는 거부한다. |
| 응답 | 제한된 엔진 식별·정의 버전/시각, 탐지 결과, 확인 바이트 수/해시만 내부 호출자에게 반환. 원문 오류·탐지명·경로·내용·자유 설명은 반환/기록하지 않는다. |
| 실패 | 입력/바이트 수/내용 해시 불일치는 `SCAN_INVALID`. 연결·정의·응답·IO·한도·취소·시간 초과는 `SCAN_UNAVAILABLE`. 내부 오류 원문이나 취소 이유는 예외에 포함하지 않는다. |

한 명령당 별도 연결을 사용한다. `z` 명령/NUL 응답, INSTREAM의 4바이트 big-endian 길이와 종료용 0 길이 프레임을 사용한다. 응답은 읽으면서 전송하며 파일 전체를 메모리에 모으지 않는다. 프레임은 최대 64KiB로 복사하고 전송 콜백을 기다려 쓰기 대기열을 제한한다. 응답은 4KiB 이하다. 방식은 [공식 ClamD 프로토콜](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)에 근거한다.

파일의 정확한 바이트 수·전체 SHA-256·입력 EOF를 확인한 뒤에만 종료 프레임을 보낸다. 응답 NUL만 보고 성공하지 않고 daemon의 EOF까지 기다린다. 추가/지연 응답, 조기 정상 응답, 크기 제한 오류, 형식 불명 응답은 정상 판정하지 않는다. 탐지 응답은 원문 탐지명을 버리고 `rejected`만 반환한다.

전체 작업 제한은 기본 90초, 연결 제한은 2초다. 최대 동시 작업은 인스턴스당 기본 2개(구성 상한 4개)이며 무한 대기열을 만들지 않는다. 제한 초과는 재시도 가능한 검사 불가다. 전체 작업 제한에는 사전 점검·스트리밍·최종 버전 점검이 포함된다. 성공·실패·취소 모두 소켓과 입력 스트림을 닫는다. 호출자는 검사 전용 새 스트림을 제공해야 한다. 여러 프로세스의 전체 검사량·daemon 내부 작업 취소/회수까지 보장하지 않으며 운영 작업 큐·프로세스 제한은 별도로 필요하다.

## 검사 정의·시각·신뢰 경계

검사 전 지원 명령과 정의 상태를 확인하고 검사 후 `VERSION`을 다시 확인한다. 엔진/정의가 바뀌거나 사후 정의가 오래되면 결과를 폐기한다. 기본 정의 최대 나이는 48시간이며 내부 구성은 이를 줄일 수만 있다. 5분을 넘게 미래로 보고된 날짜와 불가능한 달력 날짜도 거부한다.

**daemon을 실제 `TZ=UTC` 환경으로 실행하고 호스트 시간을 동기화해야 한다.** ClamAV VERSION은 timezone 없는 ctime 문자열을 사용하므로 클라이언트가 timezone을 자동 추정하지 않는다. 생성자의 `daemonTimeZone: 'UTC'`는 운영자 확인을 요구하는 계약일 뿐 실제 프로세스 설정을 검증하는 기능이 아니다. [ClamAV VERSION 구현](https://github.com/Cisco-Talos/clamav/blob/main/clamd/session.c)을 참고한다.

버전/날짜는 daemon이 보고한 값이다. 공식 서명 파일의 진위, 전체 로딩 상태, 프로세스 신원, 검사에 사용된 엔진의 암호학적 증명을 뜻하지 않는다. 사전/사후 비교 사이에 정의가 바뀌었다가 돌아온 경우를 검출할 수 없다. 운영에서는 검증된 패키지·정의, 배포 시 승인 버전, 제어된 갱신/검사 작업, 서비스 계정과 설정 파일 접근 통제가 필요하다.

## 실제 엔진 환경의 승인 기준

2026-10-03 사용자가 로컬 PC 설치를 승인했다. [실행환경 설치 이력](local-runtime-setup.md)에 설치 파일의 해시/서명, WSL 관리자 승인, Docker 사용자별 설치와 시작 장애 복구를 기록했다. 2026-10-04에는 로컬 Linux 엔진 29.8.1과 실제 PostgreSQL 8개 시나리오에 이어 실제 ClamAV 1.4.6의 합성 검사·정리를 실행했다. 약관/로그인/결제/보안 설정을 대신 처리하지 않았다. 아래 기준 중 실제로 시험한 범위만 검증 기록에 표시하며 기본 격리 정책은 유지한다.

실제 ClamAV는 읽기 전용·비관리자·네트워크 없는 scanner와 별도 합성 worker에서 검증했다. 공개 정의 updater만 외부 통신하며 검사 파일을 받지 않는다. 정의 28142/UTC `2026-10-03T06:24:16.000Z`와 48시간 제한, 무해 탐지·ZIP 개수/크기 경계 등을 확인했다. 이후 별도 오프라인 FFmpeg 9.0.2 작업자에서 허용 코덱의 합성 조합·전체 프레임·최대 바이트 용량·출력/시간 한도·손상·활성 프로세스 취소/정리 38개를 검증했다. **운영 파일 승인·metadata 제거·두 경로 통합은 아직 완료하지 않았다.** 아래 전체 운영 기준이 모두 완료된 것은 아니다.

1. 국내 Linux 검증 환경 또는 사용자가 승인한 로컬 격리 환경에 승인 버전의 ClamAV와 실제 디코더를 설치한다. 패키지/이미지 출처·버전·서명을 확인하고 가능한 경우 불변 digest를 고정한다.
2. 검사 daemon은 비관리자 전용 계정으로 실행한다. TCP를 쓴다면 같은 호스트의 loopback에만 바인딩하고 외부 포트 노출을 금지한다. TCP 자체는 인증/암호화를 제공하지 않으므로 같은 호스트의 악성 프로세스·포트 사칭을 이 클라이언트만으로 막을 수 없다. Unix socket 권한 기반 통합은 별도 구현 대상이다. [ClamAV 운영 안내](https://docs.clamav.net/manual/Usage/Scanning.html)를 참고한다.
3. 공식 검사 정의를 갱신하고 daemon에 실제 로딩됐는지 확인한다. 정의 갱신 프로세스와 임상 파일 검사 프로세스를 분리하고, 후자는 외부 네트워크·불필요한 볼륨 접근을 제한한다. 로컬 시험에서는 FreshClam으로 공개 정의를 실제 갱신한 뒤 updater를 종료하고 읽기 전용 정의로 검사했다. 외부 정의 다운로드/미러·로그·지원 경로는 전체 국내 통제 검토에 남아 있다.
4. `StreamMaxLength`와 `MaxFileSize`는 허용 영상 50MiB를 포함해야 한다. `MaxScanSize`·재귀/파일 개수·CPU/메모리/임시 디스크·대기열은 유한한 운영 한도로 설정한다. 제한으로 검사가 생략된 파일을 정상으로 처리하면 안 된다. `AlertExceedsMax` 등 실제 버전의 제한 초과 탐지 동작을 시험한다. 클라이언트의 상태 점검은 이 설정을 읽거나 증명하지 않는다. [공식 clamd 설정 예시](https://github.com/Cisco-Talos/clamav/blob/main/etc/clamd.conf.sample)에 옵션 의미가 있다.
5. `LogClean`·verbose/debug·확장 탐지 정보·임시 원본/metadata 보존을 제한한다. 서비스의 비공개 임시 경로·권한·암호화·삭제 및 백업 정책까지 확인한다. 프로세스 시간 초과가 daemon 내부 검사를 즉시 취소한다고 가정하지 않는다.
6. 합성된 정상 파일, 공식 무해 탐지 시험 자료, 손상 파일·최대 용량·제한 초과·정의 없음/오래됨·갱신 중·프로세스 장애를 실제 엔진으로 시험한다. 일반 사진/영상도 전체 프레임·코덱·다중 프레임과 픽셀/진행 시간/리소스 한도를 확인하는 별도 디코더 경로가 필요하다.
7. 두 검사 경로와 메타데이터/변환본 정책이 모두 검증된 다음에만 `scanner.inspect()` 통합을 설계한다. API·화면 연결은 그 이후 마지막 단계이며 실패 시 계속 격리해야 한다.

안티멀웨어·디코더가 실제로 동작해도 개인정보 보호, 국내 통제, 보존/파기·복구와 전체 보안 검증이 완료됐다는 의미는 아니다. 실제 아동/건강 자료 사용을 허용하지 않는다.
