2026-10-02 [비공개 임시 업로드 기반](media-upload-storage.md)과 [첨부 원본 연결·공유 접근](media-binding-storage.md) 추가: 예약·스트리밍·내용 검증·검사 대기·원 소유자 미리보기·취소/삭제 재시도에 이어 대화/기록/피드백 첨부를 연결하고 선택 공유·철회 후 권한·수정본 이력 보존을 구현했다. 해당 단계의 서버 검증은 122개다. 실제 검사기·운영 객체 저장소·장기 보존/파기 정책·HTTP/화면 연결은 남아 있다.

같은 날 [최소 기본정보·기존 계정 센터 연결](profiles-provisioning.md)을 추가했다. 아동/참여자 표시 정보, 센터에 노출하지 않는 가족 관심사, 본인 세션/초대 확인을 구현했다. 계정 소속만으로 아동 대화 권한을 부여하지 않는다. 해당 단계 서버 검증은 143개이며 화면 연결은 마지막 단계다.

개편안의 P0-1(홈·대화)과 P0-2(상세 기록 연결)를 구현했다. 가상 역할 전환으로 검증하는 로컬 프로토타입이며, 서버에는 실제 계정·세션 기반이 준비됐지만 기존 화면과 대화 API가 연결되지 않았다. 현재 배포 사이트 역시 서버 메시지 서비스가 아니다. 실제 개인정보·아동 사진·건강정보를 입력하면 안 된다.

## 반영한 변화

- 치료사·보호자 메뉴를 홈 / 대화 / 기록 / 아이 정보로 정리했다. 센터의 운영 현황·아동·일정은 유지했다.
- 치료사 홈은 담당 아동 전체, 보호자 홈은 연결된 아동만 집계한다. 새 소식, 다음 일정, 이어 쓸 초안(보호자는 가정 활동) 순서다.
- 홈 소식을 누르면 해당 아동의 대화와 읽지 않은 메시지 위치로 이동한다. 데스크톱은 목록·대화 분할, 모바일은 단일 화면이다.
- 일반 소식·사진·영상, 공유 기록·활동 카드, 원문 인용 답변, 활동 피드백을 하나의 대화 흐름으로 연결했다.
- 읽음과 치료사의 ‘다음 회기에 반영’ 메모를 구분했다. 후자는 내부용이며 공개 답변은 따로 전송한다.
- 대화의 ‘기록에 참고’에서 원문·첨부를 확인하고 다음 회기 기록을 작성한다. 일반 메시지를 자동으로 임상 기록으로 만들지 않는다.
- 기록은 활동·반응·다음 계획을 기본으로 한다. 상세 관찰, 복수 평가, 가정 활동, 내부 메모, 사진·영상은 접어서 제공한다.
- 빈 초안을 허용하고 정식 기록에는 작성 내용을 요구한다. 제목은 날짜·활동으로 제안한다. 이전 기록에서 목표·측정 항목만 가져오며 과거 측정값은 복사하지 않는다.
- 공유 전 보호자용 요약·수신자·선택한 첨부를 확인한다. 상세 관찰·평가 원문·내부 메모·다음 계획은 공유하지 않는다.
- 센터의 담당 관계 관리에서 가상 치료사·보호자 연결을 바꿀 때 기존 기록 열람 범위를 명시적으로 확인한다. 현재 데모는 확인된 관계에 기존 이력을 표시하며, 연결 해제된 참여자는 새 화면에 접근하지 못한다.

| 개편안의 검증 항목 | 구현·증거 |

| 2. 보호자 답변·첨부, 치료사 공개 답변, 내부 계획 비노출 | 역할별 메시지 조회, 공유본 참조; 사진·영상 재생과 비노출 브라우저 검증 |
| 3. 답변 참고 기록, 기본 3항목, 복수 평가, 공유 미리보기 | `record-fields.js`, `record-ui.js`; 서로 다른 측정값 2개와 실제 값 0 저장 검증 |

| 5. 실패·재시도·방 전환 시 입력/첨부 보존, 중복 방지 | 발신 clientId, 별도 초안 IndexedDB, 파일 저장 롤백; 전송 실패 후 재시도와 방별 초안·재접속 검증 |
| 6. 모바일·키보드 접근 | 320/390px 전 역할 메뉴, Tab 이동, 높이 420px 축소 뷰포트 검증; 실물 휴대전화 키보드는 별도 확인 필요 |

기존 공유본·피드백 카드는 원본 ID를 참조한다. 재공유는 새 버전이며 과거 답변은 당시 버전에 연결된다. 종료된 버전은 보호자에게 내용 없는 안내로 대체하지만 독립 메시지는 삭제하지 않는다. 직접 대화 첨부는 방 참여자에게, 기록 첨부는 선택한 파일만 공유된다.

## 코드와 저장 구조

- `app.js`: 화면 연결·기존 운영 기능·기록 폼 구성

- `conversations.js`: 대화/메시지/읽음, 역할별 조회, ID 참조, 저장 형식 변환

- `record-fields.js`, `record-ui.js`: 상세 기록 검증·입력·조회
- `repository.js`: 기존 저장소 인터페이스 유지, 전환 백업, revision 충돌 검사

- `config.js`, `domain.js`, `conversations.js`: 가상 구성원 선택지, 관계 변경 검증, 연결 해제된 이전 참여자의 메시지 보존

## UI 추가 정리 2026-10-02

기존 99개 레이아웃 검사는 통과했지만, 조건을 확장하니 긴 입력값에서 실제 넘침이 재현됐다. 문제는 공백 없는 평가 단위/조건, 가족 피드백의 내부 메모, 대화 인용문과 641px의 좁은 데스크톱 대화 열이었다. 페이지 전체를 숨기는 방식 대신 해당 텍스트의 줄바꿈과 Grid/Flex의 최소 너비를 조정했다.

- `src/styles.css`: 기록/아이 정보 그리드의 최소 너비, 평가 비교 행과 피드백/대화 인용문의 줄바꿈, 모달 제목과 닫기 버튼 간격을 수정했다. 모바일 일정은 제목·설명을 첫 줄에, 상태·동작을 다음 줄에 배치하고 제목 13px·설명 11px로 읽기 쉽게 했다.
- `src/communication.css`: 대화방의 열 너비를 명시하고 641~900px 목록/대화 간격을 조정했다. 목록의 이름과 발신 역할을 분리하고 메시지의 발신자·시간을 필요한 경우 줄바꿈한다.
- `src/viewport.js`: CSS 화면 높이가 그대로인 브라우저에서도 실제 보이는 `visualViewport`가 500px 이하이면 모바일 대화 상단을 축약한다. 이때 긴 아동 이름만 시각적으로 말줄임하며 접근성 이름과 원래 데이터는 전체 이름을 유지한다. 이름은 아이 정보에서 전체를 확인할 수 있다. 높이가 복원되면 참여자 설명과 일반 레이아웃도 복원된다.
- `tests/layout-browser.mjs`: 320/390/640/641/720/768/1024/1440px, 유효 길이의 합성 이름·메시지·평가·활동·메모, 공유 미리보기/인용/담당 관계 모달을 검사한다. 420px 높이와 CSS 높이는 유지한 채 `visualViewport`만 줄이는 모의 키보드 조건에서 전송 버튼 접근, 대화 영역 최소 높이, 전체 접근성 이름·일반 화면 복원도 확인한다. 실패 시에도 보고서와 화면을 남긴다.
