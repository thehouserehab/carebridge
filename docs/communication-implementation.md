# Carebridge 소통 중심 개편 — 구현·검증 현황

작성일: 2026-09-22

## 현재 단계

개편안의 P0-1(홈·대화)과 P0-2(상세 기록 연결)를 구현했다. 가상 역할 전환으로 검증하는 로컬 프로토타입이며, 실제 계정·서버 저장·기기 간 동기화(P1)는 아직 구현되지 않았다. 현재 배포 사이트 역시 서버 메시지 서비스가 아니다. 실제 개인정보·아동 사진·건강정보를 입력하면 안 된다.

## 반영한 변화

- 치료사·보호자 메뉴를 홈 / 대화 / 기록 / 아이 정보로 정리했다. 센터의 운영 현황·아동·일정은 유지했다.
- 치료사 홈은 담당 아동 전체, 보호자 홈은 연결된 아동만 집계한다. 새 소식, 다음 일정, 이어 쓸 초안(보호자는 가정 활동) 순서다.
- 홈 소식을 누르면 해당 아동의 대화와 읽지 않은 메시지 위치로 이동한다. 데스크톱은 목록·대화 분할, 모바일은 단일 화면이다.
- 일반 소식·사진·영상, 공유 기록·활동 카드, 원문 인용 답변, 활동 피드백을 하나의 대화 흐름으로 연결했다.
- 읽음과 치료사의 ‘다음 회기에 반영’ 메모를 구분했다. 후자는 내부용이며 공개 답변은 따로 전송한다.
- 대화의 ‘기록에 참고’에서 원문·첨부를 확인하고 다음 회기 기록을 작성한다. 일반 메시지를 자동으로 임상 기록으로 만들지 않는다.
- 기록은 활동·반응·다음 계획을 기본으로 한다. 상세 관찰, 복수 평가, 가정 활동, 내부 메모, 사진·영상은 접어서 제공한다.
- 빈 초안을 허용하고 정식 기록에는 작성 내용을 요구한다. 제목은 날짜·활동으로 제안한다. 이전 기록에서 목표·측정 항목만 가져오며 과거 측정값은 복사하지 않는다.
- 공유 전 보호자용 요약·수신자·선택한 첨부를 확인한다. 상세 관찰·평가 원문·내부 메모·다음 계획은 공유하지 않는다.

## 핵심 불변 조건과 검증 근거

| 개편안의 검증 항목 | 구현·증거 |
|---|---|
| 1. 올바른 아이·메시지 진입, 사용자별 읽음 | `access.js`, `conversations.js`, `chat-controller.js`; communication 단위·브라우저 테스트 |
| 2. 보호자 답변·첨부, 치료사 공개 답변, 내부 계획 비노출 | 역할별 메시지 조회, 공유본 참조; 사진·영상 재생과 비노출 브라우저 검증 |
| 3. 답변 참고 기록, 기본 3항목, 복수 평가, 공유 미리보기 | `record-fields.js`, `record-ui.js`; 서로 다른 측정값 2개와 실제 값 0 저장 검증 |
| 4. 재공유·철회·재접속, 기존 데이터 보존 | 공유본별 고정 메시지 ID, 보호자용 종료 안내, v2→v3 백업 전환; 단위·브라우저 검증 |
| 5. 실패·재시도·방 전환 시 입력/첨부 보존, 중복 방지 | 발신 clientId, 별도 초안 IndexedDB, 파일 저장 롤백; 전송 실패 후 재시도와 방별 초안·재접속 검증 |
| 6. 모바일·키보드 접근 | 320/390px 전 역할 메뉴, Tab 이동, 높이 420px 축소 뷰포트 검증; 실물 휴대전화 키보드는 별도 확인 필요 |

기존 공유본·피드백 카드는 원본 ID를 참조한다. 재공유는 새 버전이며 과거 답변은 당시 버전에 연결된다. 종료된 버전은 보호자에게 내용 없는 안내로 대체하지만 독립 메시지는 삭제하지 않는다. 직접 대화 첨부는 방 참여자에게, 기록 첨부는 선택한 파일만 공유된다.

## 코드와 저장 구조

- `app.js`: 화면 연결·기존 운영 기능·기록 폼 구성
- `access.js`: 담당·보호자 관계의 공통 조회 정책
- `conversations.js`: 대화/메시지/읽음, 역할별 조회, ID 참조, 저장 형식 변환
- `chat-ui.js`, `home-ui.js`, `communication.css`, `viewport.js`: 소통 화면과 반응형 구성
- `chat-controller.js`, `chat-drafts.js`: 입력·첨부 임시 저장, 전송·실패·재시도
- `record-fields.js`, `record-ui.js`: 상세 기록 검증·입력·조회
- `repository.js`: 기존 저장소 인터페이스 유지, 전환 백업, revision 충돌 검사
- `media-ui.js`: 기존 첨부 선택/미리보기 재사용, 대화 초안의 미전송 파일 복원

기존 localStorage 키 `child-development-demo-v2`는 그대로 사용하고 내용의 schema만 3으로 바꾼다. 변경 전 원문을 `child-development-demo-v2-backup-schema-2`에 저장한다. 백업·검증·쓰기 중 실패하면 기존 원문을 덮어쓰지 않고 오류를 표시한다. 기존 미디어 ID와 `carebridge-media-v1`의 원본 파일은 유지한다. 기존 자유 텍스트는 ‘기존 형식 기록’으로 표시한다.

대화 초안은 별도 `carebridge-chat-drafts-v1`에 탭·사용자·아동별로 보관한다. 이 탭의 새로고침에서 복원하며 다른 아동 방의 초안을 덮어쓰지 않는다. 브라우저 저장소 삭제·사이트 데이터 정리로 데이터가 사라질 수 있다. 복구가 필요하면 원문 백업을 별도 보관한 뒤 전체 탭을 닫고 개발 담당자가 형식과 첨부 참조를 검증해야 한다. 자동 초기화·일괄 삭제는 하지 않는다.

## 실행한 검증

- `npm run check`: JavaScript 구문 검사
- `npm test`: 18개 단위 테스트
- `npm run build`: 정적 결과물 `dist` 생성
- `tests/communication-browser.mjs`: 소통 개편 8개 검증 묶음, 실제 사진/영상 재생, 오류·초안·공유 이력·모바일/키보드
- `tests/browser.mjs`: 기존 기록·목표·피드백·센터 일정·충돌·손상 데이터 등 14개 검증 묶음
- `tests/media-browser.mjs`: 기존 첨부·공유 선택·용량·실패 롤백 등 7개 검증 묶음
- 브라우저 검증은 별도 테스트 컨텍스트와 가상 정보만 사용한다. 사용자 브라우저 저장 내용을 삭제하거나 테스트 데이터로 바꾸지 않는다.

실행 결과·화면은 로컬 `test-results/`에 보관하고 공개 저장소·배포에서 제외한다. 브라우저 테스트는 `PLAYWRIGHT_MODULE`, `CDP_URL`, `APP_URL`을 지정해 실행한다.

## 기존 화면과의 비교

`tests/ux-comparison.mjs`는 기존/개편 화면을 각각 독립 컨텍스트에서 3회 실행한다. 같은 가상 활동 피드백과 같은 정보를 담은 단일 평가 기록을 비교한다. 기존 기록의 활동·반응은 자유 텍스트, 개편 기록은 구분된 필드다.

2026-09-22 자동화 실행 중앙값:

| 작업 | 기존 | 개편 |
|---|---:|---:|
| 가정 활동 확인→경험 저장 | 288ms | 258ms |
| 동일 정보의 기록·평가 입력→저장 | 529ms | 485ms |
| 가정 활동 입력창까지의 열기 클릭 | 2회 | 2회 |

자동화 대기·기기 성능·브라우저 상태에 영향을 받는 값이며 **사람의 작성 시간이나 임상 업무 개선율이 아니다**. 비교 중 발견한 불필요한 ‘활동 설명 펼치기’를 없애 바로 경험을 남길 수 있도록 개선했다. 기존 앱에는 치료사의 공개 답변 기능이 없어 ‘확인→공개 답변’의 동등한 기준값은 없다. 보호자가 요약을 읽고 다음 행동을 설명할 수 있는지는 실제 사용자 테스트로 남아 있다.

## 다음 단계와 남은 제한

1. P0 사용자 확인: 보호자·치료사의 대표 과제 수행, 요약 이해도, 실물 휴대전화 키보드·영상 확인. 이번 자동화 결과를 사용자 검증으로 대체하지 않는다.
2. P1 서버 소통: 기존 백엔드·로그인 서비스 유무를 확인하고, 계정 초대·담당 관계·메시지/파일 저장·재접속 동기화를 구현한다. 담당 변경 후 이력 접근, 메시지 수정/삭제 정책도 확정해야 한다.
3. P2 알림·검색·센터 운영 소통: 사용성 검증에서 필요성이 확인된 항목부터 추가한다.

현재 역할 전환은 로그인이나 보안 경계가 아니다. 같은 브라우저의 데모 계정만 바뀌며 서로 다른 기기에서 메시지가 전달되지 않는다. 실제 온라인 상태·푸시·AI 요약을 제공하는 것처럼 표시하지 않는다. 기존 GitHub/Vercel 프로젝트·도메인 설정은 변경하지 않고 정적 프로토타입의 코드만 갱신한다.
