## 현재 앱의 PC 사람 평가 준비 명령

`study:p0-local-api`는 최신 `local-api/`의 A/B/C 한 과제를 사람이 직접 수행할 **PC 전용 합성 서버**를 준비한다. 과거 `study:p0`의 공개 프로토타입 창과 다르며, 브라우저를 자동 열거나 사람 평가를 대신 수행하지 않는다.

```text
npm run test:p0-local-api:browser
npm run study:p0-local-api -- --task=A
```

2026-10-24 실행 한도 보완: 준비·로그인과 채팅 안내에 시간이 걸리는 PC 평가는 `npm run study:p0-local-api -- --task=A --duration-minutes=120`으로 최대2시간을 선택할 수 있다. 생략하면 기존30분이며 명시적30분 또는120분만 허용한다. A 대신 B/C도 같은 옵션을 사용한다. 준비 시작부터 한 번의 실행 제한을 적용하며 자동 연장하거나 로그인 세션 만료를 바꾸지 않는다. 서버 유지 시간은 사람의 과제 수행 시간이 아니다.

첫 명령에 필요한 설치된 Playwright/Chrome 경로는 [비교 환경](p0-comparison-environment.md)에 있다. 두 번째 명령은 직접 사용하는 터미널에서만 실행한다. 최신 자동 준비 결과가 오늘·현재 소스와 일치하고 A/B/C 여섯 조합과 자원 종료가 모두 확인돼야 새 자료를 만든다. 최신 실패·미완료를 건너뛰어 과거 성공을 채택하지 않는다. 실행 소스를 바꿨거나 날짜가 바뀌면 사전 검사를 다시 수행한다.

- A/C는 보호자, B는 치료사 계정 하나만 터미널에 표시한다. B/C는 위 두 번째 명령의 `--task=A`만 바꾼다. 계정·비밀번호나 터미널 전체 내용을 채팅/평가표에 복사하지 않는다.
- 진행자가 새 Chrome 시크릿 창에서 표시된 루프백 주소를 직접 열고 로그인·역할·‘하루’ 홈·과제 초기 상태를 확인한다. CLI는 시크릿 여부나 로그인 완료를 자동 검증하지 않으므로 확인 전 측정을 시작하지 않는다. 준비·로그인 시간은 과제 시간에서 제외한다.
- 과제마다 새 서버·메모리 자료를 사용한다. 소스는 실행 중 편집하지 않는다. 시작/종료 시점의 소스 지문 비교는 제공하며, 임의 편집·되돌리기의 중간 상태까지 감시하는 것은 아니다.
- 실제 자료·첨부·아이폰 접속은 사용하지 않는다. 이 서버는 가상 첨부 격리만 지원하므로 D의 파일 검사·전달 시험을 대신하지 않는다. C에서는 진행자가 정답/평가 기준을 먼저 설명하지 않는다.
- 종료는 `q`+Enter, 빈 Enter, Ctrl+C 또는 터미널 입력 종료다. 준비를 포함한 선택 시간(기본30분, 명시적120분)이 지나면 종료를 요청한다. 정리 실패 시 같은 창을 유지하고 Ctrl+C로 재확인한다. 임의 파일 삭제나 강제 종료를 정상 정리로 간주하지 않는다.
- 종료 전에 필요한 비식별 관측값만 별도 기록하고 사용한 시크릿 창은 직접 닫는다. 이 실행기는 참여자 답변·시간·이동 수·과제 완료를 자동 기록/판정하지 않는다. 기존 대비 개선율 산출에는 아래 비교 조건이 별도로 필요하다.

## 다음 실물 시험 한 회차 — 참여자가 할 최소 조작

**아래는 미실행 계획이며 성공 기록이 아니다.** 진행자는 먼저 최신 소스 식별, 실제 준비 완료인 가상 세션, 현재 PC/아이폰 주소와 허용 범위, 파일 검사·전달, 필요한 임시 보안 설정의 승인을 확인한다. 종료된 과거 주소·폐기된 키를 사용하지 않는다. 아이폰이 핫스팟 제공 기기라면 단절 시험을 시작하지 않고, PC 연결이 유지되는 신뢰할 수 있는 개인 공유기 Wi-Fi를 준비한다. 준비되지 않은 항목을 우회해 자동 통과시키지 않는다.

1. **홈에서 답장:** 보호자가 새 소식 하나를 찾아 해당 아이에게 가상 답장을 보낸다. 진행자는 도움 없이 걸린 시간·화면 이동과 실제 수신을 기록한다. 준비/로그인 시간은 분리한다.
2. **기록과 선택 공유:** 치료사가 그 답장을 참고해 활동·반응·다음 계획과 `0회`, `2분`의 서로 다른 측정값을 작성한다. 가상 사진·영상 중 사진만 공유하고, 받는 사람과 내용을 확인한다. 저장 후 재열어 필수 정보 보존을 확인한다.
3. **보호자 이해도:** 새 공유본을 읽고 “무엇을 확인했으며 다음에 무엇을 전달하면 되는지” 자기 말로 설명한다. 진행자가 정답을 먼저 말하지 않는다. 영상·내부 메모·평가 원문은 보호자에게 없어야 한다.
4. **실물 조작:** 같은 화면에서 실제 키보드 입력/보내기, 파일 선택 취소 후 다시 선택, 방향 전환·확대, VoiceOver의 주요 버튼 이름과 초점 순서를 확인한다. 파일은 개인정보 없는 합성 자료만 사용한다. 앞서 확인한 일반 로그인·영상 성공은 다시 기본 성공으로 채우지 않고 변경된 화면·미검증 항목에 집중한다.
5. **재시작·재접속:** 진행자가 소유한 시험 API만 정상 재시작한 뒤 양 역할 재로그인으로 같은 기록·답장·사진 공개/영상 비공개를 확인한다. 이어 PC는 계속 연결한 채 아이폰만 Wi-Fi를 끊었다 다시 연결해 중복·유실·다른 아이 혼입 여부를 확인한다. API 재시작과 아이폰 단절 결과를 각각 기록한다.
6. **종료:** 시험 서버의 실제 종료와 소유 임시 자원 정리를 확인한다. 이번 회차에 별도 설치한 아이폰 프로파일이 있을 때만 그 이름을 확인해 사용자가 제거한다. 다른 프로파일/인증서를 정리하지 않는다.

이 한 회차의 현재 화면 관찰만으로 기존 대비 개선율을 계산하지 않는다. 원 개편안의 비교 평가는 아래 A/B처럼 같은 정보·기기·입력 방식·도움 규칙을 맞춘 기존/개편 화면의 사람 관측이 추가로 필요하다. Chrome 320/390px 자동 조작이나 실제 서버의 처리 시간을 사람 작성 시간으로 옮겨 적지 않는다. 독립 백업 매체와 운영 복구 책임도 이 실물 회차의 결과로 대신하지 않는다.

## 준비

- 기존 화면은 Git `580b873d7cbc71ddf7d1589f50286ed5c11fd3e1`로 고정한다. 개편 화면은 시험 시점 소스/빌드 체크섬과 주소를 기록한다. 미커밋 변경이 있으므로 HEAD만으로 개편 버전을 식별하지 않는다.
- 각 버전/과제는 시험 전용 새 브라우저 컨텍스트에서 시작한다. 사용자 탭·사이트 데이터는 초기화하지 않는다. 같은 가상 ‘하루’·목표 ‘놀이에 스스로 참여하기’·공유 기록/활동을 준비하고, 두 버전의 저장소를 공유하지 않는다.
- 실제 역할 참여와 대리 역할 체험을 구분한다. 실명·연락처·아동 건강정보를 수집하지 않는다. 기본 녹화 없음. 실제 사례가 나오면 가상 과제로 돌아간다. 기록은 무작위 참여 코드로 비공개 보관하며 보관/삭제 책임을 먼저 정한다.
- 같은 사람이 같은 기기/입력 방식으로 두 버전을 사용한다. 기존→개편/개편→기존 순서를 번갈아 배정하고 순서·반복 여부를 기록한다. 모바일/PC 결과를 섞지 않는다.
- 먼저 진행자가 과제를 완주해 초기 상태·필수 정보·저장 확인을 점검한다. 준비 오류가 있으면 사람의 시간을 측정하지 않는다.
- 실물 휴대전화에는 버전이 확인된 합성 시험 전용 접속 주소가 필요하다. 휴대전화의 `127.0.0.1`은 개발 PC가 아니다. 지정 아이폰·신뢰하는 개인 네트워크의 가상 시험 범위는 이미 승인받았지만, 새 시험에서는 현재 네트워크 주소와 필요한 임시 보안 설정을 확인한다. 과거 성공 세션은 종료되었으므로 그 주소가 지금도 유효하다고 추정하지 않는다. 공개 인터넷·실자료·운영 DB는 계속 제외한다.

## 관측 규칙

준비 실행 도구가 추가됐다. [비교 환경·명령·실행 증거](p0-comparison-environment.md)의 `npm run test:p0-study:browser`는 고정 기존/현재 소스와 동일 합성 자료로 A/B의 입력·실제 저장·새로고침·재열기를 8조합 검사한다. `npm run study:p0 -- --task=A --order=baseline-first`는 사전 검사 후 새 PC 시험 창을 연다. 사람 관측값은 자동 수집하지 않는다. 현재 화면의 참가자 보고는 아래 실행 기록에 따로 남기며, 준비 시험 시간/화면 이동을 사람 성과로 기록하지 않는다.

| 지표 | 정의 |
| --- | --- |
| 시작 | 역할/아동/홈을 확인하고 참여자가 과제 안내를 읽은 뒤 시작에 동의한 순간. 자료 준비·역할 선택 시간 제외. |
| 완료 | 과제별 필수 정보와 실제 저장 결과를 확인한 순간. 버튼 클릭만으로 완료 아님. |
| 시간 | 같은 실행의 시작/완료 시각·경과 초. 중단/실패는 그때까지의 시간으로 별도 남김. |
| 화면 이동 | 주 화면 교체·모달 열기·모달 닫기 각각 1회. 잘못 갔다 돌아온 경로도 셈. 스크롤/상세 펼치기/키 입력 제외. |
| 조작 수 | 버튼/탭/링크/상세 펼치기의 클릭·탭 횟수. 글자 수/스크롤 제외. 화면 이동과 합산하지 않음. |
| 도움 | 안내 재낭독·조작 힌트·대리 조작을 구분. 독립 완료와 도움 받은 완료를 구분. |
| 완전성 | 저장 후 요청한 활동/반응/계획·측정값/단위/조건 모두 확인. 정보가 누락된 빠른 실행은 성공으로 평가하지 않음. |

막히면 중립 질문을 사용하고 버튼 위치나 치료 정답을 먼저 알려주지 않는다. 중단 요청을 즉시 수용한다. 실제 네트워크/시험 준비 오류를 사용성 실패와 구분한다.

## 참여자용 과제

모든 내용은 **합성 화면 시험 자료**이며 치료 처방/평가 지침이 아니다.

### A. 소식 확인 후 활동 답변 — 두 버전 비교

홈에서 하루의 ‘놀이 참여 관찰’ 소식을 읽고, 연결된 ‘좋아하는 놀이 함께 고르기’ 활동에 오늘 조금 해봤다고 남겨 주세요. 반응은 ‘가상 사례: 놀이를 직접 골랐어요.’, 어려움은 ‘가상 사례: 오래 이어가기 어려웠어요.’로 전달해 주세요.

완료: 해당 공유본에 날짜·수행 상태·반응·어려움이 한 번 저장됨. 두 버전 모두 **활동 피드백**을 비교한다. 새 자유 대화/공개 답변은 기존에 동등 기능이 없어 이 시간 비교에 섞지 않는다. 첨부는 과제 D에서 따로 확인한다.

### B. 필요한 상세 정보를 포함한 기록 — 두 버전 비교

홈에서 하루의 기록을 새로 작성해 주세요. 목표 ‘놀이에 스스로 참여하기’, 날짜 시험일, 제목 ‘비교용 가상 기록’입니다.

| 항목 | 동일하게 보존할 내용 |
| --- | --- |
| 활동 | 가상 놀이 두 가지 중 선택 |
| 반응 | 가상 관찰: 손으로 가리킴 |
| 다음 계획 | 다음 회기에 가상 관찰 조건 재확인 |
| 보호자 요약 | 가상 놀이를 선택해 참여했어요. |
| 측정 1 | 직접 관찰 / 참여 시간 / 3 / 분 / 동일한 가상 놀이 공간 |
| 측정 2 | 직접 관찰 / 도움 횟수 / 0 / 회 / 동일한 가상 놀이 공간 |

기존 화면에는 활동/반응 구분·복수 평가 행이 없다. 활동·반응·두 번째 측정은 기존 내부 메모에 명시하고 첫 측정은 평가 입력에 남기는 방법을 준비 때 안내한다. 개편 화면은 세 기본 항목·두 측정 행을 사용한다. **보존 정보의 완전성/작성 시간**을 비교하되 기존이 복수 평가를 구조화해 저장했다고 주장하지 않는다.

완료: 정식 저장 후 위 정보 모두 확인. 초안은 완료 아님. 실제 공유까지 시간에 포함하지 않는다. 제목/평가를 찾는 이동·빈 값과 0의 혼동도 관찰한다.

### C. 공유 요약 이해 — 개편 보호자 확인

아래 합성 요약을 읽고 무엇을 보았고 다음에 무엇을 하면 되는지 자기 말로 설명해 주세요.

> 화면 시험용 가상 사례입니다. 하루는 두 가지 가상 놀이 중 하나를 손으로 골랐습니다. 다음 가상 활동 후에는 선택한 놀이와 반응을 이 기록의 답변으로 알려 주세요. 오래 이어가기 어려웠다면 그 점도 남겨 주세요. 실제 활동은 담당 치료사와 정해 주세요.

진행자는 ① 관찰한 사실 ② 다음 전달 행동 ③ 이 기록에 답하는 위치 ④ 어려움도 전달 가능함 ⑤ 합성 예시와 실제 치료의 구분을 ‘독립 설명/질문 후 설명/설명하지 못함’으로 기록한다. 임상 적합성·개인의 문해력 평가·근거 없는 단일 총점으로 바꾸지 않는다. 제품 문구의 모호함만 비식별화한다.

### D. 개편 전체 연결·실물 조작 — 개선율 비교하지 않음

1. 보호자: 홈 → 아이/해당 메시지 → 공유 카드 답변·준비된 합성 사진/영상 → 보내기 → 같은 브라우저 새로고침 후 표시.
2. 치료사: 공개 답변·내부 반영을 각각 작성, 읽음과 반영 상태 구분 → 대화 참고 기록 → 과제 B 정보/두 측정 → 수신자·요약·사진 한 개만 선택 미리보기 → 공유.
3. 보호자: 새 공유본/선택 사진만 확인. 내부 메모·평가 원문·비공유 영상은 없어야 함.
4. 치료사: 내부 수정만으로 기존 공유본 불변 → 재공유 → 철회 → 새로고침. 이전 안내·당시 답변 참조·독립 소식 보존.
5. 진행자가 준비한 합성 저장 실패: 입력/첨부 유지 → 같은 ID 재시도 한 번 저장 → 방별 초안 분리. **오프라인만으로 로컬 저장 실패를 만들었다고 가정하지 않음.** 준비 안 됐으면 미실행.
6. 실물: 실제 키보드가 열린 상태의 입력/첨부/보내기, 파일 선택 취소/다시 선택, 사진 표시·영상 재생/중지, 방향 변경·확대 시 버튼 접근. 카메라는 동의한 참여자가 직접 단색 시험 물체만 찍는 선택 시험. 얼굴·손·집 내부·실제 아동 자료 사용 금지.

기존 공개 프로토타입의 P0는 같은 브라우저의 가상 역할 전환이다. 이를 실제 로그인이나 다른 기기 전달로 설명하지 않는다. 현재 로컬 API에서 D를 진행할 때는 가상 치료사/보호자의 별도 로그인을 사용하고, 같은 PC의 역할별 확인과 실물 기기 전달을 구분한다. 통신 단절·API 재시작·재로그인 후 저장 자료 보존은 별도 P103 결과로 남기며, 새로고침 성공만으로 재접속 검증을 완료하지 않는다.
