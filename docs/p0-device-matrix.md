후속 [연결 없음 화면·이력 보존 검사](empty-assignment-ui.md)는 센터 폼에서 치료사/보호자의 모든 관계를 해제하고 다시 연결하는 흐름을 세 화면에서 추가로 6묶음 검증했다. 기존 여섯 소통 사례의 대체 검사는 아니며, 실제 데이터 손상은 계속 오류로 차단한다. 로컬 단위 검사는 76개로 늘었다. 아래 이전 단계 숫자는 당시 결과로 보존한다.

후속 [전송 중 갱신·담당 변경 검사](chat-send-lifecycle.md)는 아래 여섯 사례를 대체하지 않는다. 지연 완료·실패·다른 탭/담당자 변경·초안 정리 실패를 같은 세 화면에서 별도로 12개 검증했다. 최종 코드에서 아래 전체 흐름도 재실행해 통과했다. 최신 로컬 단위 검사 74개·전송 경계 12개·기존 전체 흐름 18조합·레이아웃 203조건의 상세 결과는 후속 문서에 기록했고 아래 이전 수치는 당시 결과로 유지한다. 실제 기기·사용자 확인과 P1 연결은 여전히 별도 완료 요건이다.

개편안의 여섯 가상 사례를 데스크톱 1440×1000, 모바일 390×844·320×720에서 각각 처음부터 끝까지 수행했다. 각 화면은 별도의 비영구 Chromium 컨텍스트와 합성 자료를 사용한다. 여섯 사례 × 세 화면, 총 18개 사례/화면 조합이 통과했다. 사용자 탭·기존 저장소는 채택하거나 초기화하지 않았다.

기존 `communication-browser.mjs`는 주요 업무 흐름을 1440px에서 실행한 뒤 모바일 메뉴·키보드만 확인했다. 그 결과만으로 모든 업무를 모바일에서도 완주했다고 판단할 수 없었다. 새 `communication-matrix.mjs`는 화면별 전체 실행 결과와 실행 UUID를 확인하며, 실패한 화면에서 중단하고 이전 실행의 결과를 성공 증거로 재사용하지 않는다.

이 검증은 **가상 역할·로컬 저장·Chromium 화면 검증**이다. 실제 인증·서버 전달·국내 운영 승인·실물 휴대전화·사용자 이해도 검증은 아니다. API 연결은 마지막 단계로 유지한다.

## 실제로 수정한 문제

1. **공유 미리보기의 첨부 로딩 취소**: 기록 저장 → 공유 준비가 같은 `<dialog>`를 즉시 다시 열었다. 이전 창의 지연된 `close` 이벤트가 새 미리보기의 파일 로딩을 정리해 ‘불러오는 중’으로 남았다. 새 창이 열려 있으면 이전 종료 이벤트로 정리하지 않도록 변경했다. 새 폼을 여는 기존 정리 절차와 창이 실제 닫혔을 때의 정리는 유지한다. 선택 공유·원본 저장·권한 규칙은 변경하지 않는다.
2. **모바일 새로고침의 열린 대화방 복원 누락**: 아동·메뉴는 복원됐지만 방의 열림 상태는 항상 false였다. 열린 방 또는 목록 상태를 기존 탭별 화면 설정 `child-development-view`에 선택적 boolean으로 함께 저장한다. 구형 설정은 그대로 읽고, 계정 전환은 기존처럼 홈/목록 상태로 초기화한다. 대화·첨부 저장 키와 ID는 변경하지 않는다.

테스트 자료의 문제도 별도로 고쳤다. 0fps 캔버스 스트림으로 생성한 WebM이 이 실행 환경에서 재생 오류를 냈다. 공통 합성 미디어 도우미는 10fps로 기록한 뒤 실제 영상 크기·양수 재생 시간을 먼저 확인한다. 앱 검사·재생 조건을 완화하거나 미리보기 실패를 통과로 바꾼 것은 아니다.

## 요구사항별 증거

| 개편안 사례 | 각 화면에서 수행한 확인 |
|---|---|
| 1. 홈 → 올바른 아이/소식, 사용자별 읽음 | 홈만 열어서는 읽음 저장이 없음; 하루 소식 선택 후 해당 대화 영역·공유 카드 강조 확인; 보호자의 열람이 치료사 읽음으로 기록되지 않음 |
| 2. 보호자 답변/첨부 → 치료사 공개 답변, 내부 계획 비노출 | 공유 카드에 사진·영상 답변; 새로고침 후 실제 이미지 디코딩·영상 재생; 공개 인용 답변; 열람과 명시적 임상 반영을 구분; 내부 기록/활동 검토 메모는 보호자 화면에 없음 |
| 3. 참고 대화 → 상세 기록 → 공유 준비 | 답변 원문·사진 확인; 활동/반응/다음 계획; 횟수 0회·시간 3분과 조건을 저장; 첨부 두 개는 기본 비공유, 사진 하나만 선택; 수신자·요약·선택 사진의 실제 표시 확인; 내부 영상/평가/계획 비노출 |
| 4. 재공유/철회/새로고침, 기존 자료 보존 | 내부 수정만으로 기존 공유본이 바뀌지 않음; 새 공유 후 옛 카드의 내용/첨부/답변 버튼 없음; 철회 후 새 요약 비노출; 이미 보낸 독립 메시지·당시 공유본 참조 유지; 실제 v2 원문 백업·기존 날짜/값 0/단위/조건/ID/원본 파일 바이트 유지 |
| 5. 실패/재시도/방 전환 | 두 아이 방의 별도 텍스트·사진 초안; IndexedDB 커밋 후 ID·파일 바이트 확인; 새로고침에도 같은 열린 방과 초안 유지; JSON 저장 실패 뒤 입력/첨부/발신 ID 유지; 재시도는 같은 ID로 해당 아이에게 한 번만 저장 |
| 6. 좁은 화면·키보드 접근 | 각 역할의 모든 주요 메뉴와 대화에 페이지 가로 넘침 없음; Tab으로 입력 → 첨부 → 보내기; 모바일 420px 높이에서 보내기가 하단 메뉴 위에 있음; 목록으로 돌아간 상태도 새로고침 후 그대로 유지 |

추가로 가정 활동 카드 → 보호자 경험 → 대화 카드 한 개 → 치료사의 명시적 반영 확인을 모든 화면에서 수행한다. 일반 소식·첨부·활동 경험은 임상 기록으로 자동 저장되지 않는다. 빈 기록 초안과 홈의 이어 쓰기도 확인한다.

실행 보고서는 화면별 9·10·10개 세부 묶음을 기록한다. 이는 29개의 개별 사용자나 29개 독립 제품 기능을 의미하지 않는다. 성공 보고서에는 여섯 요구사항 ID, 오류 목록, API/외부 요청 목록이 포함된다. 이번 전체 실행에서 브라우저 오류와 API/외부 요청은 0건이었다.

## 남은 위험과 다음 우선순위

1. **실물·사용자 P0 확인**: 실제 iOS/Android 기기의 키보드·카메라/파일 선택·영상 표시, 치료사/보호자의 과제 완주와 공유 요약 이해도를 확인한다. CSS 뷰포트 축소는 실제 키보드 시험의 대체 증거가 아니다.
2. **기존/개편 사용성 비교**: 같은 합성 소식·같은 세부정보의 기록을 사용하고 시작/완료 조건을 맞춰 화면 이동 수·사람의 소요 시간을 측정한다. 자동 클릭 시간이나 사전 개선율을 성과로 제시하지 않는다. 요약을 읽은 보호자가 다음 행동을 설명할 수 있는지도 확인한다.
3. **운영 준비와 P1 연결**: 국내 공급자/예산·실제 계정·담당 관계 이력 정책·메일·보존/파기·백업 복구·운영 승인 후 마지막 API/화면 연결을 진행한다. [복구 준비도](recovery-readiness.md)의 미완료 항목을 유지한다. 로컬 v2 JSON 백업과 파일 바이트 보존 시험은 운영 DB+파일 백업/복구 완료를 뜻하지 않는다.
4. **P2**: 알림·검색·센터 운영 소통은 사용자 확인에서 필요성이 드러난 경우 우선순위를 정한다. 이번에 임의로 추가하지 않았다.

사용자 확인은 실제 아동 정보·사진·건강 데이터 없이 합성 자료로 진행하고, 기기/브라우저·실패 단계·화면 이동 수·시작/완료 시간·요약에서 이해한 다음 행동을 기록한다. 조사 참여자의 실제 연락처나 임상 내용을 코드·로그·공개 보고서에 넣지 않는다.
