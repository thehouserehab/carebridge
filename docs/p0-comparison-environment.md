# P0 기존·개편 화면의 가상 비교 실행 환경

## 2026-11-02 고정 기존 화면과 최신 API 화면의 비교 절차

현재 사용자는 직접 참여가 어렵다고 답했다. 아래는 다음 참여 시 적용할 진행 절차이며 새 사람 평가 결과가 아니다. 지금 새 서버·계정·평가 제한시간을 시작하지 않는다.

기존 도구 두 개를 순차 사용한다. `study:p0`의 제목이 **개편**인 창은 `src/` 공개 프로토타입이므로 최신 앱의 비교 대상으로 쓰지 않는다. 이 도구에서는 **기존** 창만 측정하고, 최신 앱은 `study:p0-local-api`로 별도 준비한다. 두 도구는 같은 A/B 입력 상수와 고정 Git seed를 사용하지만 전체 대화 이력과 저장 방식은 같지 않다. 따라서 동등 과제의 전체 사용성 비교이며 시각 디자인만의 인과 효과나 개선율을 선제 주장하지 않는다.

1. 참여자와 과제 A 또는 B를 정한 뒤 기존→현재 또는 현재→기존 순서를 별도로 기록한다. `study:p0 --order`는 두 공개 프로토타입 창 사이의 순서일 뿐 **기존/최신 API의 실제 평가 순서를 기록해 주지 않는다.** 같은 사람이 이전 과제를 수행한 경험과 도움 제공 여부도 남긴다.
2. 같은 날·PC·설치 Chrome·입력 방식·확대율·실제 콘텐츠 영역 크기를 맞춘다. 과거 도구의 기본 viewport는1440×1000이므로 화면 배치가 다른 상태로 시간을 비교하지 않는다. 조건을 맞추지 못하면 각 화면의 독립 관찰로만 기록한다. 날짜가 경계를 넘었으면 진행자가 먼저 같은 시험일인지 다시 확인한다.
3. 기존 화면은 `npm run study:p0 -- --task=A --order=baseline-first`로 준비한다(B는 `--task=B`). 내부8조합 준비가 통과한 뒤 열리는 **기존** 창만 참여자에게 제시한다. 함께 열린 **개편** 창은 조작·측정하지 않으며, 시험이 끝나면 실행기의 Enter 종료로 두 창과 서버를 함께 정리한다.
4. 최신 앱은 당일·현재 소스의 `npm run test:p0-local-api:browser` 통과 후 `npm run study:p0-local-api -- --task=A --duration-minutes=120`으로 새 자료를 준비한다(B는 `--task=B`). 가상 로그인·역할·하루 홈 확인을 마친 다음 측정한다. 순서를 반대로 배정했다면 이 단계를 기존 화면보다 먼저 진행한다. 종료는 `q`+Enter이며 예전 주소·계정을 재사용하지 않는다.
5. 양쪽 모두 같은 과제 문구와 완료 조건을 사용한다. B의 기존 화면은 활동·반응·두 번째 측정값을 내부 메모에 명시하는 대체 입력 방법을 준비 때 안내한다. 실제 클릭 경로는 안내하지 않고, 요청으로 도움을 제공했다면 종류·시점을 기록한다. 이전 A의138초는 추가 안내를 받은 단독 결과이므로 새 독립 비교의 기존값으로 가져오지 않는다.
6. 시작·저장 완료·새로고침 재조회 완료 시점을 구분하여 전체 소요와 저장/재조회 대기를 기록한다. 화면 이동 수와 버튼 조작 수는 [관측 규칙](p0-user-validation.md#관측-규칙)에 따라 별도로 센다. 저장된 필수 정보가 같고 모두 유지돼야 해당 시도를 완료로 판정한다. 준비 오류·중단·도움·조건 불일치는 따로 기록한다.
7. 두 실행의 ID·소스 지문·브라우저 버전·시험일·실제 순서와 비식별 관측값만 연결한다. 비밀번호·쿠키·실제 아동 자료는 남기지 않는다. C의 요약 이해도는 최신 앱에서 별도로 수집하며 시간 비교나 AI 조작 결과로 대신하지 않는다.

## 2026-10-14 현재 앱의 PC 평가 실행 경로

`scripts/local-p0-study.mjs` / `npm run study:p0-local-api -- --task=A`는 현재 앱의 사람 평가용 서버 진입점이다. A/B/C 중 하나, 직접 사용하는 터미널, 오늘의 동일 소스에 대한 최신 자동 사전검사 성공이 필요하다. 사전검사 자체를 CLI 안에서 다시 실행하지 않으며 정리 미확인·소스 변경·최신 실패 결과는 거부한다. 준비 도중 실패해 정리가 남으면 신뢰된 생성자가 전달한 정확한 소유 정리 함수만 재시도한다.

새 메모리 DB·임시 루프백 주소·필요한 한 역할의 합성 계정을 사용하고, 사람이 새 Chrome 시크릿 창에서 직접 로그인한다. 사용자 브라우저를 자동 열거나 닫지 않고 외부 접속/실제 자료/첨부 전달/자동 사람 지표 수집은 하지 않는다. 현재 앱의 독립 과제 관찰을 준비하는 것이지 기존/개편 양쪽의 조건이 모두 통제된 비교나 사람 평가 완료의 증거가 아니다. [조작·종료·측정 전 확인](p0-user-validation.md#현재-앱의-pc-사람-평가-준비-명령)을 따른다.

### 변경 파일과 이유

- `scripts/local-p0-study.mjs`, `package.json`: 기존 자동 검사가 즉시 종료되어 사람이 현재 앱의 과제를 수행할 수 없던 경로를 보완한다. 명시한 과제 하나·직접 사용하는 터미널만 허용하고, 준비 취소 시 생성 중인 자원을 기다린 뒤 같은 소유자가 정리한다.
- `scripts/local-p0-study-preflight.mjs`: 현재 소스·한국 날짜·6개 조합·종료 확인을 읽기 전용으로 검사한다. 실행 순서는 Windows 디렉터리 생성 시각으로 구분하며, 과거 폴더의 후속 수정 시각으로 최신 실패를 숨기지 않는다. 생성 시각이 없거나 최신 시각이 중복이면 실행하지 않는다. 이는 이 PC의 준비 확인이며 변조 방지 서명이나 운영 승인 체계가 아니다.
- `server/local-sandbox-cleanup.mjs`, `server/local-api-sandbox.mjs`, `tests/local-p0-study-fixture.mjs`: 준비 실패와 종료 실패가 겹쳐도 정확한 생성자의 정리 함수를 유지한다. 임의 오류의 메서드를 실행하지 않으며, 진행 중인 DB 종료를 중복 호출하지 않는다. 실제 `database.closed` 확인 전에는 정리 완료로 처리하지 않는다.
- `tests/local-p0-study-browser.mjs`: 실행기·검사 모듈·시험 코드까지 소스 지문에 포함한다. 기존 A/B/C 과제 조건·제품 화면·인증/저장 정책은 변경하지 않았다.
- 관련 시험 5개(`tests/local-p0-study-{cli,preflight,fixture}.test.mjs`, `server/tests/local-{sandbox-cleanup,api-sandbox}.test.mjs`)와 이 문서·`docs/p0-user-validation.md`·`docs/communication-acceptance.md`: 실패·취소·재시도·과거 결과 오채택 방지 및 사람 평가와 자동 준비의 구분을 남긴다.

변경 파일은 다음과 같다. 제품 `src/`, SQL, 인증, API, 운영 DB, 배포 설정은 이번 작업에서 수정하지 않았다.

- `scripts/p0-study-policy.mjs`: 합성 과제, 명시적 실행 옵션, 최소 자식 환경, 기존 사이트 저장소 덮어쓰기/시험 자료 유실 후 재초기화 금지.
- `scripts/p0-study-snapshots.mjs`: Git 읽기·현재 공개 소스 캡처, 파일별 SHA-256, 메모리 전용 공개 파일 서버.
- `scripts/p0-study.mjs`: 전용 새 브라우저·과제별 새 컨텍스트, 실제 화면 입력/저장/재조회 검사, 선택적 PC 대화형 세션, 종료/진단.
- `tests/p0-study.test.mjs`, `tests/ux-comparison.mjs`, `package.json`: 격리 회귀와 실행 진입점.
- 이 보고서·사용자 진행표·전체 완료표·README: 준비 결과와 사람 검증의 구분.

## 실행 방법

Node.js 24, Git, 이미 설치된 Playwright·Chromium을 사용한다. 의존성/브라우저를 자동 설치하지 않는다. 프로젝트 폴더의 PowerShell에서 아래 환경 경로를 설정한다. 이 PC에서 확인한 경로이며 다른 PC에서는 설치 경로를 확인해야 한다.

```powershell
$env:PLAYWRIGHT_MODULE = 'C:/Users/USER\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules\playwright\index.mjs'
$env:STUDY_CHROMIUM_EXECUTABLE = 'C:/Users/USER\AppData\Local\ms-playwright\chromium-1228\chrome-win64\chrome.exe'
npm run test:p0-study:browser
```

이 명령은 숨김 브라우저에서 A/B × 두 버전 × 1440/390px의 8조합을 실행한 뒤 자체 브라우저와 서버를 종료한다. PC에 설치된 브라우저를 명시하지 않으면 Playwright의 기본 설치 버전을 사용한다. 없으면 실패하며 자동 다운로드하지 않는다. `APP_URL`, `CDP_URL`, 운영 DB 주소는 사용하지 않는다.

PC 사람이 체험할 때는 **별도 실제 터미널**에서 한 과제씩 실행한다. 준비 시험 8조합이 같은 캡처 소스로 먼저 통과해야 두 개의 새 시험 창이 열린다. 역할/아동/홈은 준비되어 있으며, 버전은 창 제목의 기존/개편으로 구분한다.

```powershell
npm run study:p0 -- --task=A --order=baseline-first
npm run study:p0 -- --task=B --order=baseline-first
```

첫 과제 종료 후 다음 명령을 실행한다. 다음 참여자에게는 두 과제 모두 `--order=revised-first`로 바꾸는 등 [진행표](p0-user-validation.md)에 순서·반복 여부를 남긴다. 자동 실행 시간이나 준비 과정은 사람 시간에 포함하지 않는다. 브라우저 창을 닫거나 터미널에서 Enter를 누르면 두 시험 창과 저장소가 종료된다. 임시 기록은 복구할 수 없으므로 진행자는 **종료 전** 비식별 관측값을 책임/보관 규칙에 맞게 별도 기록해야 한다. 이 도구는 사람이 완료했다고 판정하지 않는다.

B의 기존 화면은 활동/반응·두 번째 측정값을 내부 메모에 명시하고 첫 측정값은 평가 입력에 보존한다. 개편 화면은 구분된 기본 항목·측정 행 2개를 쓴다. 두 번째 값은 실제 `0회`이며 빈 값이 아니다. 같은 정보의 완전성을 비교하되 기존 화면에 복수 구조화 평가가 있다고 하지 않는다. C 요약 이해·D 전체 연결/실물 조작은 이번 A/B 도구의 자동 결과로 대체하지 않는다.
