## 현재 상태와 변경 이유

기존 `Auth`에는 로그인·초대·세션 폐기가 있지만 로그인한 본인이 현재 비밀번호를 재확인하고 새 비밀번호로 바꾸는 내부 기능이 없었다. `server/auth.mjs`의 `changePassword(sessionValue, { currentPassword, newPassword })`로 이를 보완했다. 새 인증 공급자·클라우드·의존성은 추가하지 않았다.

인증·백엔드 스킬의 서버 경계 원칙을 적용했다. 요청 본문의 사용자 ID/이메일/역할을 신뢰하지 않고 실제 서버 세션과 DB 계정을 확인한다. 국내 E 저장·기존 Node/pg 구조·API 마지막이라는 사용자 제약을 유지한다. [OWASP 인증 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)의 현재 비밀번호 재확인 원칙을 참고했으며, [분실 비밀번호 복구](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)는 다른 본인 확인 절차가 필요하므로 이 기능으로 대체하지 않는다.

## 내부 계약

| 항목 | 동작 |
| --- | --- |
| 입력 | 실제 세션 토큰, 현재/새 비밀번호만 허용. 사용자/센터/역할 주입 거부 |
| 자격 확인 | 미폐기·미만료 세션, 활성 사용자와 계정, 현재 비밀번호 확인 |
| 비밀번호 | 기존 12~128자 경계 유지, 공백/Unicode 원문 그대로 비교. 동일 비밀번호 거부 |
| 실패 제한 | 로그인과 현재 비밀번호 증명이 같은 DB 누적 횟수 사용. 5회 실패 시 DB 시간 기준 15분 잠금 |
| 해시 | 기본 `scrypt N=32768, r=8, p=1`, 새 16바이트 salt. 테스트의 N=1024는 합성 시험에만 명시적 주입 |
| 성공 | 새 해시·변경 시각·실패 상태 초기화와 해당 계정의 모든 기존 세션 폐기를 같은 트랜잭션에서 커밋 |
| 응답 | `{ passwordChanged: true, reauthenticate: true }`만 반환. 새 세션/자동 로그인/계정 목록 없음 |
| 보존 | 다른 사용자 세션, 소속/역할·아동 관계·대화·기록·공유본·초대는 변경하지 않음 |
| 실패 | 세션 폐기 쓰기에 실패하면 이미 쓴 새 해시·시각·실패 초기화도 롤백 |

틀린 증명은 실패 표식을 반환해 횟수를 먼저 커밋한 뒤 `AUTH_INVALID`로 거부한다. 예외를 먼저 던져 횟수 증가가 롤백되는 우회를 만들지 않는다. 실제 자격 변경·실패 횟수 쓰기 시점에도 DB 시간으로 세션 만료를 재확인한다. 잠긴 계정은 올바른 현재 비밀번호로도 잠금을 우회하지 못한다. 정상 인증 세션까지 강제로 폐기하는 계정 잠금 정책은 별도로 추가하지 않았다.

## 동시성·잠금 순서

세션의 사용자 조회는 잠금 대상 식별용 힌트일 뿐 권한 부여가 아니다. 계정 쓰기 잠금을 먼저 잡고 실제 세션/사용자를 재검사한다. 비밀번호 변경·로그인·기존 계정 초대 연결·전체 세션 폐기가 계정→세션 순서를 지키도록 정리했다. 기존 초대 연결은 초대 행을 먼저 잠그되 계정 전에 세션 공유 잠금을 잡지 않는다.

이 순서가 없으면 초대 연결이 세션을 잡은 채 계정을 기다리고, 비밀번호 변경은 계정을 잡은 채 그 세션 폐기를 기다리는 교착이 가능하다. 전체 세션 폐기 또한 계정 잠금 없이 여러 세션 행부터 잠그면 증명 세션의 공유 잠금과 교착할 수 있어 동일한 순서로 직렬화했다. 운영 SQL·향후 관리 도구도 이 규칙을 지켜야 한다.

`authenticate`는 처음 세션을 읽은 뒤 마지막 조회 시각을 갱신할 때 미폐기/미만료·활성 사용자를 다시 확인하고 영향 행 수 0이면 `null`을 반환한다. 따라서 그 두 단계 사이에 비밀번호 변경/로그아웃이 먼저 커밋한 세션을 이전 조회만으로 인증하지 않는다. 이미 끝난 요청까지 회수한다는 뜻은 아니며 각 임상 서비스는 기존처럼 현재 관계를 별도 검사해야 한다.

## 실행 증거

- 집중 `node --test --test-concurrency=2 server/tests/auth-password-change.test.mjs server/tests/auth.test.mjs server/tests/existing-accounts.test.mjs`: **40/40**, 실패/취소/누락 0. 새 22개 + 기존 로그인/초대 9개 + 기존 계정 연결 9개다.
- `npm run test:server`: **710/710**. 전체 구성요소 회귀이며 실제 운영 계정 사용 성공이 아니다.
- `npm test`: **95/95**. `npm run check`, `npm run build`, `git diff --check` 통과.
- `npm run test:postgres:local`: 실제 PostgreSQL 18.6/Node 24.15.0에서 **45/45**, 신규 인증 동시성 9개 포함. PGlite의 순차 시험이나 주입된 만료 대역을 실제 두 연결 경합의 대체 증거로 사용하지 않는다.

새 단위 시험은 해시/전체 세션·타 사용자 보존, 현재/새 비밀번호, 공유 실패 횟수/잠금, 미만료·활성 자격, 엄격 입력/원문/입력 캡처, 세션 폐기 실패 롤백, 쓰기 시점 만료, stale 인증 읽기, 초대 연결 유지, 기본 강도 및 HTTP 경로 미추가를 검사한다. 최초 집중 실행은 HTTP 부재 검사 대역에 기존 login/logout 메서드가 빠져 503/404 기대가 어긋났다. 대역만 수정했으며 실제 HTTP 코드는 변경하지 않았다.

네이티브 시험은 합성 계정과 고정 PostgreSQL 18.6/Node 24.15.0을 기존 격리 Docker 실행기에 넣는다. 별도 연결 PID와 `pg_blocking_pids`로 실제 잠금 대기를 확인하고 gate로 선후를 제어한다. 고정 지연값이나 단일 연결 흉내를 교착 회피 증거로 사용하지 않는다. 세션 만료 사례는 대기 중 실제 DB 시간이 만료 시각을 지난 뒤 해제한다. 테스트 오류 때도 자기 gate를 해제하고 모든 자기 트랜잭션 종료를 기다린다.

신규 네이티브 사례 9개는 변경 간 단일 승자, 변경 우선/로그인 우선, 변경 우선/초대 연결 우선, 실제 잠금 중 만료, 동시 틀린 증명/로그인 잠금, 초기 읽기 후 폐기된 인증, 전체 세션 폐기 우선이다. 기존 SQL/원장/파일 준비·큐/자원/작업자/기록 초안 36개를 함께 실행한다. 시험 이미지 허용 목록에 누락되어 있던 기존 기록 초안 모듈·공통 필드도 명시적으로 포함했다. 문서·환경 파일·운영 자료를 빌드에 보내는 허용 범위 확대는 하지 않았다.

## 남은 위험과 다음 순서

1. **분실 복구 미구현:** 이메일 소유 증명·일회용 만료 토큰·실패 제한·복구 통지·전체 세션 해제의 독립 흐름이 필요하다. 센터 ID/역할이나 초대만으로 비밀번호를 초기화하지 않는다.
2. **전체 인증 감사/통지 미완료:** 후속 [최소 계정 사건](account-security-events.md)에 비밀번호 변경/전체 세션 폐기 성공만 분리해 보존한다. 로그인 실패·분실 복구·운영 행위자/조회·변경 통지·경보·보존/파기 정책은 아직이며, DB 소유자까지 막는 외부 불변 원장도 아니다.
3. **HTTP/화면 미연결:** 세션 쿠키에서만 토큰 전달, TLS·same-origin/CSRF·상위 요청 제한·내용 없는 오류와 쿠키 삭제/재로그인을 마지막 API 단계에서 검증해야 한다. 새 비밀번호 변경/복구 경로는 제공하지 않는다.
4. **커밋 응답 유실:** 자동 재시도/멱등 성공 보장은 없다. 이미 커밋했으면 이전 세션은 폐기되므로 새 비밀번호 로그인으로 상태를 확인해야 한다. 메모리 내 JS 비밀번호 문자열의 완전 소거도 보장하지 않는다. 로그/DB에는 원문을 추가하지 않는다.
5. **운영 준비 미완료:** 실제 계정·메일/감사·운영 Windows 실행/감독·독립 매체/키 복구·보존/파기·사용자/실물 기기·기기 간 재접속 흐름은 별도 검증해야 한다. 본 결과로 P101/P1·전체 개편이나 국내 통제 적합성을 완료 처리하지 않는다.

다음은 독립 백업 매체/복구 책임 확정과 P0 사람 관측을 우선 확보하고, 그동안 계정 복구·통지/전체 감사와 운영 실행 경계를 준비하는 순서다. 최소 사건 두 종류는 후속에 구현했지만 공개 활성화 조건을 모두 충족한 것은 아니다. 실제 자료·외부 접속은 해당 보호/복구 조건 전까지 보류하며 API는 마지막이다.

## 변경 파일과 재검증

제품 변경은 `server/auth.mjs`다. 새 시험은 `server/tests/auth-password-change.test.mjs`, `server/auth-password-change-native-tests.mjs`; 기존 네이티브 진입점·허용 이미지 입력·완료 수/내용 없는 결과 파일을 함께 갱신했다. SQL 스키마·권한 부여·프런트엔드·의존성·운영 자료·GitHub/Vercel 배포는 바꾸지 않았다.

- 최종 산출물 검사: 위 변경 파일 14개 엄격 UTF-8/뒤 공백, 문서 내 로컬 링크 140개 확인. 공개 소스 31개와 `dist`가 바이트 단위로 같고 추가 출력은 `build.json`뿐이다. 서버/문서·시험·자격증명 파일은 정적 빌드에 포함되지 않았다. 자기 UUID 컨테이너·이미지의 추가 Docker 조회도 0개였으며 다른 자원은 삭제하지 않았다. 합성 일회용 자원은 위 명령으로 다시 생성할 수 있다.
